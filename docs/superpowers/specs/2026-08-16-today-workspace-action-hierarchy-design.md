# 今日工作台单线程行动层级设计

## 目标

让 Windows 与 macOS 桌面客户端的今日工作台在进入页面后只突出一个明确的下一步，消除“风险状态、新建交易、待补结果、待复盘、进行中”同时争夺注意力的问题。

本阶段只调整今日工作台的行动层级与风险摘要密度，不改变风险计算、交易状态、持久化、路由、统计口径和侧栏数量。

## 方案选择

### 方案 A：仅调整颜色和按钮样式

改动最小，但无法解决用户仍需自己判断下一步的问题。风险、队列和新建交易依然是三套并列入口。

### 方案 B：共享风险模型并重构完整队列

可以把风险状态和交易任务统一成一个领域队列，但会同时改动风险计算组件、今日页数据流和队列结构，超出第一阶段范围。

### 方案 C：单一主动作与渐进式风险摘要

保留现有风险与交易数据流，由今日页根据现有队列直接打开最高优先级记录；风险异常通过现有风险状态 DOM 契约接管主动作。正常风险只显示一行摘要，超限时展开完整周期信息。

采用方案 C。它能直接解决最高权重问题，同时保持业务边界稳定，并为后续共享记录动作合同留出独立改造空间。

## 行动优先级

今日工作台的唯一主动作按以下顺序解析：

1. 风险已超限：主动作显示“处理风险”，进入风险管理；暂停突出新建交易。
2. 风险状态无法判断、未配置或本周未复核：主动作显示“处理风险状态”，进入风险管理。
3. 存在待补结果：主动作显示“补齐交易结果”，直接打开第一笔待补结果记录。
4. 存在待复盘：主动作显示“完成交易复盘”，直接打开第一笔待复盘记录。
5. 存在进行中交易：主动作显示“继续当前交易”，直接打开第一笔进行中记录。
6. 没有待办：主动作显示“新建交易”，打开现有交易编辑器。

同一优先级中的记录顺序完全沿用 `getTodayWorkflowBuckets`，本阶段不新增排序规则。

## 页面结构

### 顶部行动区

- 标题继续说明当前筛选和待办数量。
- 说明文字继续交代遗留任务与闭环顺序。
- 右侧只允许一个主色动作。
- 还有交易待办时，“新建交易”保留为次级描边按钮。
- 风险异常时，交易队列主动作隐藏，风险处理成为唯一主动作；“新建交易”保持次级，不从页面消失。

### 风险摘要

- 风险正常、接近限额、待确认、无法判断或未配置时，今日页只显示现有总结文案与恢复入口。
- 任一周期已超限时，展开今日、本周、本月三段详情，保留超限范围和剩余额度信息。
- 风险管理页和其他消费 `RiskStatusStrip` 的位置继续使用完整布局，不受今日页密度调整影响。

### 行动队列

- “全部、进行中、待结果、待复盘”继续作为浏览与检查入口。
- 顶部主动作直接打开第一笔最高优先级记录，不只切换标签。
- 用户从详情返回时继续沿用现有返回锚点，不改变导航行为。

## 组件与数据边界

- 在 `TodayWorkspace.tsx` 增加纯函数 `resolveTodayPrimaryAction`，只根据三个队列数量返回业务动作类型、标签和目标队列。
- `TodayWorkspace` 使用现有 buckets 中的第一笔记录执行主动作，不复制交易判断逻辑。
- `RiskStatusStrip` 增加仅影响布局的 `density="workbench"` 参数；默认仍为完整布局。
- 风险优先级通过今日工作台范围内的风险状态数据属性与 CSS `:has()` 表达，不新增异步回调或第二份风险计算。

## 可访问性与键盘行为

- 顶部主动作使用真实按钮或链接，并保持共享 36px 大控件契约。
- 主动作标签描述业务结果，不使用“更多”“继续”等模糊文案。
- 队列标签的方向键、Home、End 行为保持不变。
- 风险摘要链接保留可见焦点样式和明确目标。

## 验证标准

- 纯函数测试证明结果、复盘、进行中、新建交易的固定优先级。
- 浏览器测试证明主动作直接打开对应交易，且风险异常时只有风险处理使用主色。
- 设计契约证明今日页正常风险为单行摘要、超限风险展开详情，其他页面不受影响。
- `pnpm test`、`pnpm typecheck`、`pnpm build` 和 `pnpm qa:desktop-visual` 全部通过。
- 960×640、1280×860、1920×1080 的今日工作台无横向溢出、文字遮挡或双主动作。

## 非目标

- 不在本阶段统一右键、批量和详情页记录动作合同。
- 不拆分风险数据修复中心。
- 不调整案例库列、侧栏数字或数据安全文案。
- 不新增手机、iPad、浏览器产品形态或其他平台适配。
