# 实盘绩效统计周期设计

日期：2026-08-05
状态：设计已确认，实施计划已编写
范围：实盘绩效周期、Dashboard 与策略统计范围、周期交易下钻、持久化与导入导出

## 1. 背景

用户长期记录实盘后，会在更换账户阶段、调整交易体系或开始新执行阶段时，希望“重新统计”。当前 Dashboard 的默认实盘口径为全部历史，虽然可以查看本周、本月、30 天、90 天和今年，但不能建立一个长期有效、可命名、可反复切换的统计阶段。

直接删除或批量改写旧实盘会造成不可逆的数据损失，并可能破坏由旧交易提炼出的案例、正文、截图和复盘追溯。项目已经存在“风险核算起点”，但该设置只用于风险额度、风险覆盖与开仓门禁，现有产品文案也明确声明它不改变策略与绩效统计。因此，绩效重置必须使用独立概念，不能复用或联动风险核算起点。

## 2. 目标

1. 用户可以在不删除、不复制、不移动交易的前提下开始新的实盘统计周期。
2. Dashboard、策略表现、胜率、盈亏、R 分布和权益曲线默认统计当前周期。
3. 历史周期与全部历史可随时切换查看，并保留稳定的 URL 状态。
4. 一笔交易按平仓交易日动态归属周期；起点前开仓、起点后平仓时计入新周期。
5. 案例、笔记、截图、活动记录、周复盘和风险核算设置不因创建周期而改变。
6. 支持多次创建周期，适合长期使用，并提供安全的最近一次撤销能力。
7. 旧数据升级后保持原统计行为，只有用户明确创建首个周期后才改变默认口径。

## 3. 非目标

- 不删除、归档、复制或批量修改实盘交易。
- 不给每笔交易写入固定周期 ID。
- 不修改案例来源同步、案例复习、掌握状态或案例正文。
- 不重算或改写已经完成的周复盘快照。
- 不改变今日战绩、自然周复盘或年度复盘的日期定义。
- 不改变风险核算起点、风险额度、亏损预算或开仓门禁。
- 不增加云端账户、跨设备协作或新的发布服务。
- 首版不允许删除任意中间周期或直接编辑历史边界。

## 4. 方案选择

采用“独立统计周期记录 + 按平仓日动态归属”。

未采用单一统计起点，因为用户多次重置后无法直接恢复和比较上一阶段。未采用在交易上持久化 `cycleId`，因为导入历史交易、修改平仓日、恢复回收站记录和跨周期持仓都会要求迁移归属，容易形成交易日期与周期 ID 两个相互冲突的事实来源。

周期只保存边界与名称；交易归属始终由现有交易事实动态推导。这样创建周期是一个轻量、可逆的设置操作，而不是数据迁移。

## 5. 领域模型

新增独立持久化集合，建议命名为 `livePerformanceCycles`：

```ts
type LivePerformanceCycle = {
  id: string
  name: string
  startTradingDayKey: string
  createdAt: string
}
```

约束如下：

- `id` 为稳定且唯一的本地 ID，用于 URL 与导入导出。
- `name` 去除首尾空白后长度为 1–40 个字符；同一交易库内不得与其他周期同名。
- `startTradingDayKey` 必须是严格、可 round-trip 的 `YYYY-MM-DD` 本地交易日。
- 周期按 `startTradingDayKey` 严格递增，同一天不得存在两个边界。
- `createdAt` 必须是有效 ISO 时间，仅用于审计与稳定冲突处理，不参与交易归属。
- 不保存 `endTradingDayKey`；某周期的结束边界由下一个周期开始日推导，避免冗余字段失配。
- 不复用现有 `liveStatsStartTradingDayKey`。该字段虽然名称包含 `Stats`，当前实际属于风险核算周期，必须保持原语义与兼容性。

最新开始的周期是当前周期，不另存 `currentCycleId`，从而避免“最新边界”和“当前 ID”出现矛盾。

## 6. 周期区间与交易归属

### 6.1 区间规则

对于按开始日排序的周期 `C1...Cn`：

- `C1` 的范围为 `[C1.start, C2.start)`；
- 中间周期 `Ci` 的范围为 `[Ci.start, Ci+1.start)`；
- 最新周期 `Cn` 的范围为 `[Cn.start, +∞)`；
- 第一条边界之前存在一个只读虚拟区间“统计起点前”，范围为 `(-∞, C1.start)`。

周期开始日包含当天。结束日在 UI 中显示为下一周期开启日的前一个自然日，但不写入持久化数据。

当周期集合为空时，不生成虚拟区间，实盘统计保持现有“全部历史”行为。

### 6.2 交易日期事实

周期归属只使用已平仓实盘的规范平仓交易日：

1. 优先使用已经冻结的 `closedTradingDayKey`；
2. 缺失时沿用现有统计口径，从 `closedAt` 解析；
3. 无法得到有效平仓交易日时，不进入周期统计，并计入“待补平仓日期”数据健康提示。

开仓日在周期归属中不具有决定权。因此，起点前开仓、起点后平仓的交易计入新周期。修改平仓日期、导入旧交易或恢复软删除记录后，交易会自动进入正确区间，不需要迁移命令。

### 6.3 排除项

以下记录不进入实盘绩效周期统计：

- `tradeKind` 为 `paper` 或 `case`；
- 未平仓、计划、错过机会等非已执行平仓状态；
- 已软删除记录；
- 结果口径不满足现有可信统计规则的字段，仍按现有 `summarizeTradeResults` 分别处理覆盖、冲突与缺失，不因周期功能降低校验标准。

案例是独立 `case` 记录，保留 `sourceTradeId`、来源正文快照、案例正文、截图与掌握状态。创建、重命名、切换或撤销周期都不得写入案例或来源交易。

## 7. 统计范围组合

周期是实盘绩效的外层范围，现有日期范围是其内层范围。

当 Dashboard 为 `kind=live` 时：

1. 先按选中的统计周期筛选已平仓实盘；
2. 再应用现有 `all`、本周、本月、30 天、90 天或今年范围；
3. 最终集合统一供累计胜率、盈亏、平均 R、权益曲线、R 分布和策略表现使用。

选择“全部历史”时，结果与创建周期前的现有行为一致。选择“统计起点前”时，只统计第一条边界之前的记录。

当 `kind=paper` 或 `kind=all` 时，不应用实盘统计周期，并从 URL 清除本功能拥有的参数。首版不定义混合实盘周期与模拟盘的组合口径，避免同一指标中出现不同时间边界。

Dashboard 顶部“本周交易分析”包含自然周内的平仓交易与错过机会，继续按当前自然周和交易类型显示，不受历史统计周期选择影响；文案必须明确“本周”而非“当前统计周期”。今日战绩仍按当前平仓交易日计算；由于新周期不得晚于当前交易日，今日已平仓实盘自然属于当前周期。周复盘页面和已冻结周复盘快照继续按自然周展示，不接受周期筛选，也不因统计周期改变而重写。

## 8. URL 契约

新增查询参数 `statsCycle`，与现有风险范围参数 `liveCycle` 明确分离：

| 状态 | URL 规则 |
| --- | --- |
| Dashboard/策略的当前统计周期 | 省略 `statsCycle` |
| 指定历史周期 | `statsCycle=<cycle-id>` |
| 统计起点前 | `statsCycle=pre-cycle` |
| 全部历史 | `statsCycle=all` |

规则：

- 周期集合为空时，省略参数并解释为全部历史。
- `kind` 不是 `live` 时删除 `statsCycle`。
- 用户切换统计周期时同时把 `range` 重置为 `all`，先展示完整周期，避免历史周期与“本周/30 天”等当前日期范围相交后出现难以理解的空结果；用户仍可在切换完成后主动选择周期内日期范围。
- Dashboard 与策略页遇到无效或已撤销的周期 ID 时，使用 `replace` 规范化到当前周期，不制造额外浏览器历史；当前周期显式 ID 在这两个分析页面规范化为省略参数。
- `range`、视觉测试参数和其他不属于本功能的参数必须保留。
- Dashboard 跳转策略详情时携带相同的 `statsCycle` 与 `range`。
- 交易日志保持“省略 `statsCycle` 即不启用统计周期筛选”的现有默认语义。“查看本周期交易”必须显式携带当时当前周期的真实 ID；交易列表不会把该 ID 压缩为空参数，因此以后创建新周期时，旧链接仍稳定指向原周期。无效或已撤销的列表周期 ID 只清除该筛选，不自动改成当前周期。
- “查看本周期交易”进入交易日志后显示明确筛选标签和清除入口。
- `statsCycle` 与现有风险范围 `liveCycle` 不同时作为交互式筛选生效。用户选择其中一个时清除另一个；遇到外部 URL 同时包含两者时，以显式 `statsCycle` 为准并规范化删除 `liveCycle`。

## 9. 用户流程

### 9.1 Dashboard 周期选择

实盘模式的范围区域新增“统计周期”选择器，顺序为：

1. 当前周期；
2. 按时间倒序排列的历史周期；
3. 统计起点前；
4. 全部历史。

周期集合为空时不显示空选择器，而显示轻量入口“开始新统计周期”；Dashboard 指标保持全部历史。

选中周期后，页面显示明确副标题，例如：

`当前统计周期 · 第 2 期 · 2026-08-05 至今`

风险核算起点如需同时出现，必须使用“风险核算”措辞，不得简称为另一个“周期”。

### 9.2 创建周期

Dashboard 提供“开始新统计周期”操作。弹窗包含：

- 周期名称，默认 `第 N 期 · YYYY-MM-DD`，可编辑；
- 开始交易日，默认当前交易日；
- 上一周期结束日预览；
- 新周期当前包含的已平仓实盘数量；
- 起点前开仓、起点后平仓按平仓日计入的说明；
- “不会删除交易、案例、笔记或截图”的明确说明；
- “不会改变风险核算设置”的明确说明。

首个周期可选择任意不晚于当前交易日的合法日期。后续新周期必须晚于当前周期开始日且不晚于当前交易日。

确认后先写入内存，再使用现有立即持久化能力落盘。只有持久化成功才关闭弹窗并提示完成；失败时恢复原周期集合并提示原设置已保留。若保存和回滚均失败，提示用户重新打开应用核对，沿用现有高风险设置保存策略。

### 9.3 管理与纠错

- 任一真实周期允许重命名，仍需通过名称校验和持久化回滚。
- “统计起点前”为虚拟区间，不允许重命名。
- 只允许撤销最新周期。撤销意味着删除最后一条统计边界，使上一周期重新成为当前周期；不删除任何交易或案例。
- 只有一个真实周期时撤销它，周期集合回到空状态，Dashboard 恢复全部历史默认口径。
- 首版不允许编辑已经保存的边界。最新周期日期填错时，用户先撤销再重新创建；中间边界不可直接删除，避免隐式合并两段历史。
- 撤销弹窗必须预览新的当前周期和受影响统计范围，并再次声明不会删除记录。

周期管理入口放在 Dashboard 范围区域附近；设置页可以提供同一管理组件的入口，但不得建立第二套编辑逻辑。

## 10. 交易列表与策略下钻

交易日志平时打开时保持现有默认行为，不因存在统计周期而自动隐藏旧交易。

从 Dashboard 点击“查看本周期交易”时：

- 进入实盘交易列表；
- 应用 `statsCycle` 的平仓日范围；
- 显示可见筛选标签，例如“统计周期：第 2 期”；
- 提供一键清除，恢复交易日志原默认范围；
- 不修改或复用现有风险周期筛选标签。

策略详情使用与 Dashboard 相同的周期解析与筛选函数。周期、日期范围或交易日期发生变化后，Dashboard 总数、策略汇总与下钻列表必须来自同一交易 ID 集合，不允许各页面复制日期判断。

## 11. 持久化、升级与导入导出

### 11.1 旧数据升级

旧快照缺少 `livePerformanceCycles` 时规范化为空数组。升级后 Dashboard 继续显示全部历史，不自动创建边界、不自动猜测起点，也不使用风险核算起点填充。

### 11.2 校验

快照校验与导入校验必须拒绝：

- 非数组集合；
- 缺失或重复 ID；
- 空名称、超长名称或重复名称；
- 非法日期、重复开始日或非严格递增边界；
- 非法 `createdAt`；
- 未知额外字段按项目现有兼容策略处理，不得绕过核心字段校验。

### 11.3 归档与合并

- 完整 ZIP 归档、JSON 快照和可恢复导出包含周期集合。
- 完整替换恢复使用归档中经过校验的周期集合。
- 合并导入沿用“当前交易库配置优先”原则：当前集合非空时保留当前集合并在导入摘要中说明未覆盖；当前集合为空时可接收经过校验的导入集合。
- 周期集合不引用附件，不改变资产清单和垃圾回收规则。
- 持久化 schema/导出版本按项目现有迁移规范递增，并为旧版本提供空数组默认值。

## 12. 错误与空状态

- 周期内没有已平仓实盘时，Dashboard 显示真实空状态，不显示伪造的零胜率或零收益曲线。
- 有已平仓记录但缺少有效平仓交易日时，显示待补数量和进入数据修复的入口；这些记录不静默归入任一周期。
- 周期内结果缺失或冲突继续使用现有数据健康提示。
- 同日重复边界、未来日期、早于或等于当前周期开端的日期在提交前阻止保存，并给出可执行原因。
- 页面 URL 指向已撤销周期时安全回到当前周期。
- 创建、重命名或撤销期间禁用重复提交；关闭弹窗不得绕过正在进行的持久化操作。

## 13. 组件与职责边界

建议拆分为以下独立单元：

1. 周期领域模块：验证周期、排序、推导区间、解析选中周期、按平仓日筛选交易。
2. 周期路由模块：读写和规范化 `statsCycle`，保留无关参数。
3. 周期管理 Store 动作：创建、重命名和撤销最新周期，只管理周期集合。
4. 周期选择器：显示当前、历史、起点前和全部历史。
5. 周期管理弹窗：负责表单、预览、持久化与失败回滚。
6. 统计消费者：Dashboard、策略详情和交易列表只调用共享筛选接口，不自行实现边界判断。

现有 `analysisScope` 继续负责交易类型与相对日期范围；周期模块提供外层实盘集合。现有 `liveCycle` 继续负责风险周期范围，禁止通过重命名或复用字段把两个概念重新耦合。

## 14. 验收测试

### 14.1 领域与统计单测

- 空周期集合保持全部历史。
- 第一条边界生成“统计起点前”与当前周期。
- 多条边界生成互不重叠、完整覆盖的半开区间。
- 周期开始日当天计入新周期。
- 起点前开仓、起点后平仓计入新周期。
- 无效平仓日不归属并进入数据健康计数。
- 模拟盘、案例、未平仓、错过机会和软删除记录被排除。
- 修改平仓日后动态跨周期归属。
- Dashboard、策略统计和列表下钻得到同一交易 ID 集合。
- 现有胜率、盈亏、R、结果冲突和覆盖规则保持不变。

### 14.2 路由与浏览器测试

- 当前周期使用规范 URL，历史周期和全部历史可刷新恢复。
- 无效或已撤销 ID 使用 `replace` 回到当前周期并保留无关参数。
- `kind=paper/all` 清除周期参数。
- Dashboard 切换周期后所有指标、曲线和策略行一致更新。
- Dashboard 跳转策略详情与本周期交易列表时保留范围。
- 交易列表清除周期筛选后恢复现有默认行为。
- `statsCycle` 与 `liveCycle` 冲突时按契约规范化。
- 创建、重命名、撤销及保存失败回滚走真实持久化路径。
- 375、768、1280 和 1920 宽度下选择器、弹窗和空状态可用。

### 14.3 持久化与兼容测试

- 旧快照升级为空集合且统计结果不变。
- 新周期经过刷新、关闭重开、ZIP 归档与完整恢复后保持一致。
- 损坏、重复或乱序周期数据被拒绝。
- 合并导入遵守当前配置优先并给出摘要。
- 案例、来源正文快照和附件引用在全部周期操作后字节级保持不变。

## 15. 完成标准

1. 用户可以多次开始新统计周期，并切换当前、历史、起点前与全部历史。
2. 默认实盘 Dashboard 只统计当前周期，策略详情和列表下钻口径一致。
3. 跨周期交易按平仓交易日归属。
4. 案例、旧实盘、笔记、截图、周复盘与风险设置均不被修改。
5. 首次升级不改变统计，所有周期变更可持久化并在失败时回滚。
6. 最近一次周期可安全撤销，不允许危险的中间边界删除。
