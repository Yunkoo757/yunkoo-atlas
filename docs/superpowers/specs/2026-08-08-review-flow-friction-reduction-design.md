# 随机复盘与工作台减负设计

日期：2026-08-08
状态：已实施并通过完整回归
范围：随机复盘启动流程与图片呈现、工作台主导航、案例详情复制入口

## 1. 背景

随机复盘目前在开始前要求用户逐项选择数据来源、案例范围和正文条件。对于高频复盘，这些选项把本应直接进入内容的动作变成了一次表单填写，增加了重复操作和决策成本。

复盘内容包含多张图片时，图片资源解析和浏览器解码存在短暂时间差。当前界面会直接挂载图片，用户可能先看到高度不一致、画廊尚未稳定的中间状态，随后才切换为正常的等高双列布局。这种跳动会破坏进入复盘时的专注感。

工作台主导航同时提供可见文字、快捷键 Tooltip 和拖拽排序。主导航项目数量少且有明确的信息架构，自定义排序及提示层带来的复杂度高于实际收益。案例详情正文右侧还重复提供“复制 TRD-xxx”，而页面顶部“更多”菜单已经有“复制编号”，造成界面噪音。

本次优化不改变交易复盘软件的定位、随机抽取算法或案例模型，只减少开始复盘和日常导航中的操作负担。

## 2. 目标

1. 用户从随机复盘入口用一次点击即可开启新一轮复盘。
2. 默认复盘池只包含全部案例，避免账户交易混入日常案例复习。
3. 高级筛选仍然可用，但退出主要流程，收纳到“更多”中的“复盘设置”。
4. 多图案例在资源未准备好时保持最终画廊尺寸，整组稳定呈现，不再出现明显跳动。
5. 工作台主导航使用固定标准顺序，不再支持自定义拖拽排序。
6. 移除工作台主导航项目的 Tooltip，同时保留可见名称、键盘焦点和快捷键能力。
7. 移除案例正文中的重复复制按钮，复制编号继续由顶部“更多”菜单提供。

## 3. 非目标

- 不重新设计工作台信息架构或视觉风格。
- 不改变“我的空间”的添加、管理和拖拽排序。
- 不移除全局搜索、创建等纯图标按钮的必要 Tooltip。
- 不移除或重新分配现有键盘快捷键。
- 不改变随机顺序、去重、评分、进度恢复和一轮结束逻辑。
- 不新增独立的全局设置页面，不引入新的持久化 schema。
- 不删除复制编号能力，只调整入口位置。
- 不以固定延时掩盖图片问题；实施前必须用可控的延迟加载复现并定位真实时序。

## 4. 方案选择

采用“默认一键开始 + 更多菜单内临时设置”。

未采用独立全局设置页，因为当前筛选数量少，为此增加设置层级会扩大改动范围，也会让临时筛选难以发现。未采用自动记住上次设置，因为偶尔启用“账户交易”或“仅有正文”后，下一次进入可能在用户不知情时继续使用窄范围，违背降低理解成本的目标。

默认值始终明确、可预测；高级设置只影响当前标签页中的当前轮次。重新打开应用后恢复轻量默认值。

## 5. 随机复盘启动流程

### 5.1 默认状态

随机复盘起始页只保留以下主要内容：

- 当前默认条件下可复盘的案例数量；
- 主按钮“开启一轮新的复盘”；
- 次级“更多”菜单，其中包含“复盘设置”。

默认筛选固定为：

```ts
{
  includeCases: true,
  includeAccountTrades: false,
  caseScope: 'all',
  requireContent: false,
}
```

用户点击主按钮后立即以当前筛选快照建立一轮复盘，不再经过额外确认页。

### 5.2 复盘设置

“更多 → 复盘设置”打开轻量设置面板，沿用现有筛选能力：

- 是否额外包含账户交易；
- 案例范围；
- 是否只包含具有有效富文本正文的记录。

“案例”始终是默认来源。若现有数据约束允许用户关闭案例，则必须保证至少选择一个来源，并在提交前给出就地说明；不得产生一个看似可开始但必然为空的轮次。

设置确认后返回同一起始页，数量预览立即按临时设置更新。设置只保存在当前视图会话中，不写入持久化快照或全局偏好。

### 5.3 一轮结束与再次开始

- “再来一轮”沿用刚完成轮次的筛选快照，适合连续复盘同一批内容。
- “重新设置”打开与起始页相同的设置面板。
- 退出随机复盘后重新进入，恢复默认的“全部案例”条件。

轮次自身继续保存筛选快照，确保刷新恢复、进度统计和再次开始的行为可解释，不在进行中的轮次里隐式切换条件。

### 5.4 空状态

默认案例池为空时：

- 主按钮禁用；
- 明确说明“还没有可复盘的案例，请先创建案例”；
- 不自动回退到账户交易，避免改变用户预期。

高级设置导致结果为空时，说明当前设置下没有可复盘内容，并提供“调整复盘设置”，而不是显示通用错误。

## 6. 图片稳定呈现

### 6.1 用户可见行为

进入某个复盘项后，先按最终图片数量渲染固定尺寸的画廊骨架：

- 单图使用单图最终尺寸；
- 多图使用最终双列网格及统一高度；
- 标题、案例信息和复盘操作区不随图片解码发生位移。

所有图片完成加载或失败判定后，整组从骨架一次性切换为结果：成功图片正常显示，失败图片在原槽位显示稳定的错误占位。不得先逐张显示而让画廊经历多个中间布局。

### 6.2 加载边界

现有正文资源解析仍负责把持久化资源地址转换为浏览器可用地址。界面层在得到当前复盘项的全部图片地址后，执行一组并行预加载与解码：

1. 为当前复盘项生成唯一加载代次；
2. 并行创建图片加载任务；
3. 优先等待 `decode()`，并兼容已经完成加载或不支持该方法的环境；
4. 用 settled 结果记录每个槽位的成功或失败；
5. 仅当本组全部 settled 且代次仍属于当前复盘项时提交显示状态。

快速切换到下一条记录或退出复盘时，旧任务即使随后完成，也不得覆盖当前记录。对象 URL 的释放继续遵守现有资源生命周期，不因预加载增加永久引用。

### 6.3 根因验证要求

截图反映的是资源准备期间的中间布局，但设计不预设唯一根因。实施必须先建立带延迟的浏览器测试，分别观察：

- 正文资源地址解析完成前；
- `<img>` 网络加载完成前；
- 图片完成像素解码前；
- 懒加载视图首次挂载时。

修复应放在最窄且能稳定消除跳动的边界。如果确认问题发生在解码阶段，则采用上述画廊就绪门；若测试证明对象 URL 解析已经向界面暴露部分结果，则先修正解析的原子性，再保留固定骨架作为用户体验保障。

## 7. 工作台主导航

### 7.1 固定顺序

工作台主导航固定为：

1. 今日
2. 随记
3. 交易
4. 案例
5. 周复盘
6. 随机复盘
7. 仪表盘

主导航项目不再设置 draggable 属性，不绑定主导航拖拽开始、经过、放置或结束事件，也不显示拖拽过程样式。

已有持久化的主导航排序字段暂时保留，以维持旧快照和导入数据兼容；界面不再读取该字段决定主导航顺序，也不再写入新的排序结果。这样无需本次增加迁移或破坏旧归档。后续若清理字段，应单独进行 schema 评估。

“我的空间”继续使用现有独立排序逻辑，不受本次调整影响。

### 7.2 Tooltip 范围

只移除工作台七个主导航项目外层的 Tooltip。每项已有可见文字，因此不需要悬停后重复说明。

以下行为必须保留：

- 可见导航名称；
- 当前项状态；
- 键盘焦点样式和无障碍名称；
- 已有快捷键触发能力；
- 搜索、创建等纯图标按钮的 Tooltip；
- “我的空间”中确有解释需要的提示。

## 8. 案例复制入口

案例正文标题区域不再显示“复制 TRD-xxx”按钮，并清理只服务于该按钮的无用样式。

页面顶部现有“更多 → 复制编号”保持原文案、剪贴板行为和成功/失败反馈。复制能力只有一个低频入口，不再占用正文阅读区域。

交易详情及其他页面若存在不同用途的复制按钮，不在本次范围内，不能通过全局选择器误删。

## 9. 组件与状态边界

建议沿用现有组件结构做局部收敛：

1. `ReviewSessionStart`：只负责数量、开始动作和打开“更多”。
2. 复盘设置面板：负责编辑当前视图的临时筛选，并把确认后的完整筛选对象交回起始页。
3. 复盘轮次创建逻辑：继续复制筛选快照，避免引用后续可变设置。
4. 图片就绪控制：位于复盘正文/画廊边界，以复盘项 ID 和加载代次隔离异步结果。
5. `Sidebar`：直接从规范主导航常量渲染工作台项目；“我的空间”的排序状态与事件保持独立。
6. `DetailView`：移除正文复制入口，复用现有顶部菜单动作，不增加第二套剪贴板逻辑。

如设置面板仅服务于随机复盘，可先保留在随机复盘模块附近；不为了形式拆出全局设置基础设施。

## 10. 错误处理与无障碍

- 图片加载失败时显示有文字含义的占位，并保留槽位尺寸；不能只留下破图图标。
- 画廊加载状态应具备适当的可访问状态，但不得对每张图片重复播报造成干扰。
- 设置面板打开后焦点进入面板，关闭后回到触发按钮；Escape 和取消不保存草稿。
- 开始按钮在忙碌期间禁止重复触发，并保留现有轮次创建失败反馈。
- 主导航移除 Tooltip 后，交互元素仍须具有可访问名称，键盘用户能确认当前页面。
- 复制编号失败继续使用现有错误反馈，不因入口移动而静默失败。

## 11. 测试策略

实施遵循 RED → GREEN → REFACTOR，先用真实失败证明每一项改动。

### 11.1 随机复盘流程

- 默认筛选只包含全部案例，不包含账户交易。
- 起始页不再直接显示多组选项，一次点击建立轮次。
- “更多 → 复盘设置”可以改变本轮临时条件和数量预览。
- 新轮次保存独立筛选快照；“再来一轮”沿用该快照。
- 重新进入页面恢复轻量默认值。
- 默认无案例与高级筛选为空显示不同、可执行的说明。

### 11.2 图片时序

- 人为延迟第二张图片时，最终画廊槽位从首次呈现起尺寸不变。
- 第二张图片未就绪前，第一张也不提前暴露为半完成画廊。
- 全部 settled 后整组显示。
- 单图失败和多图部分失败均保持稳定占位。
- 快速切换记录后，旧记录迟到的成功或失败结果不影响新记录。
- 在目标桌面宽度及窄视口验证没有横向溢出或高度突变。

### 11.3 导航与详情

- 工作台主导航始终按规范顺序渲染，旧持久化顺序不改变结果。
- 拖动主导航不能重排，也不产生排序写入。
- 悬停或聚焦主导航项目不出现 Tooltip。
- 导航快捷键、焦点与当前项状态保持可用。
- “我的空间”仍可拖拽排序。
- 案例正文中不存在复制编号按钮；顶部“更多 → 复制编号”仍能复制正确编号。

### 11.4 完整门禁

- 相关领域与回归单元测试；
- 随机复盘、Sidebar 和 DetailView 浏览器测试；
- 375、768、1280 与 1920 关键视口；
- TypeScript 类型检查；
- 完整测试套件和生产构建；
- 设计治理、移动 QA、`git diff --check`；
- 所有变更文件严格 UTF-8、无 BOM。

## 12. 完成标准

1. 默认用户从随机复盘入口到看到第一条内容只需一次主要点击。
2. 默认复盘池为全部案例，高级筛选可发现但不阻挡主要流程。
3. 多图复盘在延迟加载环境中不存在可见的非最终尺寸阶段，失败图片也不引发布局跳动。
4. 工作台主导航固定顺序、不可拖拽且不显示重复 Tooltip，“我的空间”排序不受影响。
5. 案例正文阅读区不再显示复制编号，顶部“更多”仍完整保留能力。
6. 不改变既有轮次恢复、随机算法、评分、案例数据、快捷键、持久化兼容和对象资源生命周期。
7. 聚焦测试、完整测试、类型检查、构建、视口回归与 UTF-8 无 BOM 检查全部通过。
