# Trader Atlas 实盘新周期与规则前历史设计

> 日期：2026-07-28
> 状态：已确认，待实施
> 基线：`codex/fix-star-and-risk-gate@573f04d`
> 范围：实盘统计起点、规则前历史、风险预算、今日工作台、策略统计、周复盘与交易历史筛选
> 数据版本：`PersistedSnapshot` Schema v9（向后兼容可选字段）

## 1. 结论

本功能不把真实交易迁移为模拟盘，也不改写历史交易。系统新增一个可撤销的“实盘统计起点”，以此建立当前实盘周期：

1. 当前资料库的建议起点为 `2026-07-27`，即首条已确认风险规则的生效日。
2. 交易按开仓交易日归属周期；起点前开仓的实盘交易属于“规则前实盘”，起点当日及之后开仓的实盘交易属于“当前周期”。
3. 规则前实盘保留真实类型、详情、截图、笔记、标签、复盘和活动记录，但不参与当前周期的风险、工作台、策略绩效和新生成的周复盘事实。
4. 历史页提供“当前周期 / 规则前 / 全部实盘”筛选，让旧记录保持可见、可搜索、可复盘。
5. 设置只保存一个资料库级日期，不批量改写交易；修改或清除起点即可恢复统计，因而无需逐笔撤销。

该设计的核心是“建立新的统计口径”，而不是“伪造新的交易类型”。

## 2. 背景与问题

风险规则在已有实盘历史之后才引入。当前月份包含 17 笔实盘记录，其中 16 笔发生在规则生效前，缺少当时可验证的账户 1R；只有 1 笔发生在规则生效后。

不能采用以下补救：

- 用当前 1R 追溯计算旧交易，因为这会制造虚假的历史风险数据；
- 逐笔补录旧规则，因为实际 1R 变化且已无法可靠还原；
- 把真实交易改为“模拟盘”，因为这会同时污染模拟盘统计与历史真实性；
- 继续把旧交易显示为“覆盖未知”，因为缺口来自规则尚未存在，而不是当前执行失控。

因此需要明确切分“规则前历史”和“当前实盘周期”。

## 3. 目标与非目标

### 3.1 目标

- 在不改写交易事实的前提下，从首条正式风险规则开始新的实盘统计周期。
- 让当前风险预算只由适用现行规则的交易决定。
- 让每天打开的工作台默认聚焦当前周期，不再被旧体系数据干扰。
- 保留完整实盘历史，并允许用户显式查看全部或规则前记录。
- 保证所有当前周期入口使用同一口径，避免页面间统计不一致。
- 提供清晰的影响预览以及无损撤销能力。

### 3.2 非目标

- 不修改任何交易的 `tradeKind`。
- 不补造历史 `riskAmount`、`budgetR` 或风险规则版本。
- 不删除、复制或重新编号历史交易。
- 不重写已经冻结的周复盘事实快照。
- 不建立多账户、多阶段资金曲线或任意数量的命名周期。
- 不改变模拟盘和案例研究现有语义。

第一版只支持一个可选的资料库级实盘统计起点。

## 4. 术语与归属规则

| 术语 | 定义 |
|---|---|
| 实盘统计起点 | 当前实盘周期的首个有效开仓交易日，包含该日 |
| 当前周期 | 开仓交易日大于或等于统计起点的实盘交易 |
| 规则前实盘 | 开仓交易日早于统计起点的实盘交易 |
| 全部实盘 | 不应用统计起点过滤的全部实盘交易 |

### 4.1 周期归属

交易归属必须按“开仓交易日”判断，因为风险规则约束的是开仓决策，而不是平仓时间：

```text
tradeKind !== live                 -> 不属于实盘周期
liveStatsStartTradingDayKey = null -> 所有实盘均属于当前周期
openedTradingDayKey < start        -> 规则前实盘
openedTradingDayKey >= start       -> 当前周期
```

旧仓位即使在起点之后平仓，也仍属于规则前实盘。起点当日开仓的交易包含在当前周期中。

`openedTradingDayKey` 必须复用现有交易日开始小时与日期解析规则。纯 `YYYY-MM-DD` 保持原日期；带时间的值按资料库当前交易日起始小时换算，不得直接用字符串截取或 UTC 日期比较。

### 4.2 异常日期

设置预览发现无法解析开仓日期的实盘记录时，不得静默归类。预览列出“无法判断”的记录并阻止确认，用户修正日期后再设置起点。正常导入和创建流程仍应保证 `openedAt` 有效。

## 5. 用户体验

### 5.1 入口

当系统同时检测到以下条件时，在风险预算区域提供低干扰入口“建立实盘统计起点”：

- 已存在有效风险规则；
- 有实盘交易的开仓交易日早于最早有效规则；
- 尚未设置实盘统计起点。

设置页的数据或风险设置区域同时保留常驻入口“实盘统计起点”，用于查看、修改或清除当前设置。完成设置后，风险卡中的引导入口消失。

### 5.2 设置与影响预览

首次打开时默认建议最早有效风险规则的生效日。本资料库预计展示：

- 统计起点：2026-07-27；
- 规则前实盘：16 笔；
- 当前周期：1 笔；
- 无法判断：0 笔。

预览必须展示会改变的统计范围，并明确说明“不会修改或删除交易”。用户确认后只保存起点设置，不执行交易批量更新。

日期不得晚于当前交易日。若选择的日期与任何风险规则都不重叠，界面给出明确警告，但数据层仍以风险规则是否实际生效为准，不能伪造覆盖完整。

### 5.3 设置完成后的反馈

确认成功后：

- 风险卡标题显示类似“本月 · 自 7月27日起”；
- 规则前缺失的 1R 或风险规则不再显示为当前周期“覆盖未知”；
- 页面提示“16 笔规则前实盘已从当前周期统计中排除”；
- 提供“查看规则前记录”和“撤销设置”操作；
- 不使用危险、违规或错误色表达规则前记录。

清除起点后恢复原来的全历史统计口径，并再次显示设置前真实存在的覆盖状态。

### 5.4 交易历史

实盘历史筛选新增三个互斥范围。交易日志承担完整档案职责，因此缺省展示“全部实盘”；统计起点只改变风险、工作台与绩效口径，不得静默隐藏历史记录：

1. 全部实盘：默认值，显示完整实盘历史；
2. 当前周期：显式筛选，只显示当前周期实盘；
3. 规则前：显式筛选，只显示规则前实盘。

规则前交易在列表和详情中使用中性标签“规则前”。标签是派生状态，不写入交易实体。搜索、标签筛选和排序在周期范围内继续生效。

## 6. 各页面统计口径

### 6.1 当前周期口径

以下日常页面默认只消费当前周期实盘：

- 今日工作台的行动队列、今日战绩和待复盘数据；
- 日、周、月风险预算及首次开仓 Gate；
- 策略表现、策略 KPI 和当前实盘汇总；
- 新创建或尚未冻结的周复盘事实；
- 其他明确标注“当前实盘”的指标。

实现不得在各页面重复手写日期条件。应提供唯一的领域判断与选择器，例如：

```ts
isTradeInCurrentLiveCycle(trade, liveStatsStartTradingDayKey, tradingDayStartHour)
selectCurrentLiveCycleTrades(trades, liveStatsStartTradingDayKey, tradingDayStartHour)
```

所有消费方复用该逻辑。

### 6.2 全历史口径

以下能力继续保留全部事实：

- “全部实盘”和“规则前”历史视图；
- 单笔详情、搜索、导出和完整资料库备份；
- 已经冻结的历史周复盘；
- 数据完整性、重复检测和资产引用检查。

导出不得因为统计起点而丢弃规则前交易。

### 6.3 风险预算

风险预算先按开仓交易日过滤到当前周期，再按既有平仓交易日规则分配到日、周、月：

1. 规则前交易完全不进入当前风险候选集合；
2. 当前周期交易继续使用平仓业务日对应的有效风险规则；
3. 当前周期内缺失 PnL、日期冲突或缺少有效规则时，仍保持 `partial` / `unknown` 和现有 Gate 行为；
4. 起点只消除规则前历史造成的假性缺口，不降低当前周期的风险保护；
5. 周期标题在统计起点截断当前自然周期时显示“自 M月D日起”，但止损限额仍沿用该日有效规则，不按天数折算。

例如起点为 2026-07-27 时，7 月月度预算只统计当前周期交易，但月限额仍为完整的 10R；系统不得把限额按剩余天数缩小或放大。

## 7. 数据模型与持久化

`PersistedSnapshot` 在现有 Schema v9 内新增向后兼容的资料库级可选字段：

```ts
interface PersistedSnapshot {
  // existing fields...
  liveStatsStartTradingDayKey?: string | null
}
```

Store 暴露最小动作：

```ts
setLiveStatsStartTradingDayKey(value: string | null): void
```

规则：

- 缺少字段与显式 `null` 都规范化为 `null`，保持升级前行为不变；
- 字段存在时必须严格校验为 `null` 或有效 `YYYY-MM-DD`；
- 该字段“缺失即未启用”，属于可安全默认的附加设置，因此不触发 Electron 文件级 Schema 迁移；
- Electron 快照、Web 归档、JSON 导入导出、空资料库、测试 fixture、资料库切换和恢复必须完整携带该字段；
- 不把领域设置塞入 `DisplayPrefs`，也不写入单笔交易；
- 设置保存继续走现有持久化提交与并发保护，不新增旁路存储。

完整恢复或资料库切换采用目标资料库自己的统计起点。普通“合并导入”只合并交易与内容，保留当前资料库的统计起点；不得让外部文件在无确认的情况下改变当前统计口径。

设置变更是单字段原子提交。由于没有交易批量更新，撤销只需把字段恢复为先前值；无需创建 16 条伪活动或维护跨交易撤销栈。

## 8. 已冻结复盘与后续复盘

- 已完成并冻结的历史周复盘保持原样，不因统计起点变化而重算。
- 新创建或未冻结的周复盘只使用当前周期实盘生成事实。
- 若某一周跨越统计起点，规则前开仓的交易不进入该周的新事实，即使它在该周平仓。
- 周复盘界面在首个截断周显示“当前周期自 2026-07-27 开始”，避免用户误认为这是完整自然周。

## 9. 状态与失败处理

| 场景 | 行为 |
|---|---|
| 未设置起点 | 保持现有全历史行为 |
| 起点早于所有交易 | 当前周期等同全部实盘 |
| 起点晚于所有交易 | 当前周期为空，预览明确提示 |
| 起点为今天 | 仅今天及以后开仓的实盘进入当前周期 |
| 无有效风险规则 | 允许查看设置，但不宣称风险覆盖完整 |
| 开仓日期无法解析 | 阻止确认并列出记录 |
| 设置保存失败 | 保持旧值和旧统计，不展示成功反馈 |
| 清除起点 | 恢复全历史口径，不修改交易 |
| 导入未包含该字段的 v9 资料库 | 规范化为 `null`，不擅自建立周期 |

## 10. 验收标准

### 10.1 当前资料库

1. 选择 2026-07-27 后，预览显示 16 笔规则前实盘、1 笔当前周期、0 笔无法判断。
2. 确认后，所有 17 笔交易仍为 `live`，ID 与内容不变。
3. 本月风险不再因这 16 笔规则前交易显示“覆盖未知”。
4. 当前周期中的真实缺失或触线仍会触发开仓确认。
5. 交易历史可分别查看 1 笔当前周期、16 笔规则前记录和 17 笔全部实盘。
6. 清除设置后恢复原来的全历史统计与覆盖提示。

### 10.2 自动化验证

- 周期归属单元测试覆盖边界日、带时区时间、交易日起始小时和非法日期。
- 风险预算测试证明规则前亏损不参与当前周期，边界日亏损正常参与。
- Gate 测试证明旧缺口不拦截，但当前周期未知风险仍拦截。
- 工作台、策略统计、交易历史和周复盘口径一致性测试通过。
- v9 缺省兼容、非法值拒绝、导入导出、资料库切换和恢复测试通过。
- 设置、修改、清除起点的持久化测试通过。
- `pnpm test`、`pnpm build` 和 Windows 桌面端打包验证通过。

## 12. 设计裁决摘要

| 决策点 | 裁决 |
|---|---|
| 是否迁移为模拟盘 | 否，保留真实实盘类型 |
| 是否改写历史交易 | 否，只保存资料库级统计起点 |
| 周期按何时归属 | 按开仓交易日 |
| 起点是否包含当天 | 包含 |
| 日常页面默认范围 | 当前周期 |
| 旧记录如何访问 | 规则前与全部实盘筛选 |
| 风险限额是否按剩余天数折算 | 否 |
| 当前周期未知风险如何处理 | 保持现有 unknown 与 Gate |
| 已冻结复盘是否重算 | 否 |
| 撤销方式 | 修改或清除统计起点 |
