# Trader Atlas 实盘阶段统一设计

> 本设计取代既有“重置实盘统计”与“风险核算起点”作为两套常规边界的产品语义，并覆盖《历史实盘模块设计》中“不改变重置逻辑”和“只提供全部归档范围”的旧结论。交易、案例、图片与周复盘仍然保留，不做破坏性迁移。

## 背景

当前产品同时存在三套容易混淆的时间概念：

- 风险核算起点决定风险额度与开仓门禁从何时开始计算。
- 实盘统计重置点决定交易属于当前交易日志还是历史实盘。
- 周复盘按自然周长期保留，并且刻意不受风险起点截断。

三套规则分别合理，但用户看到“核算起点”后会自然理解为整个实盘阶段的起点。当风险起点早于当前实盘周期时，起点之后的交易仍然可能留在历史实盘；周复盘也不会随重置消失。界面虽然提供了说明，仍然需要用户理解内部实现，破坏直觉。

## 目标

- 用“实盘阶段”统一交易归档、绩效统计和常规风险核算边界。
- 每次开启新阶段都完整保留旧阶段，支持回看、筛选、比较和重命名。
- 周复盘保持自然周连续，不因阶段切换被删除或拆成两份。
- 阶段只允许在交易周开始时生效，杜绝周中切换和跨阶段周复盘。
- 已归属阶段的交易不因平仓、状态变化或普通日期编辑在阶段之间跳动。
- 将独立风险日期调整降级为高级数据修复能力，并显式记录偏离原因。
- 为现有数据提供可解释、无损且可回退的迁移方案。

本设计仅面向 Windows 与 macOS 桌面客户端，不考虑手机、iPad、浏览器或其他平台。

## 产品原则

> 事实永不删除，阶段负责分界，统计按阶段计算，周复盘保持时间连续。

- “开启新实盘阶段”不是清空资料，而是关闭一个统计时期并开始下一个时期。
- 交易、案例、图片、评论、复盘正文和已完成快照都是事实记录，不随阶段切换删除。
- 当前工作面默认只呈现当前阶段；旧事实通过历史实盘和阶段筛选继续可达。
- 风险与绩效的常规起点必须一致，不能在普通设置中形成不可见的第二条时间线。

## 方案选择

### 方案 A：只优化名称与说明

继续保留风险起点和实盘归档两套边界，只重写文案。实现成本最低，但用户仍需理解两个日期，无法消除记录位置与起点不一致的问题。

### 方案 B：统一实盘阶段

每次开启新阶段都追加永久阶段边界。交易日志、历史实盘、绩效和常规风险均使用同一阶段；周复盘保留并标记阶段。

采用方案 B。它统一用户心智，同时保留长期交易与复盘历史，改造范围可控。

### 方案 C：完整工作区快照

每次切换都冻结交易、策略、风险和周复盘的完整副本，新阶段从空白工作区开始。边界最彻底，但会割裂策略与复盘脉络，引入大量复制、迁移和一致性成本，不采用。

## 周边界与生效规则

### 唯一合法边界

- 阶段起点必须是交易周周一，并服从用户配置的交易日起始小时。
- 阶段起点必须晚于当前阶段起点，并且必须等于本次合法生效周的周一；常规流程不允许回填旧周或跳过多周预约。
- 不提供任意日期作为常规阶段起点；例如周六日期必须规范到合法的周一起点后再确认。

### 立即开启与预约

- 只有当前交易日为周一且本周尚无任何实盘活动时，才允许立即开启新阶段。
- “实盘活动”包括已创建实盘计划、实际开仓、平仓结果、错过机会及其他已经归属本周的实盘事实。
- 周一已经存在实盘活动，或当前处于周二至周日时，只能预约下一个周一生效。
- 周中或周末可以安排下周阶段；生效前允许取消或修改名称。
- 同一时间只能存在一个待生效阶段。

### 延迟启动

如果客户端在生效周一没有运行，下次启动时补执行阶段激活。阶段的有效起点仍为预约周一，不改成实际启动日期。激活前先完成版本与冲突校验，避免双重阶段边界。

## 阶段模型

每个阶段至少保存：

- 稳定 ID。
- 用户可修改的名称。
- 周一起始交易日。
- 创建时间与实际激活时间。
- 当前、已结束或待生效状态。
- 阶段关闭时冻结的风险摘要。

阶段按照起点升序排列。阶段结束边界由下一阶段起点推导，最后一个已生效阶段为当前阶段。阶段一旦承载实盘事实，其起点不可通过普通设置修改；名称和说明仍可调整。

新阶段默认命名为“实盘阶段 N · YYYY-MM-DD 起”，用户可以改为“恢复纪律阶段”“导航4验证期”等有意义名称。

## 交易归属

### 稳定归属

- 实盘记录新增稳定的阶段归属 ID，而不是每次渲染时只按当前日期边界重新推导。
- 新建实盘计划时归属当前阶段。
- 交易实际开仓后锁定阶段归属；后续平仓、修改结果或补充复盘都不改变阶段。
- 重置日前已经持仓的交易永久属于旧阶段，重置后平仓产生的盈亏也计入旧阶段，不污染新阶段绩效。
- 普通编辑如果跨越阶段边界，不自动迁移交易；需要进入数据修复并明确确认影响。

### 跨阶段计划

旧阶段未开仓计划在新阶段激活后进入“待整理”，不直接占用当前交易日志：

- “保留归档”保留原计划及旧阶段归属。
- “复制到当前阶段”创建独立新计划并保留来源关系，原计划不被修改。

日期缺失、导入冲突或无法可靠判断归属的历史记录同样进入“待整理”，不得猜测并入当前阶段。

## 风险与绩效

### 常规行为

- 当前阶段起点是风险额度、开仓门禁和当前阶段绩效的共同起点。
- 新阶段真正激活时才清空当前风险准备、风险政策版本、月度限额、风险覆盖事件和待处理开仓请求。
- 安排阶段时不提前清空任何风险状态。
- 激活采用单次原子状态变更：关闭旧阶段、冻结旧阶段风险摘要、激活新阶段、切换当前范围并重置风险状态必须全部成功或全部回滚。

### 高级风险修复

普通设置不再提供可随意调整的“风险核算起点”。高级数据修复中保留“单独校正风险起算日”，用于迁移错误或历史日期错误：

- 明确提示该操作只影响风险，不移动交易，也不修改阶段。
- 保存覆盖日期、原因、创建时间和来源版本。
- 存在覆盖时，风险页与数据页持续显示“风险起点已偏离当前阶段”的状态，不允许静默分叉。
- 覆盖可以在确认后恢复为“跟随当前阶段”。

## 周复盘

- 周复盘继续按周一至周日的自然交易周存在，每周只有一份。
- 因为阶段只能从周一开始，一个周复盘只属于一个阶段，不再设计周中分段。
- 周复盘保存阶段 ID，标题区显示所属阶段标签。
- 阶段切换不删除旧周复盘，不清空复盘正文、承诺、评分或已完成状态。
- 已完成周复盘继续使用完成时冻结的交易、证据和风险快照；后续交易修改不能静默重写历史结论。
- 当前周复盘使用当前阶段事实；上一周承诺验证保持连续，不因阶段切换断开。
- 年度趋势默认展示全年连续历史，同时允许筛选某个阶段进行比较。

## 页面与交互

### 设置页

- 主标题使用“当前实盘阶段”，展示名称、开始日期、持续周数和核心表现。
- 主操作使用“安排下周新阶段”或合法周一条件下的“立即开启新阶段”。
- 待生效状态明确显示生效日期，并提供取消动作。
- 确认窗口必须展示：新阶段起点、进入新阶段的记录数、归入旧阶段的记录数、待整理计划数、保留周复盘数及将被重置的风险状态。
- 确认文案使用“开启阶段”，不再使用可能暗示删除资料的“清空”或笼统“重置”。

### 交易日志

- 默认只显示当前阶段记录。
- 页面标题旁展示“当前阶段：名称 · 日期起”。
- 单独风险覆盖不影响交易日志成员范围。

### 历史实盘

- 按已结束阶段分组，支持全部历史和指定阶段筛选。
- 每个阶段展示起止日期、交易数、胜率、净盈亏、平均 R 与关联案例数量。
- 进入阶段后继续复用交易日志的列表、看板、筛选和显示逻辑，不维护第二套行样式。
- 阶段内同时提供“实盘记录”和“关联案例”；案例通过来源交易的阶段归属投影。

### 周复盘与仪表盘

- 周复盘列表和详情显示阶段标签，历史记录始终保留。
- 仪表盘默认展示当前阶段，可切换全部历史或指定阶段。
- 风险卡只展示当前阶段或明确的风险覆盖范围，不能将旧阶段风险混入当前状态。

### 数据修复

- 独立风险日期调整移入高级修复入口。
- 阶段归属冲突、缺失阶段和日期不足进入待整理/修复队列。
- 修复动作必须预览会受影响的交易、绩效与周复盘，不提供静默批量改写。

## 数据迁移

迁移必须无损且可重复执行：

1. 将仍然存在的实盘周期边界按时间顺序转换为阶段。
2. 如果旧版本只保留了最新单一边界，则从边界前最早的可靠实盘活动周一创建“历史实盘（迁移）”，承接边界之前的记录，并以最新边界创建当前阶段；无法得到可靠日期的记录进入待整理。
3. 已经被旧逻辑覆盖而不存在于持久化数据中的更早重置边界无法可靠恢复，不根据交易分布猜测重建。
4. 完全没有周期边界时，以最早可靠实盘活动所在周的周一创建“初始实盘阶段”；没有实盘活动时使用当前周一。
5. 交易优先按可靠开仓交易日归属；缺失开仓日时使用现有可靠业务日期并标记为迁移推导；仍无法判断时进入待整理。
6. 周复盘按其周一起始日归属对应阶段。
7. 旧风险起点与当前阶段不一致时，将其迁移为显式风险覆盖并显示提示，不移动交易。

迁移提交前保留旧字段快照和迁移版本；失败时恢复迁移前状态。完整备份与 JSON 合并继续保留原始字段，直到兼容窗口结束。

## 冲突与异常

- 预约阶段与远端/备份产生不同边界时不自动合并，要求用户选择可信版本。
- 阶段激活任一步骤失败时，当前阶段与风险状态保持原样，并显示可重试错误。
- 预约日期因交易日起始小时变化而失效时，必须重新确认合法周一起点。
- 已有事实的阶段边界不允许普通撤销；数据修复必须显示成员变化预览并创建审计记录。
- 完全缺失阶段归属的记录不进入任何绩效统计，但必须在待整理入口可见。

## 组件与数据流边界

- 阶段域负责阶段排序、当前/历史范围、合法周一、预约、激活和成员归属。
- 风险域消费当前阶段起点或显式风险覆盖，不反向修改阶段。
- 交易日志、历史实盘、周复盘和仪表盘只消费统一阶段范围，不自行重算另一套边界。
- 阶段摘要与周复盘快照是冻结证据；实时交易列表仍以交易实体为事实来源。
- 页面查询参数可以表达当前阶段筛选，但持久化阶段 ID 才是归属真值。

## 验证方案

### 纯函数与状态测试

- 合法周一、交易日起始小时和下一周起点计算。
- 周一无活动立即开启、周一有活动阻止开启、周中只能预约。
- 预约取消、延迟补生效和重复激活幂等性。
- 阶段激活的原子提交与失败回滚。
- 跨阶段持仓平仓后仍属于旧阶段。
- 旧计划进入待整理，复制后新旧记录与阶段关系正确。
- 风险覆盖不改变交易阶段，恢复跟随后重新使用当前阶段起点。
- 单边界、多边界、无边界、日期缺失和风险起点冲突迁移。

### 桌面交互测试

- 设置页能够安排、取消和在合法周一立即开启阶段。
- 确认窗口的影响数量与最终结果一致。
- 交易日志只显示当前阶段，历史实盘按阶段筛选且复用同一列表逻辑。
- 周复盘保留旧周并显示正确阶段，年度趋势可切换阶段。
- 仪表盘当前、全部和指定阶段范围一致。
- Windows 与 macOS 桌面窗口下键盘焦点、弹窗、滚动和长阶段名称无溢出。

## 非目标

- 不删除或复制历史交易、案例、图片和周复盘正文。
- 不将策略实体强制复制到每个阶段；策略只作为交易引用与统计维度。
- 不允许阶段在周中生效。
- 不自动猜测已经丢失的旧重置边界。
- 不为手机、iPad、浏览器或其他平台提供适配。

## 完成标准

- 用户只需理解一个常规边界：“当前实盘阶段从哪一周开始”。
- 阶段只能在合法周一生效，周中只能预约下周阶段。
- 风险、绩效、当前交易日志和历史实盘使用同一阶段真值。
- 每次开启都永久保留独立历史阶段，并支持筛选、比较和重命名。
- 旧阶段持仓在后续平仓时不会跳入当前阶段。
- 周复盘不被清空，每周只属于一个阶段且历史快照稳定。
- 独立风险日期只存在于显式高级修复流程，并持续提示偏离状态。
- 现有数据迁移无丢失，无法可靠恢复的边界不会被系统伪造。
- Windows 与 macOS 桌面端全部自动化与构建验证通过。
