# “错过的机会”视觉与心流统一设计

## 1. 背景与问题

“错过的机会”已经具备固定入口、跨工作区聚合、来源筛选和回源能力，但当前页面的视觉表达与交易日志、模拟盘等主工作台明显割裂：

- 页面首屏以大面积“管理包含范围”配置区开场，视觉上更像设置页，而不是记录工作台。
- 来源范围、总数、临时筛选和数据列表分属多个横向区域，用户需要来回扫描才能理解当前结果。
- 大号描边来源按钮、独立筛选按钮和自定义列表行没有复用现有工作台的字体、密度、间距与交互反馈。
- 记录列表的焦点线、列间节奏、语义色和空状态与相邻页面不同，切换页面时产生明显的认知和视觉跳跃。
- 页面最醒目的内容是来源配置和总数，而用户进入页面后的核心任务应是浏览机会、判断记录并回到对应工作区。

本次设计只修复呈现层和操作心流，不重做已确认的聚合业务逻辑。

## 2. 设计目标

1. 让“错过的机会”成为现有工作台体系中的自然聚合视图，而不是独立的设置页面。
2. 用户第一眼看到记录和当前结果范围，并能在一条工具栏内完成范围调整与临时筛选。
3. 字体、间距、列表密度、按钮、菜单、反馈和空状态复用现有设计语言。
4. 保留跨工作区来源识别和回源能力，同时降低来源信息对品种与机会摘要的干扰。
5. 在桌面、平板和手机上保持连续、可预测的浏览与返回心流。

## 3. 非目标

- 不修改跨工作区聚合、排序、合并与去重规则。
- 不修改侧栏计数及其口径。
- 不修改临时筛选的 URL 状态、返回现场恢复和滚动恢复逻辑。
- 不改变交易日志、模拟盘、案例记录的详情路由与编辑职责。
- 不新增“执行缺口”、闭环进度或新的业务数据类型。
- 不系统性重做其他工作台页面或全局设计系统。

## 4. 已确认的信息架构

页面从上到下只保留三个稳定层级：

1. **工作台顶栏**：标题“错过的机会”，辅助上下文“跨工作区汇总”。
2. **单行工具栏**：左侧显示结果口径和已启用的临时筛选，右侧提供“范围”和“筛选”。
3. **机会列表**：使用与交易日志、模拟盘一致的紧凑列表语言呈现聚合记录。

原有常驻的“管理包含范围”标题、说明、大号来源按钮和右侧独立总数全部移除。包含范围仍是页面的重要能力，但降级为工具栏中的按需操作。

## 5. 页面结构与组件规则

### 5.1 顶栏

- 复用工作台现有 `Topbar` 的高度、左右内边距、下边框和标题样式。
- 主标题：`错过的机会`。
- 辅助上下文：`跨工作区汇总`，不再使用“来自你选择的工作区”。
- 主标题与辅助上下文之间沿用相邻工作台的分隔符和间距，不创建新的面包屑样式。
- “已保存”等状态只在发生需要持久化的范围变更后短暂反馈，不作为常驻顶栏元素抢占注意力。

### 5.2 单行工具栏

桌面端工具栏高度与交易日志现有筛选栏一致，建议内容高度 32px、区域上下内边距 8px、左右内边距 16px。

左侧：

- 默认显示 `全部机会 28`，其中名称使用 13px 常规字重，数量使用同字号的次要文本色或现有计数样式。
- 启用日期、品种、方向或原因筛选后，在其后显示现有紧凑筛选标签。
- 标签高度 28px，标签间距 6px；超出可用宽度时优先收起为已有的筛选汇总表达，不允许把工具栏撑成多行。

右侧：

- `范围 · 3`：使用标准次级工具按钮，桌面高度 32px，图标与文字间距 6px。
- `筛选`：复用现有筛选按钮及图标，不另造圆角、描边或悬浮效果。
- 两个按钮间距 8px；不使用紫色描边表达普通选中状态。
- 存在临时筛选时，“筛选”按钮使用现有激活态并显示筛选数量；强调只出现一次，避免与范围按钮竞争。

### 5.3 范围选择浮层

点击 `范围 · 3` 打开锚定在按钮下方的标准 `Popover/Menu`：

- 宽度 240–280px，使用现有菜单背景、边框、圆角、阴影和 8px 内边距。
- 依次显示 `交易日志 5`、`模拟盘 23`、`案例记录 0`。
- 每行高度不低于 36px；左侧为标准复选框和来源名称，右侧为低强调数量。
- 选择变化立即生效，工具栏结果数和列表同步更新；不增加“确认”按钮或二次提交步骤。
- 至少保留一个来源。用户试图关闭最后一个来源时保持原选中状态，并在浮层内显示简短说明“至少保留一个工作区”。
- 变更成功后使用礼貌级状态播报，例如“已显示交易日志和模拟盘，共 28 条机会”；不使用阻断式弹窗。
- 点击浮层外、按 `Escape` 或重新点击触发器均关闭浮层，并将焦点返回触发器。

### 5.4 机会列表

列表复用工作台的表格式记录行，不使用卡片化堆叠：

- 桌面行高 44px，左右内边距 16px，列间距服从现有栅格。
- 行内信息顺序为：来源、品种、方向、摘要、发生日期、行尾更多菜单。
- 来源使用 12px 次要文本，不制作高饱和标签；来源必须以文字出现，不能只靠颜色区分。
- 品种使用 13–14px、中等或半粗字重，是每行第一视觉焦点。
- 方向使用 12–13px 中等字重。做多/做空沿用现有语义色，但降低相对饱和度，避免压过品种。
- 摘要使用 12–13px 常规字重、次要文字色，单行省略；不得因长文本挤压日期与行尾操作。
- 日期使用 12px 次要文字色、右对齐、禁止换行。
- 行间仅使用现有低对比度分隔线，不增加自定义紫色整行焦点线。
- Hover、Pressed 和键盘 Focus 复用工作台已有浅层背景与焦点环。焦点环应围绕可操作行或行尾按钮，不跨越整个内容区域。

普通记录整行点击进入唯一来源详情。键盘用户可通过 `Enter` 或 `Space` 打开，行尾更多菜单提供可读的来源动作。

存在明确来源关系的合并记录显示低强调文本 `关联 2 个案例`。原始记录与案例的具体入口收进标准行尾更多菜单，避免在主行内堆叠多个按钮。菜单项写完整动作名称，例如“打开原始交易记录”“打开关联案例”。

### 5.5 数据区滚动与稳定性

- 顶栏和工具栏保持现有工作台的固定关系，数据区独立滚动。
- 列表不因 0、1 或大量记录改变顶栏与工具栏位置。
- 长品种名、长摘要和三位数结果数必须在 1280px 桌面宽度下不产生横向滚动。
- 返回页面时恢复筛选、滚动位置和原记录焦点；视觉层不得用自动聚焦样式制造整行高亮横线。

## 6. 字体、间距与视觉令牌

本页面不得使用局部硬编码建立新的视觉尺度，优先映射现有工作台令牌：

| 元素 | 规则 |
|---|---|
| 页面主标题 | 与现有 `Topbar` 标题完全一致，不单独放大 |
| 工具栏主要文字 | 13px，常规或中等字重 |
| 列表品种 | 13–14px，中等或半粗字重 |
| 列表元数据 | 12–13px，常规字重 |
| 辅助/日期/数量 | 12px，次要文字色 |
| 桌面横向页面内边距 | 16px，与相邻工作台一致 |
| 移动端横向页面内边距 | 12px |
| 紧凑控件高度 | 桌面 32px；触屏有效命中区不小于 44×44px |
| 控件间距 | 8px；紧凑标签间距 6px |
| 列表行高 | 桌面 44px；移动端 64–72px |

颜色规则：

- 普通文字、次要文字、边框和背景全部复用全局语义令牌。
- 紫色/品牌强调色只用于现有的选中、焦点或激活语义，不用作装饰性分隔线。
- 做多、做空继续使用统一的成功/风险语义色；来源不拥有独立高饱和颜色。
- 禁用状态同时降低文字与控件对比，并保留可识别轮廓；不可只改变透明度到难以阅读。
- 文本与背景对比度满足 WCAG AA：正文至少 4.5:1，较大文字和非文本操作边界至少 3:1。

## 7. 响应式设计

### 7.1 桌面（≥ 1024px）

- 顶栏、工具栏和列表与交易日志共享相同内容宽度。
- 工具栏保持单行；结果与激活筛选在左，范围与筛选在右。
- 列表保持六个信息区域，摘要获得剩余弹性宽度。

### 7.2 平板（768–1023px）

- 工具栏仍保持单行；优先缩短激活筛选的可见文字，保留其可访问名称。
- 列表可隐藏低价值的独立来源列，将来源并入品种的辅助信息，但来源文字必须常驻可见。
- 日期使用短格式，行尾菜单命中区至少 44×44px。

### 7.3 手机（< 768px）

- 顶栏沿用移动工作台结构，不额外增加第二行说明。
- 工具栏保持一行：左侧显示 `全部机会 28`，右侧显示图标加短标签的“范围”“筛选”；有效命中区至少 44×44px。
- 记录行高 64–72px，左右内边距 12px。
- 第一行显示品种、方向和日期；第二行显示来源与摘要。摘要单行省略，不能挤占更多菜单。
- 行尾更多菜单使用 44×44px 命中区，并为读屏提供“更多操作：BTCUSDT”等上下文化名称。
- 最后一行可以完整滚动到移动底部导航和安全区之上。

## 8. 核心操作心流

### 8.1 浏览并回源

1. 用户从侧栏进入“错过的机会”。
2. 顶栏确认所在模块，工具栏直接说明当前结果数和范围状态。
3. 用户从品种和摘要快速扫描机会，不需要先理解配置区。
4. 点击普通行直接进入对应来源详情；合并行通过更多菜单选择原始记录或案例。
5. 返回后恢复原筛选、滚动位置与焦点，用户从中断处继续浏览。

### 8.2 调整包含范围

1. 用户点击工具栏 `范围 · 3`。
2. 浮层同时显示三个工作区的选中状态和原始数量。
3. 用户勾选或取消勾选，结果立即更新并收到简短状态反馈。
4. 关闭浮层后仍停留在同一浏览位置；若当前焦点记录因范围变化消失，焦点移动到列表标题并播报结果变化。

### 8.3 临时筛选

1. 用户点击标准“筛选”按钮。
2. 使用现有筛选界面选择日期、品种、方向或错过原因。
3. 工具栏显示紧凑激活标签和结果数。
4. 无结果时用户可一键清除筛选，不需要进入范围设置排查。

## 9. 状态与反馈

### 9.1 初始加载

- 工具栏和列表使用现有加载骨架或加载状态，不显示伪造的 `0`。
- 加载期间范围与筛选按钮保持稳定位置；如果操作不可用，应使用标准禁用态。

### 9.2 所选来源无数据

- 使用现有工作台的居中空状态版式，不保留一块空白列表上方的大型范围配置区。
- 标题：`所选工作区暂无错过记录`。
- 说明：`可以前往已包含的工作区查看或补充原始记录。`
- 只展示与已包含来源对应的标准次级入口，例如“前往交易日志”“前往模拟盘”。入口不使用大号营销按钮。

### 9.3 临时筛选无结果

- 标题：`没有符合当前筛选的机会`。
- 提供唯一主动作 `清除筛选`。
- 范围入口仍保留在工具栏，避免把“无数据”和“筛选无结果”混为一谈。

### 9.4 错误状态

- 派生或读取失败时使用现有内联错误状态，说明失败内容并提供“重试”。
- 不用空状态掩盖错误，也不把技术错误文本直接暴露给用户。

### 9.5 交互反馈完整性

范围按钮、筛选按钮、行、更多菜单和清除筛选动作必须具备默认、Hover、Focus-visible、Pressed、Disabled 和加载中的适用状态。范围变化、筛选变化和返回定位通过 `aria-live="polite"` 报告，不抢夺当前焦点。

## 10. 可访问性

- 工具栏使用明确的区域名称；范围按钮通过 `aria-expanded` 和 `aria-controls` 表达浮层状态。
- 复选框有可见文字标签，数量不进入标签名称造成重复朗读。
- 列表行具备可读名称，例如“BTCUSDT，做空，交易日志，7月28日”。
- 来源、方向和状态不能只依赖颜色。
- 所有交互元素均可通过键盘到达；Tab 顺序与视觉顺序一致。
- 浮层打开后焦点进入首个选项，关闭后返回触发器；`Escape` 可关闭。
- 触屏操作目标至少 44×44px，焦点指示与背景对比度至少 3:1。
- 尊重 `prefers-reduced-motion`，结果更新不使用位移动画。

## 11. 数据与行为保持不变

本次实现必须沿用现有：

- 三类来源数据的命中条件。
- 明确关系合并与稳定排序规则。
- 来源数量、聚合总数和侧栏计数口径。
- 至少保留一个来源的约束及长期记忆。
- 临时筛选、URL 状态、详情回源、滚动位置和焦点恢复。
- 删除、恢复以及来源失效后的展示逻辑。

视觉改造不得新增数据迁移，不得改变记录状态，也不得让未包含来源被后台自动纳入。

## 12. 验收标准

1. 首屏不再出现常驻“管理包含范围”大区块；记录列表在顶栏和单行工具栏之后立即开始。
2. 页面顶栏的高度、标题样式、分隔符、内边距与交易日志或模拟盘工作台一致。
3. 桌面工具栏保持单行，包含 `全部机会 N`、激活筛选、`范围 · N` 和 `筛选`，控件高度为现有紧凑规格。
4. 范围浮层显示三类来源、选中状态和数量，选择即时生效，且无法关闭最后一个来源。
5. 桌面列表行高为 44px，移动端为 64–72px；品种是每行第一视觉焦点，来源和日期保持次要层级。
6. 页面不再出现整行紫色焦点分隔线、自定义大号描边来源按钮或独立巨型总数。
7. 普通行可直接回源；合并行通过标准更多菜单提供明确的原始记录与案例入口。
8. 加载、无来源数据、筛选无结果、错误、Hover、Focus、Pressed 和 Disabled 状态均有明确且一致的表达。
9. 375px、768px、1280px 和 1920px 宽度下无水平溢出、重叠、不可达操作或工具栏换行。
10. 纯键盘可完成调整范围、筛选、打开记录、打开合并记录菜单及返回；状态变化可被读屏感知。
11. 原有聚合、计数、筛选 URL、侧栏、详情跳转与返回现场相关自动化测试继续通过。

| 视口 | 数据状态 | 必查内容 |

| 1920×1080 | 多来源、多条记录 | 与工作台顶栏/工具栏一致、列节奏、列表密度、首屏焦点 |
| 1280×800 | 长摘要、三位数结果 | 单行工具栏、文本省略、日期和菜单稳定 |
| 768×1024 | 多个激活筛选 | 平板信息折叠、触控命中区、无横向滚动 |
| 375×812 | 多来源、多条记录 | 两行记录、工具栏单行、安全区、44px 操作区 |
| 1280×800 | 所选来源无数据 | 标准居中空状态与来源入口 |
| 1280×800 | 临时筛选无结果 | 明确零结果文案与单一“清除筛选”动作 |

## 14. 测试范围

- 单元/组件测试：范围触发器计数、复选框即时更新、最后来源约束、结果数、激活筛选标签、普通行与合并行行为。
- 路由测试：普通回源、合并项两个入口、详情返回后的 URL、滚动与焦点恢复。
- 可访问性测试：工具栏名称、浮层焦点管理、键盘操作、`aria-live` 状态反馈、对比度和 44px 命中区。
- 响应式测试：375px、768px、1280px、1920px，无横向溢出和操作遮挡。
- 回归测试：侧栏计数、来源数量、去重数量、排序、删除/恢复和现有三类来源本地视图不变。
- 真实浏览器视觉测试：按视觉复核矩阵留存改造前后截图，并检查控制台错误。

## 15. 风险与控制

- **共享样式回归**：优先复用现有组件；如需补充共享令牌，先验证交易日志、模拟盘和移动端未被意外改变。
- **工具栏空间不足**：激活筛选必须使用已有的收纳规则，不允许通过减小字号或压缩命中区解决。
- **即时范围更新导致焦点丢失**：记录消失时使用安全焦点回退与状态播报，并保留当前滚动上下文。
- **空状态误导**：严格区分“所选来源无数据”“临时筛选无结果”和“读取错误”。
- **视觉修复影响业务行为**：实现中不改动聚合派生和数据写入函数，并用既有回归测试验证边界。

## 16. 推荐实施顺序

1. 建立现有工作台样式映射，确认可复用的顶栏、工具栏、按钮、菜单、列表行和空状态。
2. 移除常驻范围配置区，将范围能力迁入工具栏浮层。
3. 重构列表视觉层级、列宽、行高和交互反馈，不改变数据派生与导航行为。
4. 补齐加载、无数据、零结果、错误和范围约束反馈。
5. 完成平板、手机和键盘操作适配。
6. 执行自动化回归和真实浏览器截图复核，再进入发布流程。
