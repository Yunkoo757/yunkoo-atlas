# Trader Atlas 历史实盘模块设计

> **2026-08-16 统一工作台修订：** 历史实盘不再维护独立页壳、摘要栏、筛选器或分组逻辑。它直接复用交易日志的 `TradesPage`、`ListView`、`BoardView`、`TradeFilters`、`QuickViewBar` 与月份分组；与交易日志的唯一业务差异是数据范围为 `all-archives`。关联案例同样复用案例工作台语义，仅增加“来源属于历史实盘”的范围约束。下文凡涉及独立摘要、独立筛选器和 `.la-*` 页面样式的旧描述均由本修订取代。

## 目标

将现有“历史记录”重新定义为独立的“历史实盘”模块，集中展示每次重置实盘统计起点之前的实盘交易，以及由这些交易衍生出的案例记录。用户可以在同一模块中切换“实盘记录”和“关联案例”，并像交易日志、案例记录等工作区一样筛选不同类型的数据。

本功能仅适配 Windows 和 macOS 桌面客户端，覆盖 960–1920px 桌面窗口，不考虑手机、iPad、浏览器或其他平台。

## 产品结论

采用扩展现有实盘归档投影的方案，不创建新的持久化集合，也不复制交易或案例数据。

- 现有“历史记录”侧栏入口更名为“历史实盘”。
- 新的规范路由为 `/live-history`；旧 `/live-archive` 及其历史子路径继续兼容并跳转到新入口。
- 页面提供“实盘记录”和“关联案例”两个视图，默认进入“实盘记录”。
- “实盘记录”由现有 `all-archives` 边界规则决定。
- “关联案例”只包含 `sourceTradeId` 指向历史实盘成员的、未删除的案例记录。
- 无来源案例、来源为当前实盘的案例、模拟盘案例和已删除案例不进入历史实盘。
- 案例始终不参与历史实盘的交易数量、胜率、净盈亏和平均 R 计算。

## 数据边界

### 历史实盘交易

继续由 `resolveLiveArchiveScope(cycles, 'all-archives')` 与 `filterLiveLogRecords` 生成。归档依据保持不变：

- 已结束交易和错过机会使用可靠平仓业务日归属。
- 计划中与持仓记录使用开仓业务日归属。
- 日期缺失或无效、无法安全判断归属的记录进入“待整理”，不强行并入当前或历史。
- 软删除记录和非实盘记录排除。

### 关联案例

新增纯函数投影：先生成历史实盘成员 ID 集合，再从全部记录中筛选：

```ts
trade.tradeKind === 'case'
&& trade.deletedAt === undefined
&& Boolean(trade.sourceTradeId)
&& archivedSourceIds.has(trade.sourceTradeId)
```

案例归档是动态关系，不写入新的“是否历史”字段。当重置边界、来源关系、删除状态或案例分类变化时，页面自动反映最新结果，不做迁移和双写。

## 页面结构

### 顶部区域

- 标题：`历史实盘`
- 副标题：`重置起点前的实盘与关联案例会保留在这里`
- 继续保留“待整理”和“导入日期核对”入口。
- 摘要保留历史实盘的交易数量、胜率、净盈亏、平均 R；切换到关联案例时摘要数值不变，避免把知识条目误解为交易绩效。

### 视图切换

使用与其他工作区一致的紧凑快捷视图条：

- `实盘记录`
- `关联案例`

视图通过查询参数 `view=cases` 表达；缺省或未知值规范化为实盘记录。这样详情页返回、深链接和刷新都能恢复当前视图。

### 实盘记录筛选

保留搜索和日期范围，扩展为以下维度：

- 编号或品种搜索
- 日期起止
- 品种
- 策略
- 方向
- 交易状态/结果
- 标签

筛选只作用于列表，不改变摘要 KPI 的归档总体范围。激活条件继续由标准 `FilterBar` 显示和逐项移除。

### 关联案例筛选

顶部提供案例快捷分类：

- 全部
- 重点
- 错题
- 错过机会
- 待复看
- 已掌握

分类成员规则复用现有案例域语义：重点与错题调用 `matchesReviewCaseScope`；错过机会使用 `caseType === 'missed'`；待复看和已掌握分别使用既有掌握状态/复盘状态规则。高级筛选提供搜索、日期、品种、策略、案例类型、掌握状态和标签。

“重点”允许星标案例、重点分类或重点复盘状态命中；“错题”继续排除错过机会，避免同一案例同时落入互斥快捷分类。

## 列表与详情交互

- 两个视图都复用 `TradeList` 和 `TradeRow`，保持行密度、键盘焦点、图标和详情入口一致。
- 实盘记录分组标题为“重置前实盘”。
- 关联案例分组标题为“关联案例”，行语义使用“案例记录”。
- 点击实盘或案例都进入现有交易详情路由。
- 详情页通过 `from.pathname = '/live-history'` 和当前查询参数返回原视图与筛选状态。
- 案例详情中的来源交易仍由既有来源关系打开；历史来源返回时应允许 `/live-history` 作为合法来源。

## 路由与兼容

- 新增 `/live-history` 作为规范入口。
- `/live-archive` 跳转到 `/live-history`，保留原查询参数。
- `/live-archive/:archiveId` 跳转到 `/live-history`，并保留原请求键用于一次性兼容提示。
- 侧栏、仪表盘、导入日期核对、详情返回文案和所有面向用户的“历史记录”统一改为“历史实盘”。
- 不删除旧路由，避免旧收藏、历史返回栈和已保存导航失效。

## 空态与可访问性

- 没有历史交易：`还没有历史实盘`。
- 有历史交易但没有关联案例：`历史实盘还没有关联案例`，提示可从交易详情创建案例记录。
- 当前筛选无结果：继续提供“清除筛选”动作。
- 视图切换、案例分类和筛选入口具有明确 `aria-label`、选中态与键盘焦点。
- 结果数量通过 `aria-live="polite"` 发布，不能只依赖颜色表达状态。

## 非目标

- 不创建独立数据库表、store slice 或归档副本。
- 不改变重置实盘统计起点的写入与恢复逻辑。
- 不改变当前“案例记录”工作区的成员范围；关联案例仍可在案例记录工作区出现。
- 不提供批量移动、恢复到当前周期或删除归档的操作。
- 不重新引入按单个历史周期浏览的旧页面结构。

## 验证方案

### 纯函数契约

- 历史实盘来源 ID 能正确投影关联案例。
- 当前实盘来源、无来源、已删除、来源不存在和非案例记录被排除。
- 分类规则与现有案例工作区保持一致。
- 案例不会进入实盘绩效统计。

### 浏览器交互

- 侧栏进入“历史实盘”，默认显示实盘记录。
- 切换到关联案例后只显示历史来源案例。
- 六个案例快捷分类、搜索与高级筛选可组合、移除和清空。
- 刷新或详情返回能恢复 `view=cases` 及筛选查询。
- 旧 `/live-archive` 路由能无损跳转。
- 960px 和 1440px 桌面窗口无横向溢出，筛选面板可完整操作。

## 完成标准

- 用户界面不再出现作为模块名称的“历史记录”，统一显示“历史实盘”。
- 重置起点前的全部实盘记录都可在“实盘记录”视图查看和筛选。
- 所有以历史实盘为来源的案例都可在“关联案例”视图查看，并支持六类快捷筛选。
- 当前实盘、无来源案例和其他工作区数据不会误入历史实盘。
- 历史实盘 KPI 只统计符合现有绩效真值规则的实盘交易。
- 旧入口和详情返回路径保持兼容。
- Windows/macOS 桌面窗口下自动测试、构建和视觉检查全部通过。
