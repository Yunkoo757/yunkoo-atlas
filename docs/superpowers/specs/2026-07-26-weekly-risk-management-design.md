# Trader Atlas 周度风控准备与风险预算设计

> 日期：2026-07-26
> 状态：已批准，待实施计划
> 基线：`main@bbe471d`
> 范围：周度风控计划、已实现净 R 进度、触线确认、周复盘证据
> 数据版本：`PersistedSnapshot` Schema v9

## 1. 设计结论

本功能采用“提醒为主、触线后软确认”的风控闭环：

1. 每周生成一份可确认的风控计划，锁定当周资金基准与 1R 金额。
2. 今日工作台常驻显示日、周、月三个周期的已实现净 R 风险预算。
3. 未确认本周计划只产生持续但低干扰的提醒，不阻止交易或其他操作。
4. 当任一周期的当前净 R 达到止损线后，每一笔新的实盘交易都必须单独确认继续交易原因。
5. 继续交易原因与最终创建的交易关联，并进入当周复盘证据。
6. 第一版只统计已平仓实盘交易，不计算持仓风险，不做自动仓位合规判定。

功能不新增独立“风控中心”导航。主要入口位于现有今日工作台，复盘出口位于现有周复盘。

## 2. 目标与非目标

### 2.1 目标

- 在每周开始时提醒用户确认资金基准、R 值和周期止损规则。
- 让用户在日常工作台中自然看到距离日、周、月止损线的剩余空间。
- 使用当前周期净结果衡量亏损，盈利必须返还风险额度。
- 对触线后继续交易增加一次有意识的停顿，并留下可复盘证据。
- 复用现有交易数据、交易日锚点、Zustand 快照、双端持久化和周复盘流程。
- 对历史与不完整数据明确显示统计覆盖情况，不静默猜测。

### 2.2 非目标

- 不推算持仓中或挂单中的潜在风险。
- 不统计同时持仓风险、保证金占用或账户高点回撤。
- 不根据入场价、止损价和仓位自动阻止下单。
- 不连接券商、交易所或外部账户净值。
- 不建设多账户、多币种或组合级风险系统。
- 不实现通用规则引擎。
- 不把模拟交易、案例记录、错过机会或未平仓交易计入风控进度。
- 不把周度准备变成进入应用或打开交易编辑器的强制流程。

## 3. 已锁定的产品决策

| 主题 | 决策 |
|---|---|
| 风控强度 | 平时仅提醒；触线后新建实盘交易采用软确认 |
| 统计对象 | 未删除且已平仓的实盘交易 |
| 进度口径 | 当前周期净 R；盈利抵消亏损并返还额度 |
| 回撤口径 | 不统计周期内高点回撤 |
| 持仓风险 | 第一版不计算，只允许以本周纪律文本提醒 |
| R 基准 | 每周锁定一次资金基准、R 百分比和 R 金额 |
| 默认值 | 1R = 资金的 1%；日/周/月止损线为 2R/5R/10R |
| 周准备提醒 | 未确认时一直保留在今日工作台，但不弹窗、不阻断 |
| 触线确认频率 | 触线状态持续期间，每笔新的实盘交易都确认一次 |
| 主界面 | 今日工作台主卡片，不新增独立导航 |
| 复盘耦合 | 继续交易原因与对应交易进入周复盘，并在完成时冻结摘要 |

## 4. 用户流程

### 4.1 首次使用

系统为当前交易周创建一份草稿计划，预填：

- R 百分比：1%；
- 日止损：2R；
- 周止损：5R；
- 月止损：10R；
- 资金基准：空；
- 本周纪律：空。

用户可继续使用全部功能。没有资金基准时，已有 `rMultiple` 的交易仍可统计；只有盈亏金额的交易暂时无法换算并显示缺失提示。

### 4.2 新交易周

系统根据当前 `BusinessDateAnchor` 得到周一日期，并确保当前周存在唯一计划：

- 若存在上一份已确认计划，复制其资金基准、R 百分比、三档止损线与纪律文本形成新草稿；
- 若不存在，使用首次使用默认值；
- 新草稿不会自动标记为已确认。

“自动沿用”提供连续性，但不代表用户已完成本周确认。

### 4.3 确认本周计划

用户在今日工作台点击准备卡后打开轻量弹窗，可编辑：

- 本周资金基准；
- R 百分比；
- 计算后的 R 金额；
- 日、周、月止损线；
- 本周仓位与风控纪律文本。

资金基准、R 百分比和 R 金额保持一致：编辑资金或百分比时自动重算金额；直接修正金额时反算百分比。确认时保存三者的固定快照，周内账户盈亏不会自动改变 1R。

确认后准备卡折叠为一行摘要。已确认计划仍可修改，但必须二次确认；修改作用于整个交易周，并更新 `updatedAt`。由于这会影响该周“只有金额、没有 R”的交易换算，确认文案必须明确说明统计可能变化。

### 4.4 日常风险查看

今日工作台在现有“行动队列”下方、“今日战绩”上方展示：

1. 未确认时的本周准备卡，或确认后的折叠摘要；
2. 常驻风险预算卡。

风险预算卡展示今日、本周、本月：

- 当前净 R；
- 止损线；
- 已使用比例；
- 距离止损线的剩余 R；
- 无法计入的平仓交易数量与原因；
- 本周纪律文本。

正收益时显示“未使用止损额度”，进度为 0。隐私模式隐藏资金基准、R 金额和金额换算，只保留 R 倍数与比例。

### 4.5 触线后继续交易

打开交易编辑器不受限制。用户提交一笔新的实盘交易时，系统使用提交瞬间的最新状态重新计算风控：

- 若所有周期均未触线，按现有流程提交；
- 若任一周期触线，交易编辑器进入确认步骤；
- 确认步骤展示触发周期、当前净 R、止损线和本周纪律；
- 用户必须填写非空的继续交易原因，再次提交；
- 交易创建成功时，交易与确认事件在同一次 Zustand 状态更新中写入；
- 用户取消或最终提交失败时，不写确认事件。

触线状态持续期间，每一笔新实盘交易都重复以上确认。编辑已有交易、模拟交易和案例记录永不触发。

如果盈利使当前净 R 回到止损线以内，系统立即解除触线状态；此前曾触线不构成永久锁定。

### 4.6 周复盘

周复盘在“本周事实”之后增加“风控执行”区块，展示：

- 当周确认的风控计划；
- 当周最终净 R 与周止损线；
- 各交易日的最终净 R，以及完成复盘时的周/月净 R 是否位于止损线外；
- 触线后继续创建实盘交易的次数；
- 每次确认的时间、原因和关联交易。

周复盘完成时，将该区块的事实摘要写入复盘快照。之后修改历史交易或周计划不会静默改写已完成复盘；如需更新，沿用现有“重新打开复盘”流程重新冻结。

这里不声称还原周期内最高点或每一次短暂触线。某日最终结果后来恢复到止损线以内时，该日显示恢复后的净 R；如果恢复前曾继续创建交易，则对应 `RiskOverrideEvent` 仍作为当时确实处于触线状态的证据保留。

## 5. 数据模型

### 5.1 WeeklyRiskPlan

```ts
interface WeeklyRiskPlan {
  id: string
  weekStart: string
  status: 'draft' | 'confirmed'
  capitalBase: number | null
  riskPercent: number
  riskAmount: number | null
  dailyLossLimitR: number
  weeklyLossLimitR: number
  monthlyLossLimitR: number
  disciplineText: string
  createdAt: string
  updatedAt: string
  confirmedAt: string | null
}
```

不变量：

- `id` 使用稳定格式 `weekly-risk-plan:<weekStart>`；
- 每个 `weekStart` 最多一份计划；
- `weekStart` 必须是本地周一的 `YYYY-MM-DD`；
- 三个止损线必须是有限正数；
- `riskPercent` 必须是有限正数；
- 草稿允许 `capitalBase` 与 `riskAmount` 为 `null`；
- 已确认计划要求 `capitalBase > 0`、`riskAmount > 0`；
- 已确认时 `riskAmount` 等于 `capitalBase * riskPercent / 100`，按显示精度规范化后锁定。

### 5.2 RiskOverrideEvent

```ts
type RiskPeriodScope = 'day' | 'week' | 'month'

interface RiskOverrideEvent {
  id: string
  tradeId: string
  weekStart: string
  createdAt: string
  reason: string
  triggeredScopes: RiskPeriodScope[]
  netRAtDecision: Record<RiskPeriodScope, number>
  limitsRAtDecision: Record<RiskPeriodScope, number>
  missingTradeCountAtDecision: Record<RiskPeriodScope, number>
}
```

`triggeredScopes` 必须非空。确认事件是审计证据，不因关联交易后续被删除而删除。交易不可用时，周复盘显示“关联交易已删除”，仍保留当时原因和数值快照。

### 5.3 WeeklyRiskReviewSnapshot

`WeeklyReview` 增加可选字段：

```ts
interface RiskPeriodOutcomeSnapshot {
  netR: number
  limitR: number
  missingTradeCount: number
  triggered: boolean
}

interface WeeklyRiskReviewSnapshot {
  plan: WeeklyRiskPlan | null
  dailyOutcomes: Array<RiskPeriodOutcomeSnapshot & { date: string }>
  weeklyOutcome: RiskPeriodOutcomeSnapshot
  monthlyOutcomeAtCompletion: RiskPeriodOutcomeSnapshot
  overrideEvents: RiskOverrideEvent[]
}
```

该字段只在完成周复盘时写入；草稿复盘实时派生，不提前复制数据。`dailyOutcomes` 表示各交易日的最终结果，`monthlyOutcomeAtCompletion` 表示点击“完成本周复盘”时的当月累计结果。历史短暂触线只由实际发生的确认事件证明，不从日内高点回撤反推。

### 5.4 PersistedSnapshot

Schema v9 增加：

```ts
weeklyRiskPlans?: WeeklyRiskPlan[]
riskOverrideEvents?: RiskOverrideEvent[]
```

旧 v8 快照缺省时规范化为空数组。现有导出载荷版本不因新增可选快照字段自动升级；实现阶段必须按仓库当前归档合同逐路径验证字段保真。

## 6. 计算合同

### 6.1 合格交易

交易必须同时满足：

- `tradeKind === 'live'`；
- 没有 `deletedAt`；
- 状态为 `win`、`loss` 或 `breakeven`；
- 存在有效 `closedAt`。

`paper`、`case`、`planned`、`open`、`missed` 和回收站交易全部排除。

### 6.2 单笔交易换算

按以下唯一优先级得到统计 R：

1. `rMultiple` 是有限数时直接使用，包括 0；
2. 否则，当 `pnl` 是有限数且交易所在周存在正数 `riskAmount` 时，使用 `pnl / riskAmount`；
3. 否则标记为缺少可统计结果，不计入净 R。

若 R 与金额同时存在，R 是风控统计权威值；不得再次用金额覆盖。金额换算必须使用交易所属周的 R 金额，而不是当前周金额，因此月度统计可以正确跨越不同的周度资金基准。

### 6.3 周期归属

- 日：当前 `BusinessDateAnchor.currentTradingDayKey`；
- 周：包含当前交易日的周一至周日；
- 月：包含当前交易日的自然月。

`closedAt` 含时间时使用现有 `tradingDayStartHour` 转换为交易日；日期字符串已视为业务日期，不再次偏移。周与月边界均以转换后的业务日期为准。

当前卡片的日、周、月止损线均取当前周计划。月度止损线允许用户在新一周确认时调整；调整后新上限立即适用于当月累计净 R。历史交易的金额换算仍使用各自所属周的 R 金额。

### 6.4 聚合与进度

对周期内所有可统计交易求和：

```text
netR = Σ resolvedTradeR
consumedR = max(0, -netR)
remainingR = max(0, limitR - consumedR)
progress = clamp(consumedR / limitR, 0, 1)
triggered = netR <= -limitR
```

示例：

| 交易序列 | 净 R | 日限额 2R 的已用额度 | 是否触线 |
|---|---:|---:|---|
| `-1R, +2R` | `+1R` | `0R` | 否 |
| `+1R, -2R` | `-1R` | `1R` | 否 |
| `+3R, -4R` | `-1R` | `1R` | 否 |
| `-1R, -1R` | `-2R` | `2R` | 是 |

系统不记录或展示周期内最高点回撤。

### 6.5 视觉状态

- 进度低于 60%：中性/正常色；
- 60% 至低于 90%：橙色预警；
- 90% 至低于 100%：强化橙色；
- 达到或超过 100%：红色触线状态；
- 正收益：进度为 0，并显示当前正 R。

颜色必须辅以文字和数值，不得成为唯一状态表达。

## 7. 架构与组件边界

### 7.1 风控领域

新增 `src/risk/`，保持计算与 React、Store、IndexedDB、Electron 解耦：

- `riskPlan.ts`：默认计划、跨周沿用、确认和校验；
- `riskMetrics.ts`：交易筛选、R 解析、周期边界、聚合与覆盖率；
- `riskGate.ts`：根据最新指标生成触线确认上下文；
- `types.ts`：风控领域类型。

这些模块以纯函数为主，可由今日工作台、交易编辑器和周复盘共同调用。

### 7.2 Store

风控状态作为独立 slice 组合进现有 `useStore`，slice 实现放在独立文件，避免继续扩大 `useStore.ts` 的内联职责：

- `weeklyRiskPlans`；
- `riskOverrideEvents`；
- 创建/更新/确认周计划动作；
- 带可选风控确认的实盘交易创建动作。

“创建交易 + 创建 RiskOverrideEvent”必须使用单次 `set`。不得由组件先写交易、再异步补写确认事件。

### 7.3 UI 组件

建议组件边界：

- `WeeklyRiskPreparationCard`：本周确认状态与摘要；
- `WeeklyRiskPlanDialog`：计划编辑与确认；
- `RiskBudgetCard`：三个周期进度与数据覆盖提示；
- `RiskOverrideStep`：交易提交时的触线确认；
- `WeeklyRiskEvidence`：周复盘中的风控执行证据。

`TodayWorkspace` 只负责排列组件，不内联计算公式。`TradeComposer` 只在最终提交处调用 gate 并管理确认步骤，不复制指标逻辑。

### 7.4 数据流

```text
WeeklyRiskPlan + Trades
        ↓
   riskMetrics（纯计算）
     ↙             ↘
今日工作台       riskGate
                    ↓
              新实盘交易提交
                    ↓
      Trade + RiskOverrideEvent（原子 Store 更新）
                    ↓
               周复盘证据
```

## 8. 持久化、迁移与兼容

### 8.1 快照升级

- `SCHEMA_VERSION` 从 8 升至 9；
- v8 读取时为两个新数组补空默认；
- v9 writer 显式写出两个字段；
- snapshot validation、canonical codec、持久化字段注册表和完整哨兵 fixture 同步扩展；
- 浏览器 IndexedDB 和 Electron SQLite 都继续保存完整快照，不新增平台专属风险表。

### 8.2 导入、导出和切库

所有支持的完整归档路径必须逐字段保留风控计划、确认事件和周复盘风险快照。合并导入时采用以下策略：

- 周计划按稳定 `id` 合并，`updatedAt` 较新者胜出；
- 确认事件按 `id` 去重，不因关联交易缺失而丢弃；
- 周复盘仍按现有周标识与更新时间策略处理，其冻结风险快照随复盘一起保留。

切换资料库、恢复备份和整库替换时，风控数据必须与交易一起切换，不能跨资料库残留。

### 8.3 回滚边界

新字段是快照附加数据。旧版本可能忽略它们，但用旧版本保存完整快照可能造成字段丢失，因此发布说明必须提示：创建 v9 风控数据后，不保证降级到 v8 再编辑的保真性。代码回滚前必须保留用户最新归档。

## 9. 错误与边界处理

- 无效资金、百分比、R 金额或止损线阻止“确认计划”，但不阻止关闭弹窗或使用其他功能。
- 无计划或计划没有 R 金额时，不妨碍直接 R 统计；金额交易进入缺失计数。
- 某周期没有可统计交易时，显示 0R 和空进度，不显示错误。
- 非有限 R、非有限金额、非法日期或缺失周计划不得进入数值计算。
- 触线检查在最终提交时重新执行；确认界面打开后的旧结果不得直接提交。
- 若重新计算后已解除触线，直接恢复普通提交，不保存原因。
- 若触发周期发生变化，更新确认界面并要求用户基于最新状态再次确认。
- 交易创建失败时不写确认事件；持久化失败沿用现有保存状态、重试和退出保护。
- 关联交易被删除后保留确认事件，周复盘不得崩溃或静默隐藏该决策。

## 10. 测试设计

### 10.1 纯逻辑测试

- 默认计划、跨周复制、唯一周计划和确认校验；
- R 优先于金额；金额按所属周 R 金额换算；
- `-1R + 2R = +1R` 且进度归零；
- `+3R - 4R = -1R`，不计算 4R 高点回撤；
- 恰好达到止损线即触线；
- 盈利恢复后解除触线；
- 日、周、月以及交易日起始时间的边界矩阵；
- 跨月多周、不同 R 金额的换算；
- 模拟、案例、错过、未平仓、已删除与非法结果排除；
- 数据覆盖率与缺失原因稳定。

### 10.2 Store 测试

- 周计划创建、沿用、确认和已确认计划修改；
- 创建交易和确认事件是单次原子状态变化；
- 每一笔触线后的新实盘交易都产生独立事件；
- 取消、提交失败、编辑旧交易和非实盘交易不产生事件；
- 删除交易不级联删除确认事件。

### 10.3 浏览器组件测试

## 11. 成功标准

功能完成必须同时满足：

1. 新周准备提醒在未确认时持续存在，但任何正常浏览和编辑不受阻。
2. 用户可锁定当周资金基准与 1R，默认百分比为 1%。
3. 日、周、月风险卡只使用已平仓实盘净 R，盈利正确返还额度。
4. R 缺失时能按交易所属周金额换算；不能换算时明确提示覆盖缺口。
5. 任一周期当前触线时，每笔新实盘交易均要求填写继续交易原因。
6. 交易与确认事件原子创建，取消或失败不留孤立记录。
7. 周复盘能审阅触线后继续交易的理由和结果，并冻结完成时摘要。
8. v9 数据在 Web 与 Electron 的受支持保存、导入、导出、备份和恢复路径中保真。
9. 第一版没有持仓风险推算、规则引擎或独立风控中心等范围膨胀。

## 12. 实施约束

- 先为纯计算和 Store 原子性编写失败测试，再修改实现。
- 复用现有 `BusinessDateAnchor`、交易分类 helper、快照 codec 和错误展示，不建立平行体系。
- 每条修改必须能追溯到本设计；不顺带重构今日工作台、周复盘或整个 Store。
- 所有新增与修改文件保持 UTF-8 无 BOM，保留中文字符。
- 实施计划必须把数据合同、纯逻辑、Store、今日工作台、交易 gate、周复盘和双端持久化拆成可独立验证的步骤。
