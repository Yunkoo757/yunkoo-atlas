# Trader Atlas 桌面视觉系统双层收敛设计

日期：2026-08-12

状态：推荐方案与书面规格已批准，可进入实施

产品范围：仅 Windows 客户端与 macOS 客户端

目标用户：每天记录交易、处理待复盘队列并持续进行周复盘的独立交易员

## 1. 结论

Trader Atlas 已经具备成熟桌面工作台的基础：深色中性表面、清晰业务语义色、稳定数据栅格、本地字体、设计令牌、键盘入口和 Electron 桌面外壳。当前问题不是缺少样式，而是视觉语言在长期迭代中逐渐分裂：同一视觉概念同时由设计令牌、局部硬编码和页面自定义实现；不同页面又分别采用线性列表、数据平铺、等权卡片长表单和超大留白四种节奏。

本设计采用已批准的“双层收敛”方案：

1. 系统层收敛：统一颜色、字体、间距、圆角、阴影、图标、动效、控件和状态反馈契约。
2. 页面层重排：按工作台、分析、叙事复盘、详情、专注复盘和设置六种页面原型重建信息优先级。

不迁移 React、CSS、路由或 Electron 技术栈，不进行装饰性重写。所有改动围绕三个结果：

- 核心交易事实首先进入视线；
- 高频操作在稳定位置、以稳定形态出现；
- 页面切换时保持同一种密度、表面和反馈语言。

最终观感应是极简、克制、专业、高密度但不拥挤的桌面交易工作台，而不是网页后台、卡片模板或 Notion/Linear 的表面仿制。

## 2. 范围与证据

设计依据包括：

- 当前 `src/styles/tokens.css`、`src/styles/global.css` 和 80 个 CSS 文件；
- `Button`、`Select`、`DatePicker`、`ModalShell`、`Toolbar`、`FilterBar`、`Sidebar`、`AppFrame` 等基础组件；
- 今日工作台、交易日志、交易详情、仪表盘、周复盘、随机复盘和设置页实现；
- `ux-audit/screenshots`、`qa-screenshots` 和 `.gstack/qa-reports/screenshots` 中的 1440×900 与 1920×1080 页面证据；
- Windows Electron 黑盒 QA、桌面生命周期报告和现有视觉契约测试；
- 960×640 最小窗口、1280×860 默认窗口及 Windows/macOS 平台约束。

浏览器渲染和 Playwright 只作为 Electron 渲染层的内部回归工具，不构成浏览器产品支持。设计不再考虑手机、iPad、触摸浏览器或底部移动导航。

## 3. 当前基线判断

### 3.1 应保留的基础

- 中性微靛暗色轴及语义文字层级；
- 交易盈亏、风险、警告和待处理的业务语义色；
- JetBrains Mono、表格数字和右对齐的金融数据表达；
- 4px 基准间距、小圆角、薄边框和克制阴影方向；
- 已命名的 z-index 梯级和 `prefers-reduced-motion`；
- AppFrame 的桌面侧栏与内嵌主工作区结构；
- `ModalShell` 的焦点圈、焦点恢复、滚动锁和 busy 状态；
- Select 的键盘、类型选择、上下翻转与视口收边能力；
- 保存状态的 dirty、saving、saved、error 和重试链路。

### 3.2 需要收敛的问题

1. 字体角色、行高、图标尺寸、动效时长和浮层表面存在多套局部值。
2. 侧栏、详情和标签编辑器绕过语义令牌直接绑定 LCH 值。
3. `Button` 仍通过大量旧类名兼容，页面持续绕过组件 API。
4. 侧栏导航清除了全局键盘焦点，没有替代指示。
5. `ReviewSessionView.css` 使用未定义的 `--bg-active`。
6. 当前代码仍保留手机底部导航、44px 粗指针补偿和大量手机断点。
7. 仪表盘的固定本周摘要抢占当前筛选范围结论的注意力。
8. 周复盘由七张近似等权卡片组成，主动作远离缺失字段。
9. 交易详情和随机复盘对短内容施加过大的最小高度。
10. 工作台与日志的高密度数据缺少稳定列标题。
11. 成功、警告和错误大量共用单一 Toast，阻塞错误缺少持久定位。
12. 960×640 与 1920×1080 分别存在操作拥挤和内容过度拉伸风险。

## 4. 目标与非目标

### 4.1 目标

- 建立唯一、可执行、可测试的桌面视觉语言。
- 降低边框、胶囊、说明文字、重复标题和同质卡片产生的噪音。
- 让当前筛选范围、待处理事项、盈亏、R、风险和下一步动作优先进入视线。
- 统一所有页面的内容轨道、顶栏节奏、控件几何和状态反馈。
- 在 960×640 至 1920×1080 的 Windows/macOS 窗口中保持可达、紧凑和沉浸。
- 通过实际 Electron 页面截图反复迭代，而不是只依赖静态 CSS 契约。

### 4.2 非目标

- 不新增主题市场、皮肤系统或浅色主题。
- 不改变交易统计口径、资料库 schema 或领域数据。
- 不新增业务页面、顶级导航或营销式视觉装饰。
- 不引入渐变英雄区、玻璃卡片、发光边框、彩色噪点等装饰性趋势。
- 不为了截图重写已有业务流程或隐藏真实错误状态。
- 不适配手机、iPad、浏览器产品形态或触摸优先交互。
- 不迁移 CSS 框架，不增加仅用于视觉效果的运行时依赖。

## 5. 设计原则

### 5.1 事实先于容器

视觉权重由交易事实和决策价值决定，不由卡片面积决定。当前范围结果、待处理数量、风险阻断和主动作必须比背景、标签和辅助说明更醒目。

### 5.2 密度来自结构，不来自缩小

高密度通过稳定列、短标签、紧凑行高和渐进披露实现，不通过把正文压到 11px、把按钮压到难以点击或把所有信息塞在一行实现。

### 5.3 表面只表达层级

页面、内嵌区域、浮层和模态框各有一种表面。边框、阴影和圆角只有在解释包含关系、交互边界或浮层高度时出现。

### 5.4 一屏一个主动作

同一视区最多出现一个填充主按钮。描边按钮表示次级动作，文本或图标按钮表示三级动作。状态胶囊不承担“完成”“保存”等命令职责。

### 5.5 错误留在问题旁边

成功可以短暂消失；阻塞、失败和未完成条件必须持久显示、可导航，并指向用户可以修复的位置。

### 5.6 桌面小窗口不是手机

960×640 使用紧凑侧栏、分组折叠和操作溢出，仍保持桌面导航、鼠标与键盘模型；不切换底部导航或移动表单。

## 6. 视觉语言

### 6.1 令牌架构

令牌分为三层：

1. Primitive：原始颜色、4px 间距、字号、圆角、图标尺寸和时长。
2. Semantic：文字、表面、边框、焦点、状态和业务语义。
3. Component：按钮高度、工具栏间距、侧栏行高、字段几何和浮层配方。

页面 CSS 只消费 Semantic 与 Component 令牌。原始颜色只能出现在 `tokens.css`；必要光学校准值必须命名并写明用途，不能继续复制无解释的 5/7/9/15/18px。

兼容别名保留一个迁移周期，但新代码只能使用 canonical token。以下同义项收敛：

- `--fs-md` / `--fs-base`；
- `--radius-lg` / `--radius-xl`；
- `--shadow-med` / `--shadow-md`；
- `--sidebar-width` / `--sidebar-w`；
- `--list-text-strong` / `--list-text-primary`。

### 6.2 色彩

基础仍为石墨黑与微靛中性色，形成四个稳定层级：

- App：窗口最深底色；
- Pane：主工作区；
- Inset：表格头、字段、选中区域和局部强调；
- Floating：菜单、选择器、Toast 与模态框。

强调色使用一套低饱和靛蓝：

- 只用于键盘焦点、当前选中、主动作和少量结构定位；
- 不用于大面积卡片底色；
- 不与盈亏红绿争夺金融含义。

导航图标默认单色。选中项通过背景、文字和一处强调色表达，不再为每个入口配置独立彩色图标。盈亏、风险、警告、错过机会与收藏保留各自业务色，但减少背景填充和高饱和边框。

### 6.3 字体

UI 拉丁字体改为项目已安装的 Geist Sans；中文继续使用 `PingFang SC`、`Microsoft YaHei` 等系统黑体回退。金融数字使用 JetBrains Mono 或 Geist 的 tabular figures。

字体角色固定为：

| 角色 | 字号 | 行高 | 用途 |
| --- | ---: | ---: | --- |
| Page title | 20px | 1.25 | 页面标题、关键周期 |
| Section title | 13px | 1.35 | 区块标题、列表组标题 |
| Body | 15px | 1.5 | 说明、复盘正文、错误解释 |
| Data row | 13px | 1.35 | 表格、导航、紧凑控件 |
| Metadata | 12px | 1.35 | 日期、范围说明、辅助标签 |
| Caption | 11px | 1.3 | 非关键注脚；禁止承担操作原因或风险说明 |
| Financial value | 20–24px | 1.15 | KPI、盈亏、R |

页面不能用 metadata/caption 替代正文。大标题使用轻微负字距；小标签不默认全大写。所有金额、百分比、R、编号和时间开启 tabular figures。

### 6.4 间距与密度

保留 4px 基准，新增语义间距角色：

- control-gap：6px；
- row-gap：8px；
- section-gap：24px；
- page-inset-compact：20px；
- page-inset-default：28px；
- page-inset-wide：32px；
- optical-icon-gap：7px。

标准交易行保持 44px。工具栏和次级控件使用 28px，字段使用 32px，主要确认按钮使用 36px。不得用 44px 粗指针规则覆盖桌面控件。

### 6.5 圆角、边框与阴影

- 4px：小选项、日期格、kbd；
- 6px：按钮、字段、行选中、标签；
- 10px：独立面板、浮层；
- 14px：仅模态框外壳；
- full：仅状态点、头像、真正的胶囊标签。

页面级容器默认不使用阴影。分组优先使用间距和 1px 分隔线。浮层使用一套 tinted shadow，模态框使用更深一级配方；Tooltip 不与菜单共享阴影重量。

### 6.6 图标

图标尺寸固定为 14、16、18、20 和 24px；常用桌面工具栏只使用 14/16px。图标按钮容器固定为 28、32 和 36px。

TS 常量与 CSS 令牌保持同值，并通过静态测试验证。禁止新增 11、13、15、17、19、26px 的裸图标值。原始字符 `···`、`＋`、CSS 绘制的勾号和叹号逐步替换为同一图标系统；业务状态图标保持统一描边重量。

### 6.7 动效

动效按意图命名：

- state：100ms；
- tooltip/menu enter：100ms；
- dialog enter：150ms；
- dialog exit：120ms；
- panel：220ms；
- skeleton/spinner：独立周期。

只动画 `transform`、`opacity` 和必要的颜色属性。列表重排、KPI 数字和图表范围切换不播放装饰性入场。所有行为提供 reduced-motion 替代。

## 7. 桌面外壳与窗口规则

### 7.1 窗口档位

| 窗口 | 设计用途 |
| --- | --- |
| 960×640 | 最小可操作窗口；完成核心任务，不保证同时展示全部辅助信息 |
| 1280×860 | 默认窗口；主开发基准 |
| 1440×900 | 主要视觉验收基准 |
| 1600×1000 | 宽表、双栏详情与证据对照 |
| 1920×1080 | 宽屏约束、最大化和留白控制 |

### 7.2 侧栏与主工作区

- 1100px 以上：244px 标准侧栏。
- 960–1099px：208px 紧凑侧栏；减少章节留白，但保留文字标签。
- 用户显式折叠时可进入 56px 图标轨；不自动切换手机底栏。
- 主工作区继续使用内嵌 Pane，但最小窗口可将外缘 inset 从 8px 减至 6px。
- 低优先级顶栏动作进入统一 OverflowMenu，不通过隐藏滚动条让操作静默离屏。

现有 `MobileNavigation` 从受支持产品路径移除；移动端 CSS 可分批删除，但新增改动不得继续依赖 `pointer: coarse` 或手机安全区。

### 7.3 内容轨道

- 工作台/日志：最大 1200px，横向 inset 28px；宽表可占满可用 Pane。
- 分析页：最大 1240px；图表不超过 1200px 可读宽度。
- 叙事复盘：统一 920px；页头与正文严格共轨。
- 详情：主栏 `minmax(620px, 1fr)`，属性栏 336px，中间 1px 分隔线。
- 专注复盘：最大 1080px，短内容不撑满全部高度。
- 设置：正文 680px，允许右侧出现说明或预览列；不把 620px 内容孤立在 1920px 左侧。

## 8. 组件系统

### 8.1 Button 与 IconButton

`Button` 必须真实实现 sm、md、lg：

- sm：28px，用于工具栏；
- md：32px，用于页面操作；
- lg：36px，用于模态确认和关键完成动作。

变体固定为 ghost、bordered、primary、danger 和 danger-solid。旧类名只在迁移适配层存在，页面逐步改用组件 API。

`IconButton` 统一图标居中、可见焦点、hover、pressed、disabled、tooltip 和 aria-label。普通桌面动作不得小于 28px 容器。

### 8.2 SegmentedControl

接管 Topbar、仪表盘和周复盘的分段选择。选中态使用单一 inset 表面，不叠加重阴影；未选中项必须有 hover 与 pressed。

### 8.3 Field 与 FieldTrigger

文本输入、Select、DatePicker 和组合字段共享高度、内边距、边框、焦点和禁用配方。DatePicker 增加方向键、Home/End、PageUp/PageDown 和 roving tabindex。

### 8.4 PopoverSurface

浮层分为三类：

- Menu/Select：10px 圆角、标准浮层阴影；
- Tooltip：6px 圆角、轻阴影、短延迟；
- Modal：14px 圆角、深一级阴影与遮罩。

ContextMenu 补齐 `role=menu`、打开首焦点、方向键、Escape 和关闭后焦点恢复。TradeComposer、TradeCloseDialog 和 StrategyFormModal 复用 `ModalShell` 的焦点与 busy 合同。

### 8.5 状态组件

统一 `InlineStatus`、`Toast`、`SaveStatus`、`EmptyState` 和 `Skeleton`：

- Toast 支持 success、info、warning、error；错误默认不自动消失，除非页面已有持久错误。
- Toast 支持小队列，不能让后一个消息覆盖前一个失败。
- InlineStatus 用于表单阻塞、风险、数据缺失和恢复动作。
- SaveStatus 固定在页面顶栏同一位置。
- EmptyState 按“首次使用、筛选为空、权限/资料缺失、操作完成”区分构图与动作。
- Skeleton 必须匹配最终布局；修复未定义的 `--bg-active`。

## 9. 页面原型

### 9.1 工作台与日志

使用线性列表、稳定列和分隔线。超过三列的数据列表必须提供可见列标题。分组说明只在第一次需要解释时出现，后续分组使用短状态摘要。

### 9.2 分析页

控制区、当前结论、上下文摘要、图表和下钻依次排列。当前筛选范围永远是第一结论；固定本周或历史上下文不能抢占主层。

### 9.3 叙事复盘页

以章节和连续阅读为主。卡片只用于异常、独立交互或需要冻结的承诺。页面提供完成度和缺失项概览，主动作在长页面中保持可达。

### 9.4 详情页

正文和证据优先，属性栏次之。主动作属于正文工作流，不作为微型状态胶囊藏在标题边缘。短正文不强制撑出大片空白。

### 9.5 专注复盘页

一次只呈现一条记录，内容与评分保持视觉关联。短内容使用自适应高度；长内容独立滚动，评价栏保持可达。

### 9.6 设置页

按主题分组、以行和分隔线呈现。只在选项是互斥配置时使用独立容器；避免每项一个卡片。宽屏可以使用说明/预览列，但正文行宽保持稳定。

## 10. 核心页面设计

### 10.1 仪表盘

页面顺序调整为：

1. 分析范围与统计周期；
2. 当前选定范围 KPI；
3. 数据完整度；
4. 累计盈亏曲线；
5. 固定本周上下文摘要；
6. 策略表现和下钻。

“本周交易分析”从带背景高权重卡片降为上下文条或次级摘要，避免在选择全部历史时先展示相反方向的盈亏结论。范围控件拆成“数据范围”和“统计周期”两组；查看交易是次级动作，管理周期进入 OverflowMenu。

KPI 使用同一基线、同一说明位置和稳定等宽数字。背景只强调一个最重要值，不为四项指标分别造卡片。

### 10.2 周复盘

页头与正文统一为 920px。页面顶部增加紧凑完成度摘要：已完成步骤、缺失项和当前冻结状态。

七个步骤改为连续章节：

- 本周事实、评分、模式、证据和判断使用章节分隔；
- 风险异常、上次承诺和下周唯一承诺保留强调容器；
- 章节编号降为定位信息，不与标题争夺颜色。

完成动作使用底部 sticky action rail，并在页头提供状态而非第二个主按钮。校验失败时：

1. 显示持久错误摘要；
2. 标记所有缺失章节；
3. 滚动并聚焦第一个缺失字段；
4. Toast 只在成功完成时出现。

### 10.3 交易详情

主栏与 336px 属性栏之间增加细分隔线。右栏标题、属性和值使用稳定两列，次要分组默认折叠。

正文明确区分：

- 复盘正文：主要结论和证据；
- 补充追记：后续观察。

移除短正文强制 240px 的视觉空洞，使用内容自适应最小高度。完成复盘改为标准 32/36px 主动作，放在正文标题区或编辑区底部；“已复盘”单独作为状态，不与命令混用。

顶栏的星标、更多和前后导航统一为 28/32px IconButton。连续处理的计数、保存状态和下一条操作保持固定位置。

### 10.4 今日工作台

主标题随筛选变化：全部显示“还有 N 项需要处理”，待复盘显示“N 项待复盘”，待结果显示“N 项等待结果”。

严重风险摘要放在队列标签之前，并在不展开完整风险区时仍能解释阻断原因。队列行增加轻量列标题，稳定标明周期、盈亏、R 和日期。

分组说明压缩为单行，只在状态容易误解时出现。新建交易保持次级动作；当队列为空时才提升为主动作。

### 10.5 交易日志

保留月份分组与 44px 行高，增加吸顶列标题。收藏状态以低透明度常驻；选择入口在行 hover、focus-within 或选择模式时稳定可见。

空库状态只突出“新建第一笔交易”，导入备份和配置策略作为次级文本动作。筛选为空时不使用大插画，改为紧凑说明与“清除筛选”。

### 10.6 随机复盘

开始页将说明、数量和主按钮收进同一内容块，不把按钮放在远离文案的右侧。

单条复盘区最大 1080px。内容短时容器随内容收缩，评价栏与正文距离不超过约 240px；内容长时正文区滚动，评价栏吸底。顶部徽标减少为类型、标的和一项关键状态，其余元信息进入右侧紧凑摘要。

### 10.7 设置与系统页面

设置导航与主侧栏共用选中、hover 和 focus 语法。设置正文宽度统一，备份、导入、更新和风险管理使用同一操作行。

启动加载、资料库错误、关闭保存回执和路由错误复用统一状态组件，不再自行绘制按钮和状态图标。

## 11. 信息优先级规则

页面内信息按以下顺序分配注意力：

1. 当前任务或当前筛选范围；
2. 真实交易结果、风险和阻断；
3. 下一步主动作；
4. 支撑判断的上下文与证据；
5. 元数据、配置和历史说明。

业务颜色不能替代层级：盈利绿色金额可以醒目，但不自动成为页面主标题；风险红色只在需要行动时提升，历史错误标签保持克制。

同一信息只在一个主位置完整显示。重复出现时使用引用、短摘要或数量，避免本周指标与当前范围指标、保存状态与完成状态、标题与面包屑重复表达。

## 12. 交互与状态反馈

### 12.1 控件状态

所有交互控件必须覆盖：default、hover、pressed、focus-visible、disabled 和 busy。禁用原因不能只放 Tooltip；影响完成的原因应在控件附近常驻显示。

### 12.2 保存状态

保存状态固定在顶栏右侧：

- 未保存：中性提示；
- 保存中：静态或低运动进度；
- 已保存：短暂确认后降为低权重；
- 失败：持久错误、重试和数据管理入口。

### 12.3 成功、警告与错误

- 成功：短 Toast，可附一个有价值的下一步；
- 警告：页面内 InlineStatus，可被用户处理或明确忽略；
- 阻塞错误：持久摘要、字段标记、首错聚焦；
- 系统错误：独立状态页或模态，保留诊断、重试和安全退出路径。

通用 Toast 不能作为表单校验、资料库故障或不可恢复错误的唯一载体。

### 12.4 加载与空状态

路由和图表加载保留最终版式骨架；避免居中 spinner 让页面失去结构。空状态优先解释为什么为空以及当前最合理的一个动作，不把三个同权按钮当作导航菜单。

## 13. 键盘与焦点

- 侧栏、顶栏、列表、菜单和弹窗始终有可见 `focus-visible`。
- 侧栏不能以 `outline:none` 和 `box-shadow:none` 结束焦点定义。
- ContextMenu 打开后首项获得焦点，支持上下键、Home/End、Enter、Escape。
- DatePicker 使用日历网格键盘模型。
- 弹窗关闭后返回触发控件；busy 时禁止误关。
- 长表单校验失败滚动并聚焦首个缺失业务字段。
- 列表返回保持原行、滚动位置和焦点。
- 所有快捷键尊重输入框、编辑器和 IME composition。

## 14. Windows 与 macOS

共享 Chromium 渲染层使用同一视觉系统，但平台行为遵循原生预期：

- Windows：关闭到托盘首次明确说明，彻底退出路径可发现；系统缩放下边框和文字不落入异常亚像素。
- macOS：红色关闭仅关闭窗口并保留 Dock；`Cmd+Q` 彻底退出；菜单、快捷键和窗口控制遵循 macOS 语义。
- 两端都验证 100%、125%、150% 或对应 Retina 缩放下的字体、1px 分隔线、图标居中和浮层边缘。
- 窗口恢复必须将过大或离屏窗口收回当前 workArea，并确保标题栏可达。

窗口生命周期问题属于桌面完成度，但不以移动端兼容方案修复。

## 15. 实现边界与数据流

本设计不新增持久化领域数据。视觉设置沿用现有显示设置；所有布局状态仅存在于组件或当前窗口会话。

页面数据流固定为：

~~~text
领域事实 / 当前筛选
        ↓
页面 presenter 派生主结论、上下文和状态
        ↓
语义状态（positive / negative / warning / blocked / busy）
        ↓
统一组件原语
        ↓
用户动作 → busy → success 或持久 error → 焦点/下一步
~~~

页面不能直接根据颜色值决定业务状态；颜色只消费已命名语义。基础组件不能读取交易领域数据；页面 presenter 负责把领域事实映射为组件 props。

CSS 继续使用现有文件组织，但新增共享原语放在 `src/components/ui`。页面级结构调整尽量复用现有 DOM 与状态，避免大范围功能重写。

## 19. 风险与控制

### 19.1 字体切换导致排版漂移

Geist Sans 与 Inter 的字宽不同。先在侧栏、工具栏、表格和中文混排截图中验证，再全局切换；不通过缩小字号掩盖溢出。

### 19.2 令牌重构影响范围过大

先增加 canonical token 和兼容别名，再逐组件迁移；每批扫描 diff 和截图。兼容别名只在全路由收口后删除。

### 19.3 页面重排破坏业务行为

保持原有事件处理和数据流，优先移动现有结构而不是重写逻辑。任何行为调整都补对应回归测试。

### 19.4 移除移动端规则影响最小窗口

在删除规则前建立 960×640 Electron 基线；以桌面紧凑模式替代手机布局。不得简单删除后把溢出问题留给用户。

### 19.5 视觉统一抹平业务语义

盈亏、风险、警告、错过和收藏继续使用独立业务语义。统一的是饱和度、面积和组件表达，不是把所有状态变成同一种灰。

## 20. 完成定义

只有同时满足以下条件，视觉优化目标才算完成：

1. 验收矩阵 VIS-01 至 VIS-18 均有源码、自动化或 Windows/macOS Electron 证据；
2. 所有一级导航页面、详情、弹窗、空态、加载、错误和设置子页完成实际截图复核；
3. 960×640、1280×860、1440×900、1600×1000、1920×1080 均无不可达主动作、静默溢出或明显失衡；
4. 设计令牌、基础组件和页面 CSS 不再存在未解释的第二套颜色、字号、图标、动效或浮层配方；
5. 当前范围、核心交易数据、风险和下一步动作在每个页面都具有正确优先级；
6. 连续两轮全路由视觉审查均为 0 个 P0、0 个 P1，且第二轮没有新增跨页一致性问题；
7. 完整测试与桌面应用构建通过，Windows 与 macOS 证据分别成立；
8. 没有为了达成视觉效果引入手机、iPad、浏览器或其他平台分支。

达到以上条件前，目标保持进行中，继续根据实际页面效果迭代。
