# Linear 式全局排版系统设计

日期：2026-08-15

状态：视觉方向已批准，书面规格待复核

平台范围：仅 Windows 客户端与 macOS 客户端

## 1. 结论

Trader Atlas 的全局排版恢复为早期版本所采用的 Linear 式视觉语言。本轮不是只替换一个字体名称，而是统一字体家族、字号、字重、行高、字距、数字特性与文字灰阶，使侧栏、列表、正文、编辑器、弹窗、菜单和状态反馈共享同一套排版规则。

批准的目标为：

- 拉丁字母与数字使用随应用打包的 Inter Variable；
- 中文通过系统 UI 无衬线回退，在 Windows 使用系统中文 UI 字体，在 macOS 使用系统中文 UI 字体；
- 全局采用 11 / 12 / 13 / 15 / 20px 的核心字号层级，以及 400 / 500 / 600 的核心字重层级；
- 普通业务编号、日期、周期、R 倍数与金额继续使用 UI 字体，通过 tabular numerals 保证列内稳定，不再因为等宽代码字体产生割裂；
- 组件结构、页面布局、现有列表行高和月份分组栏保持不变。

Linear 的产品字体资产不是本项目依赖。本设计复现其排版比例、层级与节奏，不复制第三方私有字体文件。

## 2. 问题证据与根因

早期版本在 `72d2772` 中以 `Inter Variable` 为首选 UI 字体，整体目标明确标注为 Linear-style。2026-08-13 的 `1a19003e` 将入口字体改为 Geist Sans，并移除了 `Inter Atlas UI` 的本地声明，同时把设计测试改为锁定 Geist。

当前结果存在四个相互叠加的问题：

1. 拉丁与数字的字面和宽度从早期 Inter 骨架漂移为 Geist；
2. 中文依赖多段显式字体名回退，实际字面与拉丁部分缺乏统一的基线和密度；
3. `body` 基准为 16px，但页面又大量使用 11、12、13、15px 局部令牌，造成继承文字与显式文字节奏不一致；
4. 普通业务数据在 UI 字体与 JetBrains Mono 之间切换，编号、日期、R 倍数和金额形成不必要的“代码感”。

用户提供的 Linear 参考显示，目标并不是把所有文字加粗或缩小，而是建立稳定的五级字号、三级字重和清晰的文字灰阶，使高密度界面仍保持轻、稳、可扫读。

## 3. 范围

### 3.1 本轮包含

- 应用入口的字体资源与加载策略；
- 全局 UI 字体栈；
- 字号、字重、行高、字距与数字特性令牌；
- 主、次、辅助、弱化与禁用文字的对比层级；
- 侧栏、顶栏、数据列表、富文本正文、详情属性、弹窗、菜单、表单、Toast 与空状态的字体角色映射；
- 普通业务数字从等宽代码字体迁回 UI 字体；
- Windows 与 macOS Electron 客户端的字体加载、回退和视觉验证。

### 3.2 明确不包含

- 不改变月份分组栏的结构、背景、圆角、图标、间距或高度；
- 不改变列表行高、列宽、按钮尺寸、标签尺寸、侧栏宽度或页面内容轨道；
- 不重做颜色系统、图标系统、组件结构或业务交互；
- 不增加字体切换设置；
- 不下载或运行时请求远程字体；
- 不适配手机、iPad、浏览器或其他平台。

若字体切换暴露既有溢出，只允许通过正确的字体角色、最小宽度和截断规则修复，不通过改变页面布局或整体缩小字号掩盖。

## 4. 字体架构

### 4.1 UI 字体

应用入口恢复 `@fontsource-variable/inter` 的本地打包导入，并移除 Geist Sans 的 400、500、600 三个静态字重导入。UI 字体规范栈为：

~~~css
--font-ui-base:
  "Inter Variable",
  Inter,
  system-ui,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI Variable Text",
  "Segoe UI",
  "PingFang SC",
  "Hiragino Sans GB",
  "Microsoft YaHei UI",
  "Microsoft YaHei",
  "Noto Sans SC",
  sans-serif;
~~~

Inter 的 unicode range 只覆盖其提供的拉丁等字形。中文自动进入 `system-ui` 与后续平台字体：Windows 由 Segoe UI 的系统回退进入 Microsoft YaHei UI，macOS 由系统 UI 回退进入 PingFang SC。显式字体名只承担确定性后备，不覆盖平台首选。

字体资源随应用构建，不依赖网络。保留 `font-display: swap`；应用现有的 `document.fonts.ready` 启动等待继续防止首屏测量抖动，但相关注释与测试必须改回 Inter 语义。Inter 加载失败时，界面安全降级到平台系统 UI 无衬线，不得回退为 serif。

### 4.2 等宽字体边界

JetBrains Mono 只用于真正的技术内容：原始导入预览、诊断标识、哈希、代码片段或明确需要逐字符对齐的输入。

以下用户业务内容统一使用 `--font-ui`：

- 交易编号与案例编号；
- 日期与时间；
- 周期；
- 金额、百分比、胜率和 R 倍数；
- 仓位、止损、盈亏与统计 KPI；
- 列表计数和导航计数。

这些数字使用 `font-variant-numeric: tabular-nums` 保持列宽稳定；普通标题和自然语言中的数字使用 proportional nums。禁止用 JetBrains Mono 表达“专业感”。

### 4.3 字体合成与渲染

全局保留：

- `-webkit-font-smoothing: antialiased`；
- `text-rendering: optimizeLegibility`；
- `font-synthesis: none`；
- `font-optical-sizing: auto`；
- `font-feature-settings: "calt" 1, "rlig" 1, "kern" 1`。

等宽数字通过角色类或语义令牌开启，不在 `body` 全局开启，避免自然语言数字间距变僵硬。不得为中文设置负字距；负字距只允许用于经截图验证的拉丁标题角色。

## 5. 排版令牌

### 5.1 核心字号

| 角色 | 字号 | 行高 | 字重 | 使用位置 |
| --- | ---: | ---: | ---: | --- |
| Caption | 11px | 16px | 500 | 极短辅助标签、键位提示、图表微标注 |
| Metadata | 12px | 16px | 400 / 500 | 列标题、时间、次级说明、状态辅助信息 |
| Row | 13px | 20px | 400 / 500 | 侧栏、菜单、表格行、按钮、标签、表单标签 |
| Body | 15px | 23px | 400 | 复盘正文、说明段落、长文本 |
| Page title | 20px | 28px | 600 | 页面主标题与重要空状态标题 |

保留少量已命名的例外：

- Dialog title：15px / 22px / 600；
- Section title：13px / 20px / 600；
- Financial value：20px 或 24px，行高 1.15，字重 600；
- 编辑器一级、二级标题按正文比例派生，不新建第二套页面字号。

`body` 的基准从 16px 收敛为 Row 角色的 13px。产品可见文字必须映射到语义角色，不能依赖浏览器默认字号。

### 5.2 字重

全局只使用三个规范字重：

- 400：普通正文与普通数据；
- 500：选中项、交互标签、强调元数据与关键列表值；
- 600：标题、强结论与唯一主强调。

清理可见 UI 中没有语义理由的 700，以及只为“显得更清楚”而重复叠加的 600。中文跟随相同语义层级；若平台字体不提供连续变量字重，浏览器只能选择真实存在的 400、500、600，不允许人工合成。

### 5.3 字距

- 普通正文、中文、数据行与元数据：`letter-spacing: 0`；
- 页面标题和短拉丁强标题：最多 `-0.012em`，中文混排时由测试确认不存在挤压；
- 全大写微标签：最多 `0.02em`；
- 移除通用组件中无语义的 `0.04em`、`0.05em` 和 `-0.02em` 局部漂移。

### 5.4 文字灰阶

本轮只校准文字语义，不改背景与业务状态色。canonical 初始值固定为：

| 层级 | 初始值 |
| --- | --- |
| Primary | `lch(92% 0.8 272 / 1)` |
| Secondary | `lch(70% 1 272 / 1)` |
| Tertiary | `lch(56% 1 272 / 1)` |
| Quaternary | `lch(44% 1 272 / 1)` |
| Disabled | `lch(34% 1 272 / 1)` |

各层职责为：

- Primary：页面标题、选中项、关键结论与主要数据；
- Secondary：普通正文、普通列表值与可交互文字；
- Tertiary：元数据、列标题、辅助说明；
- Quaternary：占位、极弱提示和非关键图表标注；
- Disabled：只用于真实不可操作状态。

同一行最多出现三个文字灰阶。不能通过把普通文字全部提亮来模拟 Linear；Linear 式层级依赖稳定的明暗差，而不是全局高对比。

## 6. 组件映射

### 6.1 侧栏与顶栏

- 工作区名称、当前导航：Row / 500；
- 普通导航：Row / 400；
- 导航分区名：Metadata / 400；
- 数量：Metadata / 400 + tabular nums；
- 页面面包屑主项：Row / 600；次项：Row / 400。

### 6.2 列表与分组

- 列标题：Metadata / 400；
- 月份分组标题：Row / 600；数量：Metadata / 400；
- 交易编号、日期、周期：Row / 400 或 500 + tabular nums；
- 标的：Row / 600；
- 策略与标签：Metadata 或 Row / 500，取决于现有组件高度。

月份分组栏现有结构和几何必须保持像素级稳定。字体替换只允许改变字形，不得改变其高度、内边距、背景或展开行为。

### 6.3 正文与编辑器

- 复盘正文：Body / 400 / 23px；
- 正文小标题：15px / 22px / 600；
- 盘面摘要标签：Metadata / 400；
- 盘面摘要关键句：Body / 500；
- 图片说明与日期：Caption 或 Metadata，且与图片边界保持既有间距。

编辑器的占位、编辑态和只读态必须使用同一字体栈与正文度量，避免保存前后重排。粘贴内容不得把外部 `font-family` 带入产品正文。

### 6.4 浮层、表单和状态

- Button、Menu、Select、ContextMenu：Row；
- Tooltip、键位提示：Caption；
- 表单标签与输入：Row；帮助文字与错误说明：Metadata；
- Toast 标题：Row / 600；正文：Metadata / 400；
- EmptyState 标题：15px / 600；说明：Row 或 Body / 400。

Portal、弹窗和菜单继续继承 `--font-ui`，不得出现独立字体栈。

## 7. 实现边界与迁移顺序

实施顺序固定为：

1. 先建立字体加载与 canonical typography tokens；
2. 保留现有别名，让大多数页面一次继承新令牌；
3. 扫描并分类所有硬编码 `font-size`、`font-weight`、`line-height`、`letter-spacing` 与 `font-family`；
4. 只迁移偏离批准角色的声明，不机械删除合理的组件级角色；
5. 将业务数字从 `--font-mono` 迁回 `--font-ui + tabular-nums`；
6. 逐页截图检查后再删除 Geist 依赖与陈旧测试断言；
7. 最后清除兼容别名和无引用令牌。

字体切换不得顺带重构组件 DOM、事件处理、数据流或布局。发现与字体无关的问题只记录，不纳入本批次。

## 8. 状态与失败处理

- Inter 字体资源加载失败：自动回退 `system-ui`，应用仍可操作；
- 字体就绪等待超时：不得阻塞启动，记录诊断后使用系统 UI；
- 文字溢出：保留现有容器几何，优先验证角色是否错误，再使用现有省略与最小宽度规则；
- 中文缺字：继续沿平台回退链查找，最终保持 sans-serif，不能落入 serif；
- 粗体缺失：不使用浏览器合成字重；降级到最近的真实系统字重；
- 富文本外来字体：序列化与渲染层忽略外部字体家族，正文始终由产品令牌控制。

## 9. 测试与视觉验证

### 9.1 静态与单元合同

- 应用入口导入 Inter Variable，不再导入 Geist Sans；
- UI 字体栈以 Inter Variable 开始，并包含 `system-ui` 与 Windows/macOS 中文后备；
- canonical 字号只有批准的核心层级和已命名例外；
- canonical 字重只有 400、500、600；
- 普通业务数字不再使用 `--font-mono`，且启用 tabular nums；
- Portal、编辑器、弹窗、菜单与输入继承 `--font-ui`；
- 不新增 serif、远程字体 URL 或平台外适配分支；
- 月份分组栏的高度、内边距、背景和结构合同保持不变。

### 9.2 Electron 视觉矩阵

核心截图至少覆盖：

- 交易日志：侧栏、顶栏、月份分组、交易行与混合中英文；
- 今日工作台：风险、空状态、队列和数字；
- 交易详情：正文、盘面摘要、图片说明和属性栏；
- 仪表盘：金融数字、百分比、坐标与说明；
- 设置：表单、说明、按钮和禁用态；
- 菜单、Tooltip、Toast、Modal 与编辑器读写态。

Windows 验证 100%、125%、150% 缩放；macOS 验证 Retina。桌面窗口覆盖 960×640、1280×860、1440×900 与 1920×1080。浏览器截图只作为快速回归，最终字体与栅格结论来自 Electron 客户端。

### 9.3 必须量化的证据

- Inter Variable 在客户端实际完成加载；
- 中文节点实际解析为无衬线系统 UI 字体；
- 关键角色的 computed font size、weight、line-height 与 token 一致；
- 列表、侧栏和按钮没有新增截断；
- 月份分组栏几何相对基线为 0px 漂移；
- 所有采集页面 console error、page error 与水平溢出均为 0；
- `pnpm typecheck`、聚焦测试、`pnpm test`、`pnpm build:app` 和 Windows 打包通过。

macOS 字体证据必须由 macOS 构建或实机产生，不能用 Windows 浏览器回退结果代替。

## 11. 完成定义

只有同时满足以下条件，本轮字体恢复才算完成：

1. TYPE-01 至 TYPE-10 均有源码、自动化或 Electron 截图证据；
2. Geist 不再参与应用 UI 字体加载，Inter Variable 的本地资源可在离线客户端稳定加载；
3. 所有一级导航页面、详情、编辑器、浮层和系统状态完成字体角色扫描；
4. Windows 三档缩放和 macOS Retina 分别完成混排与溢出检查；
5. 月份分组栏和页面布局没有被本轮顺带修改；
6. 连续两轮核心页面视觉复核没有新增 P0/P1 字体一致性问题；
7. 测试、应用构建与 Windows 安装包构建全部通过。
