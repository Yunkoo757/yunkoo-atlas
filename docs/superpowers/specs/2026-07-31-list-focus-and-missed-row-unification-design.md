# 列表焦点与错过机会行样式统一设计

## 1. 背景

当前工作台存在两类明显不一致：

1. 交易日志等标准列表在整行入口获得键盘焦点时，会绘制蓝色整行描边；选中或程序焦点还会改变整行底色。该反馈过强，破坏高密度暗色列表的连续性。
2. “错过的机会”聚合页使用独立 `MissedOpportunityRow` 网格。来源占据固定首列，策略、错过原因和编号被压缩成一段摘要，字段顺序、结果列和行尾结构均与交易日志、模拟盘和案例记录不同。

用户已确认采用“标准 TradeRow 同构”方案，并明确要求列表整行焦点视觉全部取消。

## 2. 目标

- 所有工作台列表不再出现整行蓝框、亮边、左侧焦点标记或焦点底色。
- 多选状态只由复选框表达，不再通过整行底色表达。
- 鼠标悬停保留轻微灰色底，继续提供可点击性反馈。
- “错过的机会”与标准工作区共享相同的行结构、字段顺序、密度和响应式规则。
- 聚合页继续清楚表达来源、明确关联关系和回源动作，不损失现有业务能力。
- 通过共享布局边界阻止两个列表样式再次漂移。

## 3. 非目标

- 不取消按钮、菜单、输入框、选择框等独立控件的键盘焦点反馈。
- 不删除键盘导航、滚动跟随、详情返回焦点恢复或无障碍语义。
- 不改变交易、模拟盘、案例记录的业务数据结构和统计归属。
- 不改变错过机会的聚合、去重、来源范围、临时筛选或回源规则。
- 不把关联案例自动展开成重复列表项。

## 4. 已确认的视觉决策

### 4.1 列表行状态

标准行和聚合行采用同一状态规则：

| 状态 | 视觉反馈 |
|---|---|
| 静止 | 默认列表背景 |
| 鼠标悬停 | 轻微 `--bg-hover` 灰底 |
| 键盘焦点 | 不改变整行背景，不绘制描边、阴影或边缘标记 |
| 程序焦点 / 返回恢复 | 不改变整行背景，不绘制描边、阴影或边缘标记 |
| 多选选中 | 仅复选框显示选中；整行保持默认背景 |

整行透明覆盖按钮需要局部覆盖全局 `:focus-visible` 外框，避免在虚拟列表裁切后只露出上下两条蓝线。列表内部真实按钮（星标、菜单、标签按钮）仍保留自身紧凑焦点反馈。

### 4.2 错过机会行结构

聚合行与标准交易行使用相同的桌面字段顺序：

1. 状态图标。
2. 记录编号。
3. 品种与方向。
4. 策略、来源、错过原因及其他标签。
5. 周期。
6. 结果；错过记录显示“未成交”。
7. 机会 R；没有结果时显示“—”。
8. 业务发生日期。
9. 行尾动作。

来源不再占据固定首列，而是以中性标签出现在标准标签区，文案固定为“交易日志”“模拟盘”或“案例记录”。来源标签必须始终包含可见文字，不只依赖颜色或图标。

错过原因作为普通业务标签显示，不再与策略和编号拼接成摘要句。来源记录已删除时，在标签区显示“来源记录已删除”状态。

### 4.3 行交互

- 普通聚合项保持整行打开唯一来源详情。
- 明确关联多个来源的聚合项不允许整行猜测目标；行尾菜单提供“打开原始记录”和逐个“打开案例”。
- 普通项可保留空的行尾占位，以确保日期列和标准工作区对齐。
- 聚合页不显示多选复选框和星标动作，但共享布局必须保留相同列起点和行高。

### 4.4 响应式

- 桌面继续使用标准 44px 行高和标准列宽。
- 平板和手机复用标准 TradeRow 的断点、字段折叠顺序和触控尺寸。
- 移动端优先保留品种、方向、来源、日期和行尾菜单；次要标签允许截断或折叠。
- 375px 宽度不得产生水平滚动；最后一项必须能完整进入可操作区域。

## 5. 组件边界

### 5.1 共享行布局

从现有 `TradeRow` 中抽出纯展示型共享行布局，负责：

- 网格列与 44px 行高。
- 状态、编号、品种/方向、标签、周期、结果、R、日期和行尾插槽。
- 悬停背景和响应式折叠。
- 整行覆盖入口与行尾动作的层级关系。

共享布局不读取 Zustand，不决定业务导航，也不修改记录。它只接收已经准备好的展示内容和交互插槽。

### 5.2 标准交易行

`TradeRow` 继续负责：

- 把 `Trade`、策略、标签和结果转换为标准行内容。
- 多选、星标、右键菜单和整行打开行为。
- 将展示内容交给共享行布局。

移除 `.is-focused` 和 `.is-selected` 的整行视觉效果，但保留相应状态和业务逻辑。

### 5.3 错过机会聚合行

`MissedOpportunityRow` 继续负责：

- 从 `MissedOpportunityItem` 选择主记录、来源、关联案例和失效关系。
- 生成来源标签、错过原因标签和关联案例菜单。
- 普通项与合并项的不同导航约束。
- 将展示内容交给同一个共享行布局。

它不再声明独立桌面网格、行高、品种列、日期列或焦点样式。

## 6. 数据与导航

本次不改变数据流：

1. `MissedOpportunitiesView` 继续构建聚合摘要与筛选结果。
2. `TradeList` 继续提供虚拟化、滚动锚点和可见行上下文。
3. `MissedOpportunityRow` 将聚合项映射为共享行布局的展示插槽。
4. 普通项进入唯一来源；合并项通过行尾菜单选择来源。
5. 详情返回继续恢复 URL、滚动位置和 DOM 焦点，但恢复后的整行没有视觉高亮。

## 7. 无障碍边界

- 取消整行焦点视觉不等于删除焦点：DOM 焦点、可访问名称、键盘激活和滚动恢复全部保留。
- 整行入口仍提供明确 `aria-label`。
- 行尾菜单和列表内部按钮保留自身可见焦点样式，避免键盘用户无法判断正在操作哪个独立控件。
- 来源、错过原因、失效关系和关联数量必须通过可见文字表达。
- 多选状态由复选框的视觉与 `aria-checked` / 原生等价语义共同表达。

## 8. 测试设计

### 8.1 真实浏览器样式契约

- 聚焦标准交易行整行入口，断言入口无外框，行容器无阴影、无焦点背景、无伪元素标记。
- 聚焦聚合行整行入口，断言结果相同。
- 将标准行设为 `.is-focused`，断言背景保持默认。
- 将标准行设为 `.is-selected`，断言整行背景保持默认且复选框仍显示选中。
- 鼠标悬停标准行和聚合行，断言都使用同一轻灰背景。

### 8.2 共享几何契约

- 在同一桌面 viewport 渲染标准行和聚合行，比较行高、编号列、品种列、周期列、结果列、R 列和日期列的几何位置。
- 断言聚合行来源位于标签区，不存在独立来源首列。
- 断言普通项整行可打开；合并项非动作区域不导航，行尾菜单目标完整。

### 8.3 响应式与回归

- 在 1440px、1024px、768px 和 375px 下验证无横向溢出。
- 验证移动端菜单命中区至少 44×44px。
- 运行全部单元、浏览器、设计和生产构建验证。
- 使用真实页面截图对比交易日志、模拟盘、案例记录和错过机会的行结构。

## 9. 验收标准

1. 截图中所示的整行蓝框、亮边和焦点底色在所有标准列表与错过机会列表中彻底消失。
2. 多选行不再整行变色，复选框仍准确表达选择状态。
3. 错过机会与标准工作区的桌面行高、字段顺序和主要列位置一致。
4. 来源作为中性文字标签出现，不再占独立首列。
5. 普通项、合并项、失效来源和多个关联案例的导航行为保持准确。
6. 375px 无横向溢出，键盘、读屏和详情返回行为不回归。
7. 自动化测试、生产构建和真实视觉复核全部通过后重新生成 Windows 安装包。
