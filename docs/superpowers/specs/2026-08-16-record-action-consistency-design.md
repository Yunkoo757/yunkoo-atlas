# 记录动作一致性设计

## 背景

同一笔交易或案例在列表右键菜单、批量操作栏和详情页中拥有不同的动作名称、排序与能力。尤其是详情页只有“复制链接/复制编号”，没有与列表一致的“复制为新计划/复制案例”，用户容易把技术性复制和业务性复制混为一谈。

## 目标

- 为交易与案例建立唯一的动作名称和排序契约。
- 让列表右键与详情页共享相同的单记录业务动作。
- 让批量操作使用同一契约中适合批处理的子集。
- 让“复制记录”和“复制链接/编号”在视觉与语义上清晰分组。
- 保持现有安全复制规则：副本独立、结果和复盘状态重置、源记录不变。

## 非目标

- 不改变交易状态流转规则。
- 不为批量栏增加编辑、星标或提炼案例等语义不明确的动作。
- 不移除详情页复制链接和复制编号能力。
- 不面向手机、iPad 或浏览器产品形态进行适配。

## 统一动作契约

单记录业务动作按以下顺序出现：

1. 编辑交易 / 编辑案例记录
2. 复制为新计划 / 复制案例
3. 提炼为案例（仅非案例记录）
4. 加入星标 / 取消星标
5. 删除交易 / 删除案例记录

列表右键菜单的状态流转仍位于业务动作之前。详情页的工具动作位于业务动作之后：

1. 重新复盘（仅已完成复盘的记录）
2. 复制链接
3. 复制编号

批量操作仅提供复制与删除。单一类型选择沿用“复制为新计划”或“复制案例”；混合选择使用“复制所选记录”。

## 技术方案

新增纯函数动作契约模块，集中维护动作标识、名称和顺序。列表右键与详情页从该模块获得业务动作描述，分别映射到现有菜单组件。

新增单条安全复制执行器，读取操作瞬间的最新 store 状态并调用现有 `buildSafeTradeCopies`。列表右键和详情页共同使用该执行器，从而避免复制规则、错误提示和成功提示漂移。

详情页菜单组件增加分隔符支持，以区分业务动作与工具动作。分隔符不可聚焦，不参与键盘菜单导航。

## 交互反馈

- 源记录已变化或删除：提示“源记录已变更，无法复制”。
- 写入失败：提示“复制失败，请重试”。
- 交易复制成功：提示“已复制为新计划”。
- 案例复制成功：提示“已复制为新案例”。
- 批量混合复制：按钮显示“复制所选记录”，确认窗口显示各类型数量。

## 验证

- 纯函数测试验证交易、案例的动作名称和固定顺序。
- 单元测试验证右键与详情页共用的安全复制执行器不会修改源记录。
- 浏览器测试验证详情页可以直接复制为新计划，同时复制编号仍写入剪贴板。
- 菜单浏览器测试验证分隔符不进入键盘焦点序列。
- 运行类型检查、回归测试、构建和桌面视觉治理检查。
