# 周复盘历史状态与详情原位返回设计

日期：2026-08-02
状态：设计已确认，实施计划已完成，待执行
范围：周复盘 URL 状态、交易详情来源识别、返回位置与焦点恢复

## 1. 背景

周复盘当前将所选周次和页签保存在 `WeeklyReviewView` 的本地状态中。用户查看历史周或年度趋势时，刷新页面、复制链接或重新打开软件都会回到当前周的复盘详情。从历史周的交易证据或风险审计事件进入详情后，详情页也无法识别 `/weekly-review` 来源，返回动作通常退回交易日志；即使使用浏览器返回键，页面重新挂载后仍可能丢失原周次。

这些问题不会改变复盘数据，却会打断“查看证据—核对交易—继续复盘”的连续工作流，长期使用时尤其容易造成重复定位和上下文丢失。

## 2. 目标

1. 历史周和年度趋势状态可刷新、可分享、可在重新打开软件后恢复。
2. URL 与页面状态始终一致，不再维护互相同步的周次副本。
3. 从周复盘进入交易详情后，应用内返回和浏览器返回都恢复原周、原页签、原位置与键盘焦点。
4. 普通交易证据和风险审计事件使用不同锚点；同一交易在页面多处出现时仍返回到实际点击位置。
5. 无效链接安全回到当前周，不产生空白页、返回死循环或重复历史记录。
6. 不改变周复盘事实口径、持久化模型、视觉体系和产品定位。

## 3. 非目标

- 不重做周复盘页面布局或视觉层级。
- 不调整周复盘指标、冻结证据、风险计算或活动周推导规则。
- 不新增周复盘实体、导航历史实体或数据库字段。
- 不增加新的统计、提醒、任务或复盘模板功能。
- 不修改交易详情的正文、删除、案例提炼等业务流程。

## 4. 方案选择

采用“URL 为唯一页面状态来源”的方案。

未采用“本地状态与 URL 双向同步”，因为两个事实来源会在初始化、当前周滚动和非法参数纠正时产生竞态。未采用 `/weekly-review/:week/:tab` 路径段，因为本轮状态属于页面视图选择，不值得扩大路由结构、链接兼容和迁移范围。

周次与页签切换使用 `replace` 更新当前历史项。它们属于同一工作区内的查看状态，不应让浏览器返回键逐次穿越每次筛选操作；进入交易详情仍使用正常的历史压栈。

## 5. URL 契约

### 5.1 规范地址

| 页面状态 | 规范 URL |
| --- | --- |
| 当前周、复盘详情 | `/weekly-review` |
| 历史周、复盘详情 | `/weekly-review?week=2026-07-20` |
| 当前周、年度趋势 | `/weekly-review?tab=year` |
| 历史周、年度趋势 | `/weekly-review?week=2026-07-20&tab=year` |

默认值不写入查询参数：当前周省略 `week`，复盘详情省略 `tab=review`。这样既保留可恢复性，也避免默认入口产生冗余地址。

### 5.2 参数规则

- `week` 必须是严格的 `YYYY-MM-DD` 周起始日，并存在于页面现有 `availableWeeks` 中。
- `tab` 只接受 `review` 或 `year`；其中 `review` 会被规范化为省略参数。
- 未指定 `week` 时，状态跟随当前交易周；跨周后再次进入默认地址应显示新的当前周。
- 显式指定的有效历史周保持固定，不因自然周变化而跳走。
- 年度趋势使用当前选中周所属年份；切换周次时，年度视图随之切换年份。
- `visual` 等不属于本功能的查询参数原样保留，不参与周复盘状态判断。
- 输出查询参数使用稳定顺序，避免等价地址反复替换。

### 5.3 非法状态纠正

解析结果出现以下情况时，使用一次 `replace` 写回规范地址：

- 日期格式错误；
- 日期不是合法周起始日；
- 周次不在 `availableWeeks`；
- `week` 指向当前周；
- `tab` 值无效；
- 显式写入 `tab=review`。

非法周次回退到当前周，非法页签回退到复盘详情。纠正只删除或替换本功能拥有的 `week`、`tab` 参数，不清空其他参数。规范化必须幂等，防止 `useEffect` 与路由更新形成循环。

如果项目持久化数据存在异步就绪阶段，只有在 `availableWeeks` 已完成首次可信推导后才能判定“周次不存在”；不得把尚未加载完成误判为非法链接。

## 6. 状态与数据流

新增独立纯函数模块负责周复盘路由状态，页面不自行散落解析规则。建议职责为：

1. 输入当前查询参数、当前周和 `availableWeeks`；
2. 解析并返回 `{ selectedWeek, tab }`；
3. 同时返回规范化后的查询字符串以及是否需要替换；
4. 提供“修改周次”和“修改页签”的写回函数，并保留无关参数。

`WeeklyReviewView` 的所有派生数据继续使用 `selectedWeek`，但该值改为从路由状态取得。本地只保留草稿、展开状态等不需要刷新恢复的瞬时 UI 状态。

用户切换周次时，仍先执行现有草稿提交，再写入新 URL。提交失败时沿用现有失败策略，不提前切换到新周，避免草稿与页面周次错配。上一周、下一周和历史周选择器统一调用同一写回入口。

## 7. 交易详情来源与返回

### 7.1 来源状态

从周复盘打开交易详情时，写入现有 `TradeDetailFrom` 上下文：

- `pathname: '/weekly-review'`；
- `search`：当时完整且已规范化的查询字符串；
- `anchorTradeId`：来源页面内唯一的返回锚点 ID。

`anchorTradeId` 在现有返回机制中实际承担“来源页面锚点”职责，本轮允许使用带命名空间的稳定值：

- 普通交易证据：`weekly-trade:<trade-id>`；
- 风险审计事件：`weekly-risk:<event-id>`。

对应来源容器使用相同值作为 `data-trade-id`。这样可以复用现有 `rememberTradeReturnAnchor`、`useTradeReturnAnchor`、sessionStorage 生命周期和焦点查找逻辑，同时避免同一交易在风险审计和证据列表各出现一次时定位到错误区域。

打开详情前必须调用 `rememberTradeReturnAnchor(from)`，随后再使用 `tradeDetailNavState(from)` 导航。前者支持浏览器返回，后者支持详情页显式返回按钮、删除后返回以及记录不存在时的返回入口。

### 7.2 详情页识别

交易详情来源校验增加 `/weekly-review`，仅允许实盘交易使用该来源。详情页识别该来源后统一显示：

- 面包屑：`周复盘`；
- 返回按钮无障碍名称：`返回周复盘`；
- 空状态和已删除状态入口：`返回周复盘`。

返回目标必须保留来源 `search`，不能自行重建为当前周地址。

### 7.3 原位恢复

`WeeklyReviewView` 启用现有 `useTradeReturnAnchor`：

1. 读取详情页显式返回 state，或浏览器返回前写入的短期 sessionStorage 锚点；
2. 在查找 DOM 目标前通知来源页准备目标；风险事件锚点必须先自动展开“继续交易确认”审计区；
3. 等待目标证据或风险事件渲染并变为可见；
4. 将目标滚动到视口中部；
5. 优先聚焦带 `data-trade-primary-action` 的“查看交易”入口；
6. 恢复成功后清理一次性路由 state 或 sessionStorage 记录。

普通证据与风险事件的主链接都标记为主要操作。锚点值只用于页面内恢复，不参与交易查询、周次计算或持久化。

### 7.4 锚点缺失

交易被删除、交易日期被改到其他周、冻结证据与当前交易不再能对应，或风险事件不再渲染时：

- 仍停留在来源 URL 对应的原周和原页签；
- 不回退到交易日志，也不自动切换当前周；
- 将视口与焦点恢复到周复盘内容起点；
- 显示一次温和提示：`原交易已不在当前复盘证据中`；
- 清理待恢复锚点，避免每次渲染重复提示。

## 8. 组件职责

- 周复盘路由状态工具：纯解析、校验、规范化和查询参数写回。
- `WeeklyReviewView`：消费路由状态、协调草稿提交、统一创建交易详情来源、执行返回恢复。
- 普通交易证据组件：声明稳定证据锚点和主要操作。
- `WeeklyRiskEvidence`：声明风险事件锚点，并使用父级传入的来源上下文生成交易详情链接。
- `tradeRoute`：允许周复盘作为合法实盘详情来源，不负责解析周复盘参数。
- `DetailView`：根据来源选择周复盘文案，并完整回传锚点与查询参数。
- `useTradeReturnAnchor`：继续承担短期锚点保存、恢复前通知、查找、滚动、聚焦和一次性清理，不读取周复盘业务数据。

## 9. 错误与边界处理

- 没有任何历史数据时，默认地址仍正常显示当前周。
- 旧复盘实体永久保留在 `availableWeeks` 时，其深链接继续有效。
- 只存在活动但尚未创建复盘实体的周，只要进入现有活动周范围，其深链接有效且不自动创建实体。
- 超出现有最近活动周范围、且没有复盘实体的周按不可用处理，回退当前周。
- URL 状态纠正不得触发周复盘实体创建、草稿保存或业务事件记录。
- 查询参数变动后，异步草稿提交的完成回调不得覆盖用户后来选择的新状态。
- 浏览器返回恢复使用现有短期过期策略；过期锚点只影响原位滚动，不影响 URL 状态恢复。
- 新标签页直接打开历史周链接可以恢复周次和页签，但没有来源锚点时不尝试滚动。
- 同一交易在普通证据和风险事件同时出现时，以实际点击入口的命名空间锚点为准。

## 10. 测试设计

### 10.1 路由状态单元测试

- 默认地址解析为当前周和复盘详情；
- 有效历史周与年度趋势正确组合；
- 当前周参数和 `tab=review` 被压缩为默认地址；
- 日期格式错误、非周起始日和不可用周回退当前周；
- 非法页签回退复盘详情；
- 规范化保留 `visual` 和其他无关参数；
- 查询参数顺序稳定且规范化幂等；
- 默认地址跨周后跟随新当前周，显式历史周保持不变；
- 活动周、已有复盘周和不存在周遵守现有 `availableWeeks` 边界。

### 10.2 路由与详情测试

- `/weekly-review` 被识别为实盘详情的合法来源；
- 模拟盘和案例不能伪造周复盘返回来源；
- 返回目标保留完整 `search`；
- 详情、已删除和未找到状态都显示周复盘返回文案；
- 普通证据与风险事件生成不同且稳定的锚点。

### 10.3 浏览器集成测试

- 切换历史周后 URL 更新，刷新或重新挂载仍显示该周；
- 切换年度趋势后刷新仍保留页签和对应年份；
- 周次和页签切换使用替换语义，不增加过滤历史项；
- 复制历史周 URL 到新入口可复现页面状态；
- 非法 URL 被一次性清理，没有渲染循环；
- 从普通交易证据进入详情，应用内返回恢复原周、原页签、原卡片和焦点；
- 从风险事件进入详情，应用内返回恢复到该风险事件而非同交易的普通证据；
- 使用浏览器返回键得到相同恢复结果；
- 删除交易或修改交易周次后返回，停留原周并显示一次降级提示；
- 锚点缺失时焦点落到周复盘内容起点；
- 交易日志、看板、错失机会、复盘会话和风险设置的既有返回行为不回归。

### 10.4 完成门禁

- 受影响测试先失败、实现后通过；
- `pnpm typecheck`；
- `pnpm test`；
- 周复盘目标浏览器测试；
- `git diff --check`；
- 全部新增和修改文件可按 UTF-8 严格解码且无 BOM。

## 11. 验收标准

1. 当前周复盘详情的规范地址保持 `/weekly-review`。
2. 历史周和年度趋势可刷新、可分享、可重新打开恢复。
3. 周次和页签切换不会污染浏览器返回历史。
4. 非法周次或页签自动回到有效状态并清理参数，同时保留无关参数。
5. 从周复盘任一交易入口进入详情并返回，恢复原周、原页签、实际点击位置和键盘焦点。
6. 同一交易在页面多处出现时不会恢复到错误入口。
7. 原锚点不存在时不离开原周，并给出一次明确但不中断流程的提示。
8. 详情页所有正常、删除和缺失状态都使用“周复盘”来源文案。
9. 不新增持久化字段，不改变复盘计算和冻结数据。
10. 类型检查、完整自动化测试、目标浏览器测试和 UTF-8 检查全部通过。
