# Trader Atlas 桌面端视觉一致性优化设计

## 目标

在不改变业务逻辑、数据流、功能入口和信息顺序的前提下，收敛 Trader Atlas 在 Windows 与 macOS 桌面客户端中的视觉语言。优化重点是中等桌面窗口下的布局稳定性、跨页面信息层级、共享控件状态和设计变量复用，使产品呈现更克制、精致、专业的交易工具体验。

适配窗口范围为 960–1920px。本文不包含手机、iPad、浏览器产品形态或其他平台适配。

## 基线与结论

基线覆盖今日工作台、交易列表、交易详情、仪表盘、周复盘、随机复盘和数据设置，使用 960×640、1280×860、1440×900、1600×1000、1920×1080 五组桌面窗口，共 35 张截图。

当前系统没有阻断性视觉故障：截图不存在横向页面溢出、控制台错误或字体加载异常；Inter Variable、CJK 桌面字体回退、语义颜色、字号角色、圆角阶梯和按钮基础状态已经建立。问题主要来自页面布局规则和共享组件覆盖不完整，而不是现有设计方向错误。

## 按影响排序的问题清单

### P1：960–1100px 桌面窗口缺少统一收敛规则

- 页面：今日工作台、周复盘、设置、交易详情。
- 表现：周复盘视图切换文字折行；风险状态三列被压缩；设置页双侧栏挤压正文；详情页在固定属性栏与抽屉之间突然切换。
- 根因：页面只拥有零散的 1024、1099、1200、1268px 断点，没有统一的紧凑桌面策略。
- 方案：以 1099px 为统一紧凑桌面断点；保持交易表格隐藏次要列策略，补齐周复盘、风险状态和设置内容区的收敛规则。

### P1：页面内容轨道缺少语义化约束

- 页面：仪表盘、今日工作台、交易详情、周复盘、设置和随机复盘。
- 表现：页面最大宽度分别散落为 1240、1180、1040、920、680px，页面切换时左右边界和视觉重心跳动。
- 根因：宽度直接写在页面样式中，缺少按页面职责命名的内容轨道。
- 方案：新增 `wide`、`standard`、`reading`、`form` 四种语义轨道，以及 `compact`、`default`、`wide` 三档页面内边距。不同页面仍可使用不同阅读宽度，但必须通过同一套语义变量表达。

### P1：通用操作控件覆盖率不足

- 组件：普通按钮、图标按钮、分段切换、空状态操作、弹窗操作。
- 表现：源码中约有 278 个原生按钮，而共享 `Button` 和 `IconButton` 使用量明显偏低；视觉目前依赖多组兼容选择器维持。
- 根因：专用交互与普通操作控件没有清晰分界，页面级按钮逐渐累积。
- 方案：只迁移语义等价的普通操作按钮、图标按钮和分段切换；评分、标签、交易行和富文本操作等领域控件保持专用实现。

### P2：区块与表面层级表达不统一

- 页面：仪表盘、今日工作台、周复盘、设置。
- 表现：同级内容分别使用分隔线、卡片、内嵌底色或纯列表，区块标题、指标组和状态面的节奏不完全一致。
- 根因：语义颜色已经统一，但区块结构仍由页面独立组合。
- 方案：统一区块标题、指标网格、内嵌状态面和操作行的间距、边框与背景规则；不创建无法表达业务差异的笼统“大卡片组件”。

### P2：加载、空状态、错误、完成和禁用反馈存在多套语法

- 组件：`EmptyState`、`WorkbenchEmptyState`、`RouteState`、详情笔记加载、随机复盘加载、`InlineStatus`、弹窗按钮。
- 表现：整页状态、区块状态和行内状态的标题字号、图标容器、说明间距和操作位置不完全一致。
- 根因：状态组件按业务先后独立实现，缺少状态层级约定。
- 方案：定义 `page`、`section`、`inline` 三种状态层级；复用现有 `EmptyState`、`InlineStatus`、`Button` 和加载指示器，通过组合扩展而非重写状态逻辑。

### P2：周复盘样式缺少可维护的响应式结构

- 页面：周复盘、年度趋势。
- 表现：大量规则压缩在超长单行中，几乎没有桌面宽度适配；头部操作、评分控件、证据区和底部操作条最容易继续漂移。
- 根因：页面功能持续扩展，但样式结构没有同步分区。
- 方案：在不改变选择器语义的前提下整理样式结构，按页头、事实、风控、评分、证据、承诺和年度趋势分段，并增加紧凑桌面规则。

### P3：超宽窗口的信息利用率和锚点不稳定

- 页面：交易详情、设置、周复盘、仪表盘。
- 表现：阅读型页面留白较大，数据型页面接近满宽；合理宽度差异之外，页头和内容锚点仍存在不必要偏差。
- 根因：页面轨道和内边距分别计算。
- 方案：保留阅读型页面的窄轨道，但统一页头、正文和底部操作的水平锚点。

## 设计架构

### 1. 设计变量

在现有 `tokens.css` 中增加以下语义层：

- 页面轨道：`--page-rail-wide`、`--page-rail-standard`、`--page-rail-reading`、`--page-rail-form`。
- 页面内边距：`--page-inset-compact`、`--page-inset-default`、`--page-inset-wide`。
- 区块节奏：复用现有 4px 间距阶梯，补充必要的区块头、区块体和状态面语义别名。
- 表面层级：继续使用 `surface-pane`、`surface-inset`、`surface-floating`，不新增页面私有颜色。

颜色、字体、字号、圆角、阴影、图标网格、焦点环和动效持续由现有语义令牌管理。禁止在页面样式中新增直接颜色值、裸字号和裸圆角。

### 2. 页面布局边界

- 数据密集型：交易列表和仪表盘使用 `wide`。
- 工作台型：今日工作台和详情正文使用 `standard`。
- 阅读流程型：周复盘和随机复盘使用 `reading`。
- 配置型：设置正文使用 `form`；带辅助说明的设置页可在 `form` 旁增加固定说明栏。

布局能力优先以小型 `PageRail` 组件或公共 CSS 类提供。组件只负责宽度、内边距和水平锚点，不拥有业务标题、数据和滚动状态。

### 3. 公共组件边界

- `Button`：普通 CTA、次级操作、危险操作和弹窗操作。
- `IconButton`：只有图标的工具栏和行级操作。
- `SegmentedControl`：互斥视图与范围切换。
- `ModalShell`：弹窗层级、标题、正文、底部操作和进入/退出动效。
- `EmptyState`：整页与区块空状态。
- `InlineStatus`：警告、错误、成功和信息提示。
- `PropertyList`、`FieldTrigger`、`Select`：属性与表单行。

不迁移评分矩阵、交易行、标签按钮、日期格、富文本工具和其他领域专用控件，除非它们直接违反全局令牌或交互状态规范。

### 4. 紧凑桌面行为

在不支持移动端的前提下，为 960–1099px 桌面窗口定义如下行为：

- 应用侧栏使用现有 208px 宽度。
- 设置导航缩窄，正文使用 compact 内边距；导航文字保持单行。
- 周复盘页头操作保持单行，必要时收紧间距而不隐藏功能。
- 风险状态改为纵向紧凑行，完整保留今日、本周、本月信息。
- 交易列表继续隐藏编号、策略和部分绩效次要列。
- 交易详情属性面板继续使用现有抽屉，不改变打开方式或数据编辑行为。
- 弹窗保持现有视口内最大宽高和内部滚动策略。

## 状态与交互规范

- Hover：只提升文字、背景或边框中的必要层级，不叠加新的阴影和位移；按钮按下状态保留现有 1px 位移。
- Focus：键盘焦点统一使用现有 focus ring；鼠标点击不产生多余轮廓。
- Selected：导航、分段控件和列表选中使用 `bg-selected`，业务状态色不替代选择状态。
- Disabled：文字使用 disabled 层级，主按钮使用安静背景和边框，不仅依赖透明度。
- Loading：整页、区块和按钮加载分别使用已有加载指示器与 `aria-busy`；不引入新的动画形式。
- Empty：标题、说明和主次操作顺序一致；筛选无结果与首次使用保持不同文案但共享视觉骨架。
- Error/Warning/Success：使用 `InlineStatus` 或对应语义令牌；错误红、警告黄和盈利绿不承担普通选择反馈。
- Modal/Popover/Tooltip：继续使用既有浮层背景、边框、圆角、阴影和层级；不新增页面私有浮层样式。

## 数据流与业务边界

本次优化不改变 Zustand 状态、持久化、路由、交易计算、复盘完成条件、风险规则、导入导出、快捷键和 Electron 桥接。组件迁移仅替换视觉外壳，事件处理函数、禁用条件、ARIA 文义和数据读取保持原样。

任何需要改变文案含义、字段顺序、操作步骤或数据判断的发现均记录为后续产品问题，不在本次视觉优化中实现。

## 实施顺序

1. 增加语义页面轨道、内边距和状态节奏令牌，并建立设计契约测试。
2. 建立轻量页面轨道能力，迁移仪表盘、今日工作台、周复盘、随机复盘和设置页。
3. 修复 960–1099px 的周复盘、风险状态和设置布局。
4. 迁移风险较低的普通按钮、图标按钮和分段控件，保持专用业务控件不动。
5. 收敛空状态、加载、警告、错误和完成状态的视觉层级。
6. 整理周复盘样式结构并补齐紧凑桌面规则。
7. 重新生成所有视觉基线并进行主流程、浮层和状态回归。

## 验证方案

### 自动验证

- `pnpm qa:design`：颜色、字号、圆角、组件和令牌契约。
- `pnpm typecheck`：React、TypeScript 与 Electron 类型。
- `pnpm test`：业务和浏览器交互回归。
- `pnpm build`：生产构建和包体预算。
- `pnpm qa:desktop-visual --renderer`：五组桌面窗口、七个核心场景、字体与溢出检查。

### 视觉复查

- 对比修改前后的 960、1440、1920px 截图。
- 检查今日工作台、交易列表、详情、仪表盘、周复盘、随机复盘和全部设置入口。
- 检查空状态、加载、禁用、悬浮、焦点、选中、弹窗、菜单、Popover、Tooltip、错误、警告、成功和保存状态。
- 确认页面水平锚点、标题层级、指标数字、操作优先级、表单行和浮层表面一致。

## 完成标准

- 960–1920px 桌面窗口不存在页面横向溢出或关键操作折行。
- 页面轨道和内边距不再由核心页面直接写入无语义宽度。
- 通用操作与状态优先复用现有公共组件，专用业务控件保持清晰边界。
- 新增样式只消费语义颜色、字体、间距、圆角、阴影和动效变量。
- 所有业务测试、设计契约、类型检查、构建和桌面视觉矩阵通过。
- 主要页面和交互状态经截图复查后不存在新的视觉割裂或功能回归。
