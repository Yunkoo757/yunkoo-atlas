# 当前实盘统计与历史归档设计

> 2026-08-09 平台范围覆盖：产品后续仅支持 Windows 与 macOS 客户端。本文中的 Web、375/768 视口及移动端验收条目仅保留为历史记录，不再是产品要求；桌面 UX 与发布门以 `2026-08-09-desktop-ux-optimization-design.md` 为准。当前实盘、历史归档、边界和组合口径等业务决定继续有效。

日期：2026-08-08

状态：实施完成，待发布验收

## 1. 背景

现有产品同时向用户暴露“当前统计周期”“本周期交易”“实盘统计周期”“风险核算范围”“日志统计周期”等概念。它们实际对应不同的数据规则：

- 实盘绩效周期按平仓交易日划分已执行、已平仓实盘；
- 风险核算起点按开仓交易日决定风险额度与开仓门禁的数据覆盖；
- Dashboard 与交易日志还各自拥有自然周、自然月等时间筛选；
- Dashboard 默认把最新绩效周期视为当前范围，交易日志默认却不过滤绩效周期。

这些差异在数据层有必要，但不应要求用户在日常使用中理解。用户的真实诉求不是管理多个分析周期，而是：

> 可以单独重新开始当前实盘统计，同时不删除过去的交易、案例、图片和复盘内容；过去记录可在历史归档中回看。

## 2. 已确认的产品决定

1. “重新开始统计”只影响实盘表现统计，不重置风险规则、风险额度或开仓门禁。
2. 重新开始后，旧的已结束实盘从日常交易日志中收起，进入历史归档。
3. 旧交易形成的案例继续留在案例库正常可见，不随交易归档而隐藏。
4. 重新开始时尚未结束的计划单和持仓继续留在当前交易区；之后结束时归入新的当前统计范围。
5. 日常界面不再要求用户理解“统计周期”“绩效阶段”或“实盘轮次”。
6. 重新开始统计不复制、移动或删除历史交易和案例；归档是基于边界的派生视图。
7. 日常入口不携带用户可见的周期参数；当前实盘是默认范围，历史归档使用独立的归档入口。
8. 归档统计是随原始事实变化的派生结果，不是冻结快照；修正历史交易事实后，归属和统计可以依法重新计算。

## 3. 目标

- 让用户只需理解“当前实盘”“重新开始统计”“历史归档”三个概念。
- 重新开始后，Dashboard 的实盘结果自然从新起点重新累计。
- 日常交易日志聚焦当前仍在执行或属于当前统计范围的记录。
- 所有旧交易、案例、图片、正文和引用保持完整可访问。
- 风险核算与表现归档在用户界面和行为上完全解耦。
- 复用现有持久化边界和筛选能力，避免危险的数据迁移。

## 4. 非目标

- 重新开始统计不删除、复制或移动历史记录；用户原有的正常回收站操作不在本功能范围内。
- 不提供手动把单笔已结束交易拖入另一个归档的操作。
- 不允许通过修改筛选条件来美化归档成员关系；修正真实交易事实导致的自动重新归属是允许的。
- 不让“重新开始统计”顺带修改风险设置。
- 不隐藏或归档案例库中的旧案例。
- 不重新定义模拟盘、周复盘或随机复盘的产品方向。
- 不把历史归档设计成独立账户或多账户系统。

## 5. 用户心智模型

### 5.1 当前实盘

“当前实盘”是日常工作区，包含：

- 所有未删除的实盘计划单和持仓；
- 最新一次重新开始之后结束的实盘交易；
- 最新一次重新开始之后记录的错过机会；
- 无法可靠判断归档日期、需要用户补充信息的记录入口。

Dashboard 默认统计其中已执行且已平仓、数据有效的实盘。

“当前工作区集合”和“当前绩效统计集合”不是同一个计数：日志还要显示进行中、错过机会和待整理记录，Dashboard 指标只统计已执行、已平仓且结果有效的实盘。界面需要分别标注，避免用户将日志总数直接与绩效笔数比较。

### 5.2 历史归档

每次重新开始统计，上一段已经结束的实盘成为一份历史归档。归档页面本身是只读范围视图，不提供移动或删除成员的操作；交易详情仍可进行正常事实修正。归档保存的是边界和派生范围，不复制交易实体。

修正归档交易的平仓日期、执行状态或删除状态后，归属和统计按新事实重新计算；如果修正会使交易离开当前归档，保存前必须提示归属变化。归档不是用来锁定历史结果的快照。

归档卡片使用日期范围作为主要身份，例如：

> 2026年7月1日 — 2026年8月7日<br>
> 126 笔已平仓 · 胜率 48% · +16.4R<br>
> 关联案例 28 个

用户可以查看归档统计、搜索交易、打开详情和跳转案例。归档页不提供专门的删除成员或改写成员关系操作；从交易详情执行删除、平仓日期修正等原有操作时，仍遵循全局交易规则，并触发归属重算和必要提示。

“关联案例”只统计 `sourceTradeId` 指向该归档交易的案例；手动创建、没有来源交易的案例仍留在案例库，但不计入某一归档卡片。来源交易已被回收时，案例仍保留，并显示“来源已删除”或“来源不可用”。

### 5.3 案例库

案例库独立于当前实盘和历史归档：

- 始终显示全部未删除案例；
- 原交易归档后，案例仍处于原位置；
- 案例详情可轻量显示来源，例如“来自历史归档 · 2026年7月—8月”；
- 打开原交易时进入对应归档交易详情，不会把交易恢复到当前日志；
- 案例的图片、正文、掌握状态、标签与复盘记录均不改变。

### 5.4 风险管理

风险设置不属于归档模型。“风险核算范围”在设置页改称“风险数据起算日”，说明文案为：

> 仅用于判断风险额度和开仓门禁的数据覆盖，不影响当前实盘统计和历史归档。

交易日志和 Dashboard 不再暴露“实盘周期”“规则前”等风险范围筛选。

## 6. 归属规则

### 6.1 范围解析契约

范围解析分成“日志范围”和“绩效范围”两个层次，不能用一个筛选器混合实现：

- 日常实盘日志没有归档参数时默认当前实盘；没有任何边界时，全部历史自然属于当前；
- 历史归档使用 `/live-archive` 首页和 `/live-archive/:archiveId` 详情入口，归档 ID 只用于定位边界，不在日常界面展示；
- Dashboard 的实盘指标、策略下钻、曲线交易入口和“查看当前实盘”共享当前范围；
- `/period/this-week`、`/period/this-month` 等自然范围页，实盘取“当前实盘 ∩ 自然时间范围”，模拟盘保持原行为；
- 组合分析模式为“实盘当前范围 + 模拟盘全部历史”，并在范围说明中明确；
- 当前保存视图不固定某个边界，随当前实盘变化；历史归档保存视图固定归档 ID；
- 绩效范围只包含已执行、已平仓实盘；日志范围还要包含进行中、错过机会和待整理记录。

### 6.2 边界口径

归档继续使用业务交易日边界，最新边界代表当前实盘统计的开始日。已执行交易按可靠平仓交易日归属，区间保持左闭右开：

- 当前实盘：`closeDay >= latestStart`；
- 历史归档：`archiveStart <= closeDay < nextStart`；
- 首次边界之前的记录：进入最早的历史归档入口；
- 模拟盘不参与实盘归档。

该口径保持现有实盘绩效统计语义，不因界面重构而改写历史结果。

边界只精确到业务交易日，不按点击时刻切分同一天。因此以今天重新开始时，今天已经结束的有效实盘也属于新的当前统计，而不是旧归档。确认弹窗必须在存在此类记录时明确提示数量，不能让用户误以为会从按钮点击后的下一笔交易才开始累计。

业务交易日指应用现有的本地日期加“交易日开始小时”规则，不承诺交易所节假日历。已执行交易的 `closedTradingDayKey` 继续作为历史事实；错过机会也必须在进入终态时固化同一业务日，避免之后调整显示设置而改变归属。

### 6.3 进行中记录

计划中和持仓中的实盘始终属于当前工作区，不在重新开始时归档。它们之后结束时，按结束后的可靠交易日进入当前统计。

这样既不会隐藏真实持仓，也不会要求用户在重新开始时逐笔选择。

### 6.4 错过机会与非绩效记录

错过机会不进入胜率、盈亏和权益曲线，但可以按有效结束交易日随同交易日志进入当前或历史归档。日志归属优先使用固化的业务日，其次使用合法的 `closedAt`；不能用 `openedAt` 静默猜测归档。没有可靠日期的错过机会进入待整理。

### 6.5 日期缺失或畸形

已结束但缺少有效平仓日期的记录不得被静默隐藏，也不得猜测归档：

- 从表现统计中排除；
- 在当前交易区提供“待整理记录”入口和数量；
- 修复有效日期后自动进入正确的当前或历史归档；
- 历史归档页同样提供全局“待整理记录”入口，避免记录不可发现。

## 7. 重新开始统计

### 7.1 入口

Dashboard 的当前实盘统计区域提供主操作“重新开始统计”。不再显示“开始新统计周期”“管理周期”或周期选择器。

### 7.2 默认流程

默认以当前业务交易日为新起点。确认弹窗直接展示影响摘要：

> 将归档 126 笔已结束实盘<br>
> 3 笔进行中交易继续保留<br>
> 28 个案例继续留在案例库<br>
> 风险设置不会改变

若所选起点当天已有已结束实盘，摘要额外显示“起点当天 N 笔已结束实盘计入新的当前统计”。

操作：

- 主按钮：“确认重新开始”；
- 次级入口：“选择其他日期”；
- 取消不会改变任何状态。

不要求输入名称。持久化模型继续保留现有必填 `name` 字段以兼容 v10 快照；新边界自动生成稳定的内部日期名称，用户界面只显示日期范围。旧数据已有的自定义名称可作为归档副标题保留，但用户不再需要维护它，也不升级快照 schema。

### 7.3 高级日期选择

自定义日期必须满足：

- 是有效业务交易日；
- 不晚于当前业务交易日；
- 严格晚于最近一次重新开始的日期；
- 同一业务交易日不能重复建立边界。

选择日期后重新计算确认摘要，让用户在保存前看到将被归档、继续保留和待整理的数量。

如果所选日期之前没有有效已结束交易，仍允许建立边界，但不显示空的历史归档卡片；该边界只作为当前统计的起点。撤销这条唯一边界后，资料库恢复为“全部历史属于当前”。

### 7.4 原子保存

重新开始使用单一边界提交事务。界面不得在成功回执前宣称新范围已生效；实现可以先暂存内存边界，也可以先写入后发布，但必须具备与现有周期管理相同的失败回滚语义。若保存失败：

- 恢复原边界集合；
- 当前统计和日志可见集合保持不变；
- 提示“重新开始失败，原统计范围未改变”；
- 若回滚持久化也失败，提示用户重新打开应用核对，不虚假声明成功。

并发写入或 revision 冲突时，放弃本次提交并重新读取最新边界，不覆盖其他标签页或客户端的确认结果。

### 7.5 撤销

历史归档的更多菜单提供“撤销最近一次重新开始”。仅允许撤销最新边界。

撤销后：

- 最新归档与当前实盘重新合并；
- 交易、案例和图片实体不变；
- 新近结束的交易不会丢失；
- 确认弹窗展示合并后的交易数量和统计范围；
- 保存仍走与创建相同的原子提交和回滚路径。

撤销只移除最新边界，不恢复或重写任何交易实体；如果撤销后再次重新开始，仍按同一业务日唯一边界规则校验。

## 8. 页面设计

### 8.1 Dashboard

实盘模式下的主要区域改为：

- 标题：“当前实盘统计”；
- 辅助信息：“自 2026年8月8日重新统计”；无边界时显示“包含全部实盘历史”；
- 主操作：“重新开始统计”；
- 次要入口：“历史归档”；
- 下钻入口：“查看当前实盘”。

移除统计周期选择器和“当前统计周期”范围标识。

本周概览、净盈亏、胜率、平均 R、曲线和策略表现使用一致的当前实盘口径，再与用户选择的本周、本月、本年等自然时间范围取交集。页面不能出现顶部看似已切换、局部卡片却仍统计归档记录的情况。

周卡片、策略下钻、曲线数据表和交易详情返回链路都必须复用同一个当前范围解析结果。模拟盘保持原行为。组合分析模式中的实盘部分使用当前实盘范围，模拟盘不受归档边界影响，并在范围说明中明确显示“实盘当前范围 + 模拟盘全部历史”。

周复盘页面和已保存的周复盘快照不因重新开始统计而重算或改写；如果从当前 Dashboard 进入周复盘，页面应明确这是独立的自然周复盘口径。

### 8.2 交易日志

普通实盘交易日志默认显示当前工作区记录，不再把已归档实盘混入日常列表。

自然周期交易入口（例如本周、本月）在实盘模式下与当前实盘取交集；模拟盘和案例入口保持既有集合。显示偏好仍可隐藏已平仓行，但范围计数和“查看当前实盘”必须基于同一当前集合。

保留一个明确、低干扰的“历史归档”入口。移除日常筛选面板中的：

- 实盘周期；
- 当前周期；
- 规则前；
- 统计周期；
- 统计起点前。

“查看当前实盘”从 Dashboard 进入相同的当前集合，不额外制造用户可见的周期筛选标签。

待整理记录使用低干扰的统一入口：当前交易日志标题区在存在数量时显示“待整理 N”，归档首页顶部显示同一全局数量；点击后进入仅展示缺少可靠归属日期或结果的记录列表。修复日期或结果后，记录从待整理列表即时移出并按本地边界重新归属，返回路径保留用户原来的当前/归档语境。

直接打开归档交易详情仍然有效；详情页显示轻量“历史归档”状态和返回归档入口。

### 8.3 历史归档

历史归档是低频回看页面，按时间倒序展示：

- 日期范围；
- 已平仓数量；
- 胜率、净盈亏和平均 R；
- 结果完整度（已平仓数、有效结果数、结果冲突数、待补结果数和待整理日期数）；
- 关联案例数量；
- “查看归档交易”入口。

归档详情支持现有交易搜索和筛选能力，但不重新暴露风险范围或“周期”术语。归档范围、归档统计和归档详情中的自然时间筛选统一按可靠平仓业务日解释；筛选控件文案必须明确为“平仓日期”。普通当前交易日志若继续保留自然时间筛选，则沿用现有“开仓日期”语义，并在代码中使用独立的日志范围解析器。归档统计必须与归档交易列表共享同一归档解析结果。

最早边界之前的旧记录作为一份可发现的早期归档展示，不使用“pre-cycle”“统计起点前”等实现术语。

没有成员的边界不显示空卡片；待整理记录不属于任何归档卡片，但可从归档首页和当前交易区的统一入口进入。

### 8.4 案例库与详情

案例库默认集合不因重新开始而改变。不新增强制性的“当前/归档”顶层切换。

当案例源交易已归档时，详情页可显示来源标识并提供“打开归档交易”。来源标识不能取代案例本身的类型、标签或掌握状态。

### 8.5 风险设置

风险数据起算日只保留在风险管理相关页面。调整该日期时继续显示风险影响预览，但文案明确不会改变表现统计、当前日志或历史归档。

术语收敛必须覆盖现有入口：Dashboard 的周期控制区、交易筛选面板中的实盘范围下拉、风险设置页标题、周期管理弹窗和导入摘要文案。它们统一改用“当前实盘”“重新开始统计”“历史归档”“风险数据起算日”，不得留下“绩效阶段”“统计周期”“规则前”等用户可见同义词。

## 9. 路由与旧链接兼容

- 新的日常入口使用“当前实盘”和“历史归档”语义，不在界面暴露 `statsCycle` 或 `liveCycle`；使用 `/live-archive` 和 `/live-archive/:archiveId` 承载归档首页与详情。
- 旧的有效真实周期 ID 映射到对应归档详情；旧的 `current` 映射当前实盘并清除参数；旧的 `pre-cycle` 映射最早历史归档，没有历史归档时回退归档首页。
- 旧的 `all` 映射历史归档首页并显示全部历史归档，不得误解为当前实盘。
- 失效周期 ID、失效保存视图和无法解析的归档 ID 统一回退历史归档首页，并显示“原历史范围已不存在”的可理解提示，不得漂移到当前统计。
- 旧的风险范围深链在普通交易日志中清除并进入当前默认范围；风险管理内部仍可使用其领域状态。
- 新建的当前保存视图不固定边界，历史归档保存视图固定归档 ID；旧保存视图中的 `statsCycle` 按上述规则转换，旧 `liveCycle` 只清除风险筛选，不改变交易事实。
- 交易详情和案例详情的稳定 ID 路由保持不变。

## 10. 持久化与迁移

首版优先复用现有 `livePerformanceCycles` 边界集合：

- 最新边界解析为当前实盘起点；
- 较早边界解析为历史归档区间；
- 现有 ID 继续支持旧链接和保存视图；
- 内部 `name` 仍为 v10 快照的必填字段；新边界用稳定的日期范围自动生成内部名称，旧名称只作为可选副标题展示；不升级快照 schema；
- 不复制、不重写交易与案例实体；
- `liveStatsStartTradingDayKey` 继续只服务风险领域。

兼容规则：

- 没有边界的旧资料库：全部实盘属于当前工作区；首次重新开始时创建第一条边界，所选起点之前的有效已结束实盘形成第一份归档，起点当天及之后的记录属于当前实盘；
- 已有多个绩效周期的资料库：自动投影为当前实盘和多份历史归档；
- 缺少合法 `closedTradingDayKey` 的历史错过机会或已结束交易不补猜 `openedAt`；导入、恢复和首次读取时统一进入待整理，用户补齐事实后再按本地边界重新归属；
- 导入资料库继续保留本地边界优先的现有安全策略：导入交易、案例和周期边界时，当前资料库的边界集合胜过导入包，导入记录按本地边界重新投影，导入摘要改用“保留当前统计与历史归档设置”；
- Web、Electron、JSON 归档和恢复路径继续携带完整边界集合；
- 不因风险起算日存在而自动创建表现归档。

迁移不得通过复制交易或案例来制造归档。v10 快照读取后只补齐缺省边界字段和内部自动名称，仍以同一份实体集合计算当前与历史视图；不存在边界的快照保持“全部历史属于当前”的行为。

## 11. 数据一致性与安全

必须始终满足：

1. 重新开始前后，交易、案例、图片和复盘正文的实体数量不变。
2. 任一有效已结束实盘最多属于一个当前/归档范围。
3. 进行中实盘不会因重新开始而从当前工作区消失。
4. 案例与源交易的引用不会因归档而断裂。
5. 归档筛选不改变原始交易事实。
6. 风险预算和开仓门禁结果不因表现归档边界改变。
7. 保存失败、应用强杀或撤销操作后只能恢复完整旧边界或完整新边界，不能出现半提交。
8. 日志范围解析和绩效范围解析必须保持独立：前者可返回进行中、错过机会和待整理，后者只返回有效已执行已平仓实盘；任何页面不能用绩效解析器代替日志解析器。
9. 归档交易事实被修正后，归属和派生统计可重新计算；若交易因此离开当前归档，保存前必须提示变化，不能静默改写用户正在查看的范围。
10. 重新开始不改写既有周复盘快照；当前 Dashboard 跳转周复盘时，必须保留自然周的独立口径。
11. 当前保存视图动态跟随当前实盘，历史归档保存视图固定归档 ID；无效或已删除的范围只能回退归档首页，不能漂移到当前。
12. 正常交易回收站、案例删除和事实修正仍按原产品规则工作；表现归档不能把它们误变成“禁止删除”或“禁止编辑”。

## 12. 测试与验收

### 12.1 领域测试

- 多个边界正确生成当前范围和只读归档区间；
- 边界日交易按左闭右开规则归属；
- 跨边界持仓在新范围内结束后进入当前统计；
- 错过机会可进入日志归档，但不进入绩效指标；
- 缺失或畸形平仓日期进入待整理，不被静默丢弃；
- 错过机会的固化业务日、日志归属和绩效排除规则分别通过测试，且不会回退到 `openedAt` 猜测；
- 同日、未来或倒序边界被拒绝；
- 撤销只移除最新边界并保持实体不变；没有历史成员的唯一边界撤销后恢复全历史当前视图；
- 默认当前、显式归档、自然时间交集和“实盘当前范围 + 模拟盘全部历史”的范围契约分别通过测试；
- 新边界自动生成稳定内部名称，v10 快照无需 schema 升级即可读写。

### 12.2 页面与跨页测试

- Dashboard 不再出现统计周期选择器和相关术语；
- Dashboard 所有实盘指标使用同一当前范围；
- 重新开始确认摘要准确展示归档、进行中、案例和待整理数量；
- 起点当天已有已结束实盘时，确认摘要明确展示其仍计入新的当前统计；
- 交易日志默认集合与 Dashboard 的“查看当前实盘”一致；
- Dashboard 周卡片、策略下钻、曲线和交易详情返回链路与当前范围保持一致；
- 每份归档的统计、列表数量和侧栏数量一致；
- 结果完整度独立于风险完整度，空结果、冲突结果、待补结果和待整理日期有不同提示；
- 归档交易详情可返回原归档；
- 归档源案例仍在案例库可见并能打开原交易；
- 归档案例计数只纳入 `sourceTradeId` 指向归档交易的案例，来源已删除时仍可发现；
- 修正归档交易导致范围变化时有确认提示，归档页不提供手动移动成员操作；
- 风险设置和开仓门禁在重新开始前后结果一致；
- 375、768、1280 和 1920 宽度下主要流程可用。

### 12.3 持久化与兼容测试

- Web IndexedDB 和 Electron LibraryStorage 创建、撤销、失败回滚均原子；
- v10 现有周期数据无需复制即可投影为归档；
- 无边界旧快照保持全历史为当前；
- 旧 `statsCycle`、`all`、`current`、`pre-cycle`、无效范围、保存视图和详情深链均有稳定兼容行为；旧风险 `liveCycle` 只清除日志风险筛选；
- 导入和恢复使用本地边界重新投影，且不改写周复盘快照；
- 导入导出、备份恢复和并发写入不丢边界或案例引用；
- 强杀恢复后当前/归档范围与最后确认 revision 一致。

## 13. 发布完成标准

只有同时满足以下条件才视为完成：

- 用户日常界面不再需要理解统计周期、绩效阶段或实盘周期；
- 可以从 Dashboard 低成本重新开始实盘统计；
- 旧已结束交易全部可从历史归档发现；
- 所有进行中交易继续留在当前工作区；
- 案例库集合和案例内容完全保留；
- 当前 Dashboard 与当前交易日志口径一致；
- 日常日志默认当前、历史归档单独可达，且不要求用户理解实现周期参数；
- 结果完整度、待整理记录和无效旧链接均有可理解且不丢记录的入口；
- 模拟盘、自然周复盘和风险数据起算日不被表现归档误改；
- 不新增 v11 schema，不复制交易或案例实体；
- 风险结果在重新开始前后不变；
- 所有兼容、持久化、浏览器和构建门禁通过。

## 14. 分批实施规划

### 14.1 第一批：范围内核与当前工作流

先完成不改变交易实体的基础能力：统一日志范围与绩效范围解析器、边界校验、v10 兼容读取、旧链接映射、保存视图规则和 Web/Electron 原子持久化。随后接入 Dashboard 的“当前实盘统计”、低成本重新开始确认、当前交易日志默认范围，以及周卡片、策略、曲线和详情返回链路的同一范围契约。

第一批的用户可见结果是：用户能从 Dashboard 一步开启新的当前实盘，日常日志只显示当前工作区，风险数据起算日仍独立；历史归档先提供最低限度的可达入口和旧范围回退，不在此批引入复杂的归档管理界面。

第一批完成条件：领域与迁移测试通过；创建、撤销、失败回滚和强杀恢复通过；Dashboard 与当前日志计数一致；旧 `statsCycle`、`current`、`all`、`pre-cycle` 和无效链接均不漂移到错误范围。

### 14.2 第二批：历史归档与记录可发现性

在第一批稳定后实现归档首页、归档详情、结果完整度、待整理入口、关联案例、归档交易详情返回和“撤销最近一次重新开始”。补齐归档自然时间筛选的平仓日语义、来源交易已删除提示、事实修正导致归属变化的确认，以及无成员边界不显示空卡片。

第二批完成条件：每份历史归档可按日期范围回看，统计、列表和侧栏数量共享同一结果；所有旧已结束交易、错过机会和待整理记录都有可理解入口；案例、图片和复盘正文未被复制或隐藏。

### 14.3 第三批：兼容与长期使用加固

最后处理导入/导出、备份恢复、本地边界优先、动态与固定保存视图、周复盘快照不重算、并发 revision 冲突、焦点与无障碍提示、窄屏布局和大数据量性能。此批不新增统计概念，只降低维护成本和历史数据风险。

第三批完成条件：Web 与 Electron 路径一致；导入后按本地边界重新投影；强杀和并发冲突无半提交；375、768、1280、1920 视口主要流程可用，2 万笔交易下归档首页和详情仍保持可接受响应。

### 14.4 发布门禁

每批都必须先通过对应聚焦测试，再运行完整 `pnpm test`、类型检查、构建、浏览器四档视口和 UTF-8/no-BOM 检查。任何门禁失败都不得用放宽断言或静默回退当前范围来“通过”。发布前必须用模拟数据完整走一遍：已有历史 → 重新开始 → 当前日志 → 历史归档 → 打开案例 → 修正事实 → 撤销 → 再次重新开始。

## 15. 评审整合结论

本版吸收 DeepSeek 审阅中的高价值问题，同时保留当前代码的兼容边界：

- A1（名称必填）不升级 schema：内部继续满足 v10，界面改为自动日期名称；
- A2（非法范围回退）采纳：统一回到历史归档首页，禁止漂移当前；
- A3（Dashboard 周卡片口径）采纳：所有实盘卡片共享当前范围与自然时间交集；
- A4（交易日志默认范围）采纳：默认当前实盘，历史归档独立可达；
- B1（归档页）、B3（确认摘要）、B4（实盘/模拟混合口径）、B5（术语收敛）采纳；
- B2 改为独立“结果完整度”，不复用风险数据完整度；
- B6 采纳：待整理记录保留在实体集合中，以统一入口发现，不猜测日期；
- 额外补齐错过机会日期固化、导入本地边界优先、周复盘快照独立、事实修正重算和保存视图动态/固定规则。
