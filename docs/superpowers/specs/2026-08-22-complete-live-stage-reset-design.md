# Trader Atlas 完整实盘阶段重置设计

日期：2026-08-22  
状态：已实现；Windows 已验证；macOS CI 验证待完成
适用平台：Windows 客户端、macOS 客户端

## 1. 背景

当前“重置实盘统计”通过新的实盘时间起点重新划分当前数据与历史数据，并清空部分风险状态。交易、案例和周复盘仍是全局实体，历史归属主要由交易日期动态推导。

这种实现能够重新开始统计，但不是真正的业务阶段重置：

- 修改历史交易日期可能改变记录所属范围。
- 周复盘没有稳定的实盘阶段归属。
- 风险、绩效、案例和历史导航没有共享同一个一级领域边界。
- 重置后当前工作区与历史档案之间仍依赖多套筛选规则。
- 随机复盘无法明确选择当前阶段或历史阶段作为数据来源。

本设计将“重置实盘”升级为“结束当前实盘阶段并开启全新阶段”。每次成功重置都生成一个独立、稳定、可继续编辑的历史阶段档案。

## 2. 目标

完整实盘阶段重置必须实现以下结果：

1. 当前阶段在满足封账条件后归档。
2. 新阶段的实盘交易、案例、周复盘、风险与绩效从空白开始。
3. 策略、标签、模板、随记和个人设置继续跨阶段保留。
4. 所有阶段数据使用稳定阶段 ID 归属，不再根据可编辑日期动态换组。
5. 历史阶段中的交易、案例和复盘内容可继续自由编辑。
6. 历史阶段统计随历史交易事实实时重算。
7. 已完成周复盘的指标、证据和风险快照保持完成时事实。
8. 随机复盘默认覆盖当前阶段与全部历史阶段。
9. 阶段切换必须经过完整备份并作为一次原子提交完成。
10. Windows 与 macOS 使用相同的领域规则和持久化合同。

## 3. 非目标

本设计不包含：

- 手机、iPad、浏览器或其他平台的产品适配。
- 删除旧阶段或压缩历史档案。
- 跨资料库合并实盘阶段。
- 历史修改审计、修改原因或审批流程。
- 自动复制旧阶段交易、案例或风险参数到新阶段。
- 重置策略库、标签、模板、随记、快捷键或显示设置。

浏览器存储实现只保留为现有自动化测试和旧数据兼容基础，不构成产品平台承诺。

## 4. 核心术语

### 4.1 实盘阶段

一次连续的实盘实践周期。资料库始终且只能有一个当前阶段，可以存在任意数量的历史阶段。

### 4.2 阶段重置预约

用户发起、计划在下一个交易周生效的阶段交接意图。预约不是新阶段实体；只有成功交接时才创建新阶段。

### 4.3 阶段封账

将当前阶段标记为历史阶段、固定其结束边界，并创建新当前阶段的原子操作。封账不意味着历史数据不可编辑。

### 4.4 完成时快照

周复盘完成时冻结的指标、交易证据和风险证据。后续编辑历史交易不会改写这些快照。

## 5. 领域模型

### 5.1 LiveStage

```ts
interface LiveStage {
  id: string
  sequence: number
  name: string
  status: 'current' | 'archived'
  startsOn: string
  endsOn: string | null
  createdAt: string
  archivedAt: string | null
}
```

约束：

- `id` 在资料库生命周期内永久稳定。
- `sequence` 单调递增且不可重复。
- 阶段默认命名为“实盘阶段 N”，用户可以自由重命名。
- 只能存在一个 `status === 'current'` 的阶段。
- 当前阶段的 `endsOn` 与 `archivedAt` 必须为 `null`。
- 历史阶段必须具有 `endsOn` 与 `archivedAt`。
- 普通交易编辑不得改变实体的 `liveStageId`。

### 5.2 ScheduledStageRollover

```ts
interface ScheduledStageRollover {
  id: string
  requestedAt: string
  effectiveWeekStart: string
  postponedCount: number
}
```

约束：

- 同一资料库最多存在一个预约。
- 首次 `effectiveWeekStart` 为发起时点之后的下一个周一。
- 顺延时只更新 `effectiveWeekStart` 和 `postponedCount`。
- 预约期间不创建未来阶段，不提前改变任何实体归属。

### 5.3 显式阶段归属

以下实体新增 `liveStageId: string | null`：

- `Trade` 中的实盘交易和错过机会。
- `Trade` 中的案例。
- `WeeklyReview`。
- `WeeklyRiskPreparation`。
- `RiskPolicyVersion`。
- `MonthlyRiskLimit`。
- `RiskOverrideEvent`。

归属规则：

- 新建实盘计划、实盘交易或错过机会时使用当前阶段 ID。
- 从交易提炼的案例继承来源交易的阶段 ID。
- 独立创建的案例使用创建时的当前阶段 ID。
- 新建周复盘和风险实体使用当前阶段 ID。
- 模拟盘不写入实盘阶段 ID。
- 新建或正常编辑产生的阶段化实体不得写入 `null`；`null` 只表示旧版迁移无法可靠归属的待整理数据。
- 阶段 ID 不随开仓日、平仓日、记录时间或复盘时间的编辑而变化。

### 5.4 资料库级状态

持久化快照增加：

```ts
interface PersistedSnapshot {
  liveStages: LiveStage[]
  currentLiveStageId: string
  scheduledStageRollover: ScheduledStageRollover | null
}
```

载入快照时必须验证：

- `currentLiveStageId` 指向存在且状态为 `current` 的阶段。
- 阶段序号、ID 和名称满足唯一性要求。
- 所有非 `null` 的实体阶段 ID 都指向存在的阶段。
- `null` 阶段 ID 只允许出现在旧版迁移生成的待整理实体中。
- 不允许多个当前阶段或没有当前阶段。

## 6. 数据范围

### 6.1 随阶段归档并从新阶段清空

- 实盘交易与错过机会。
- 实盘关联案例和独立案例。
- 周复盘。
- 周风险准备。
- 风险政策版本。
- 月度风险限额。
- 风险越权记录。
- 当前阶段绩效投影。

“清空”表示新阶段查询不到旧阶段实体；旧实体仍保存在同一资料库，并通过历史阶段访问。

### 6.2 跨阶段保留

- 用户资料和头像。
- 策略库及策略图标、颜色。
- 品种目录和品种图标。
- 普通标签、错误标签预设。
- 复盘模板。
- 随记。
- 快捷键。
- 显示设置。
- 保存视图。
- 本地资料库位置、窗口状态和更新凭据。

保存视图若包含阶段范围，必须在失效时安全回退，不得自动改写到其他阶段。

## 7. 重置预约流程

### 7.1 发起入口

入口位于：

- 仪表盘的阶段管理操作。
- 设置 → 数据的实盘阶段区域。

入口文案统一为“开启新实盘阶段”，不再使用“重置实盘统计”。

### 7.2 预约确认内容

确认界面展示：

- 当前阶段名称和开始日期。
- 预计生效周一。
- 当前计划中和持仓中实盘数量。
- 当前周复盘状态。
- 将归档的交易、案例、周复盘和风险记录数量。
- 新阶段风险将恢复为未建档。
- 将继续保留的长期配置。
- 顺延规则和取消入口。

用户可以在存在计划、持仓或未完成周复盘时发起预约。这些状态只阻止实际生效，不阻止预约。

### 7.3 预约期间

- 当前阶段继续正常使用。
- 不锁定新增计划或开仓。
- 全局持续显示预计生效日和当前阻断项。
- 用户可在生效前随时取消预约。
- 同一资料库不允许创建第二个预约。

## 8. 生效与顺延

### 8.1 检查时点

应用在以下时点检查到期预约：

- 资料库完成载入、工作区显示之前。
- 应用从隐藏或休眠恢复并发现交易周已变化时。
- 用户打开阶段管理界面时。

应用关闭期间不运行后台任务。若应用在生效日之后首次打开，载入后立即检查。

### 8.2 硬阻断条件

以下任一条件成立时不得执行重置：

- 当前阶段存在 `planned` 实盘。
- 当前阶段存在 `open` 实盘。
- 生效日前一个交易周的周复盘不存在或未完成。
- 笔记图片或其他存储操作仍未完成。
- 无法创建完整备份。
- 完整备份校验失败。
- 当前资料库状态已经被其他写入者更新。

### 8.3 自动顺延

遇到硬阻断时：

- 不归档当前阶段。
- 不创建新阶段。
- 不清空风险状态。
- 不改变任何实体阶段归属。
- 将预约顺延到下一个周一。
- `postponedCount` 增加 1。
- 明确显示全部阻断项和新的预计日期。

顺延不会取消预约，也不要求用户重新确认。

### 8.4 成功交接

满足全部条件后：

1. 等待笔记草稿和存储操作完成。
2. 从最新状态捕获完整持久化快照。
3. 再次检查当前阶段和硬阻断条件。
4. 创建并验证完整 `.journal.zip` 备份或等价的桌面恢复备份。
5. 将旧阶段设为 `archived`，结束日期为新阶段开始日期的前一天。
6. 创建序号递增的新当前阶段。
7. 将预约设为 `null`。
8. 保持所有旧实体的阶段 ID 不变。
9. 将候选快照作为一次原子提交保存。
10. 保存成功后才向渲染层发布新状态并进入新阶段工作区。

成功交接不复制或删除交易、案例、周复盘和风险实体。

## 9. 新阶段行为

新阶段开始后：

- 当前交易日志为空。
- 当前案例记录为空。
- 当前周复盘按新阶段重新创建。
- 当前仪表盘没有阶段绩效。
- 当前风险状态为“未建档”。
- 可以创建实盘计划。
- 未完成首次风险建档前，禁止计划进入持仓。

首次风险建档必须重新填写：

- 资金基数。
- 单笔风险比例或金额。
- 日亏损上限。
- 周亏损上限。
- 月亏损上限。
- 风险纪律说明。

旧阶段风险值不得作为新阶段表单默认值。软件可以提供产品级空值提示，但不能把旧值视为已经确认的新阶段政策。

## 10. 当前工作区范围

以下界面默认只读取 `currentLiveStageId`：

- 今日工作台。
- 当前交易日志和看板。
- 进行中、星标实盘、错过机会。
- 当前案例记录。
- 当前周复盘。
- 当前风险状态。
- 仪表盘默认范围。
- 侧栏计数。

模拟盘和随记不受当前实盘阶段影响。

## 11. 历史实盘信息架构

历史实盘包含：

```text
历史实盘
├─ 全部历史
├─ 实盘阶段 N
├─ 实盘阶段 N-1
└─ 更早记录
```

每个独立阶段提供：

- 概览。
- 实盘记录。
- 关联案例。
- 周复盘。
- 风险记录。

阶段概览展示：

- 阶段名称和起止日期。
- 交易数量。
- 净盈亏。
- 胜率。
- 平均 R。
- 策略表现。
- 数据完整性提示。

“全部历史”聚合所有 `archived` 阶段，不包含当前阶段。

## 12. 历史编辑与统计语义

### 12.1 自由编辑

历史阶段中的以下内容可自由编辑，无需审计原因：

- 交易状态、价格、仓位、止损、盈亏和 R。
- 交易日期、策略、标签、心理、叙事和笔记。
- 评论和富文本附件。
- 案例洞见、分类、掌握状态和下次复盘时间。
- 周复盘正文、评分、标签和承诺。
- 删除、回收站恢复和永久清理行为沿用现有数据安全规则。

自由编辑不得自动改变 `liveStageId`。

### 12.2 实时统计

以下内容按当前实体事实实时重新计算：

- 单个历史阶段概览。
- 全部历史聚合。
- 历史阶段交易列表中的统计。
- 历史策略表现和盈亏曲线。

### 12.3 周复盘完成时快照

周复盘的以下字段保留完成时值：

- `metricsSnapshot`。
- `evidenceSnapshot`。
- `riskSnapshot`。
- `completedAt`。

修改历史交易后不重新生成这些快照。归档周复盘必须标注“完成周复盘时的数据”，避免与实时阶段概览混淆。

编辑周复盘正文、评分、标签或承诺不会自动改写完成时快照，也不会改变完成时间。

## 13. 随机复盘

### 13.1 默认候选池

随机复盘默认从整个资料库构建候选池：

- 当前阶段案例。
- 全部历史阶段案例。
- 当前与历史阶段中已经完成或标记错过、且具有有效复盘内容的实盘交易。

模拟盘继续由独立开关控制。

### 13.2 阶段来源筛选

设置支持：

- 当前阶段 + 全部历史，默认。
- 仅当前阶段。
- 全部历史。
- 指定一个或多个历史阶段。

每条随机内容显示来源阶段。历史案例的评估结果直接更新原历史案例，不复制到当前阶段。

随机轮次继续按资料库 ID 隔离，同一轮中同一实体不重复出现。阶段重置成功后，尚未完成的随机轮次继续保留；若轮次中的实体仍存在，则可以继续复盘。

## 14. 模块边界

为避免继续扩大现有 Store，新增独立纯领域模块：

- `liveStages`：模型验证、当前阶段解析、阶段命名和归属断言。
- `stageRollover`：预约创建、阻断检查、顺延和候选快照生成。
- `stageArchive`：历史阶段投影、聚合和实时统计范围。
- `stageMigration`：旧 Schema 到显式阶段归属的迁移。

UI 组件不得自行推导阶段归属。当前工作区、历史档案、风险、周复盘和随机复盘必须消费统一的阶段选择器或纯函数。

Zustand Store 只承担：

- 持有持久化状态。
- 调用领域模块生成下一状态。
- 在持久化成功后发布阶段切换结果。
- 提供界面所需的最小动作接口。

## 15. 持久化与失败恢复

### 15.1 原子性

阶段交接是单快照事务。不得先修改 Store、再尝试保存并依赖普通自动保存收尾。

桌面提交过程使用当前资料库的原子文件替换能力。候选快照在完整验证后一次写入 `journal.db`。

### 15.2 备份

每次实际生效前必须创建并验证恢复备份。备份包含：

- `journal.db`。
- `manifest.json`。
- 全部被当前快照引用的附件。

备份失败或验证失败属于硬阻断，不得执行阶段交接。

### 15.3 失败处理

任一步失败时：

- 当前阶段继续保持 `current`。
- 预约继续保留。
- 当前风险和周复盘不清空。
- 界面不得显示新阶段已创建。
- 错误信息说明失败环节和下一次重试时间。

遇到资料库 revision 冲突时，重新载入磁盘最新快照，并以最新状态重新计算阻断项。不得在旧状态上强行覆盖。

### 15.4 强制终止

必须验证以下终止点：

- 备份创建过程中。
- 备份验证完成后、候选快照保存前。
- 数据库临时文件写入后、原子替换前。
- 原子替换完成后、界面状态发布前。

重新启动后必须得到完整旧阶段或完整新阶段，不允许混合状态。

## 16. Schema 迁移

当前 Schema v11 升级为包含显式阶段归属的新版本。

### 16.1 阶段创建

- 若存在多个 `livePerformanceCycles`，按原顺序创建相应阶段。
- 第一个周期起点之前存在实盘数据时，创建“更早记录”历史阶段。
- 最新周期成为当前阶段。
- 若没有周期但存在数据，创建一个当前阶段并容纳现有可见实盘数据。
- 若资料库为空，创建“实盘阶段 1”作为当前阶段。

### 16.2 实体归属

- 实盘交易使用现有统一归属算法执行一次性迁移。
- 来源案例继承来源交易阶段。
- 独立案例按 `recordedAt`、`openedAt` 的可靠顺序匹配阶段。
- 周复盘按 `weekStart` 匹配阶段。
- 现存风险实体归入迁移后的当前阶段，因为旧重置流程不会保留完整历史风险集合。

### 16.3 待整理

无法可靠归属的实体不进行静默猜测，进入“阶段待整理”队列。待整理项：

- 不进入当前阶段绩效。
- 不进入历史阶段绩效。
- 保留完整原始数据。
- 提供人工选择目标阶段的修复入口。

### 16.4 迁移恢复

- 迁移前创建恢复副本。
- 数据库和 manifest 使用现有可恢复文件对协议。
- 迁移成功后才提升 manifest Schema 版本。
- 迁移失败时恢复旧数据库与旧 manifest，保持旧版资料库可再次打开。

## 17. 测试与验收

### 17.1 领域单元测试

- 资料库永远只有一个当前阶段。
- 阶段序号、ID 和名称满足约束。
- 实体日期编辑不会改变阶段 ID。
- 计划或持仓存在时禁止交接。
- 周复盘未完成时禁止交接。
- 阻断时只顺延预约，不改变阶段数据。
- 成功交接只追加一个阶段。
- 新阶段风险状态为未建档。
- 未建档风险阻止首次开仓。

- v11 空资料库。
- v11 单周期资料库。
- v11 多周期资料库。
- 周期前历史记录。

- 自动顺延文案与新日期。

### 17.4 Electron 与持久化测试

- 重置前备份创建与验证。

- revision 冲突重载。
- 磁盘空间不足。

- Windows 与 macOS 强制终止恢复。
- 退出流程与到期预约同时发生时的互斥。

### 17.5 性能与发布门禁

- 10,000 条交易下阶段筛选和历史聚合满足现有性能预算。
- 随机复盘构建全库候选池不阻塞主要交互。
- 完整阶段切换只有一个待保存快照，不产生 N 次订阅写入。
- Windows x64 安装包通过阶段交接 smoke test。
- macOS x64 与 arm64 产物通过相同领域与恢复测试。

## 18. 最终验收清单

- [ ] 用户可以在任意时间预约下周开启新阶段。
- [ ] 预约期间当前阶段继续正常使用。
- [ ] 有计划、持仓或未完成周复盘时自动顺延。
- [ ] 备份失败时不执行阶段切换。
- [ ] 成功切换后当前交易、案例、周复盘、风险与绩效为空。
- [ ] 长期配置和随记完整保留。
- [ ] 新阶段首次开仓前必须重新完成风险建档。
- [ ] 每次重置都生成独立历史阶段档案。
- [ ] 历史交易、案例和复盘内容可自由编辑。
- [ ] 历史阶段实时统计随事实变化。
- [ ] 已完成周复盘快照保持完成时值。
- [ ] 修改历史日期不会造成阶段跳动。
- [ ] 随机复盘默认覆盖当前阶段与全部历史。
- [ ] 历史案例评估写回原历史阶段。
- [ ] 旧资料库迁移失败时可以无损恢复。
- [ ] Windows 与 macOS 的行为和持久化结果一致。
