# Trader Atlas 回测项目：需求与边界记录

建立日期：2026-09-30。版本：0.9。保留既有边界、两轮独立 review、首版取舍与操作一致性记录，补充高频使用的设计打磨、两行头部的信息收敛与项目总览的对象列表整理。

状态：已在 `codex/backtest-projects` 实现首版；运行验证见第 13 节。用户已授权全部提交至 main 并推送发布；正式完成以候选认证、tag 工作流和完整双平台资产核验为准。

本文区分「已确认」「建议」「待定」。后续实现必须保留这种区分，不能将建议或待定事项直接当成用户已确认需求。

## 1. 产品定位

管理一次固定品种、固定交易规则的历史回测，按时间顺序检查系统内的交易机会，积累目标笔数，独立统计结果，并将值得反复学习的记录沉淀为案例。

示例：从 2025-02-26 开始检查 XAUUSD 历史行情，按同一套规则模拟参与交易，目标 100 笔。三个月完成或一年多完成均可。

目标笔数决定测试进度，实际覆盖日期说明测试范围。不能把「全年回测」或预先固定结束日期作为强制条件。

产品只适配 Windows、macOS 桌面客户端。浏览器路径仅用于开发和测试。

### 频繁使用要求

日常主流程：进入项目 → 记录交易与截图 → 填写最终 R → 继续下一笔。统计随记录自动更新；提炼案例、导出和归档按需操作。

- 创建项目只需名称、品种、历史开始日期；目标默认 100，规则说明和默认策略可稍后完善。
- 项目和品种自动带入新记录，不要求每笔重新选择；历史交易日期应明确填写或确认，不以今天的录入日期代替。
- 常用录入围绕历史日期与最终 R；正文、截图、价格、金额、仓位和标签按需补充，不能用长表单阻挡起稿或草稿保存。
- 沿用已有列表、详情、属性面板、图片预览和用户快捷键配置。返回保留项目、筛选及列表位置；不另造一套操作方式。
- 正常保存保持安静，结果待补可继续记录。达到目标只是提示，不弹出强制结项流程。
- 项目设置、费用说明、导出和归档在低频管理入口按需展开；解释文字不常驻占据记录区。
- 首版避免多层文件夹、强制逐笔检查清单、复杂状态审批和大批统计图表。

## 2. 已确认的决策

| 编号 | 边界 | 已确认结论 |
| --- | --- | --- |
| C01 | 回测对象 | 一个固定品种、一套固定交易规则下的系统内交易机会。 |
| C02 | 测试规模 | 以约 100 笔为目标，目标可调整；历史跨度随样本积累延长。 |
| C03 | 时间范围 | 指定历史开始日期，不强制预设结束日期。 |
| C04 | 样本选择 | 按时间顺序检查，依据当时的规则判断是否收录，不按后来盈亏筛选样本。 |
| C05 | 完成数量 | 完成模拟执行且结果可确认的盈利、亏损、保本记录均计入；观察、未参与和待补结果不计入完成数量。 |
| C06 | 结果录入 | 以最终实现的 R 为主，入场、止损、出场价格与金额可选。 |
| C07 | 单笔结果 | 每笔只保留一个最终结果，第一版不同时保存「理想结果」和「实际结果」。 |
| C08 | 执行错误 | 符合系统条件但执行出错的交易保留结果，以标签和正文说明错误。 |
| C09 | 策略与模板 | 沿用已有策略分类及复盘正文起稿模板，不建立第二套模板管理体系。 |
| C10 | 案例沉淀 | 支持从回测记录提炼案例，保留来源；案例不增加项目绩效样本。 |
| C11 | 统计隔离 | 回测统计独立，不能混入实盘、模拟盘的账户业绩与实盘风险管理。 |
| C12 | 导出范围 | 第一版支持当前项目的分析导出及完整资料库备份；单独导入一个回测项目留到后续。 |
| C13 | 实用性 | 优先复用现有记录、编辑、截图、标签、详情和案例能力，不扩展成复杂的研究或规则管理系统。 |

用户最后明确确认的三个选择是：R 为主且价格、金额可选；每笔只保留一个最终结果；先做分析导出与完整备份，项目独立导入后续再考虑。

## 3. 数据分类与归属

### 3.1 各类数据的职责

| 对象 | 职责 | 统计边界 |
| --- | --- | --- |
| 实盘记录 | 真实资金执行的交易 | 按既有实盘范围计算。 |
| 模拟盘记录 | 跟随当时行情进行的模拟交易 | 按既有模拟盘范围计算。 |
| 回测记录 | 对历史行情按固定规则进行模拟执行 | 只在明确选择的回测范围内计算。 |
| 案例 | 从交易或观察中提炼的学习内容 | 不参与交易绩效计数。 |
| 回测项目 | 管理本轮测试的范围、规则说明、样本和统计 | 统计成员必须明确可追溯。 |
| 策略 | 标记交易方法，复用现有分类 | 同名策略不能成为混合实盘与回测绩效的理由。 |
| 标签 | 标记时段、结构、错误等分析维度 | 标签或筛选条件变化不改变项目归属。 |
| 复盘池 | 按条件选择内容进行反复学习 | 复用已有学习流程，不代替项目管理。 |

「实盘＋模拟盘」等既有账户统计范围不能因加入回测而自动扩大。策略统计、周报、风险管理及其他聚合入口都需要核对来源范围，不仅核对回测项目页面。

产品分类与存储结构分开决策。当前代码没有回测类型；本文不预先规定新增枚举、表或文件的具体方式，实施设计必须证明各统计入口可以正确隔离。

### 3.2 归属建议

- 每笔回测记录只属于一个项目，以稳定归属管理，不依靠名称或标签推导。
- 一个项目固定一个品种；成员可使用已有策略分类，但仍须遵守本轮固定测试规则。
- 同一段行情用另一套规则再测试时，新建另一轮项目；两轮结果独立保存。
- 不自动将既有实盘、模拟盘或案例转换为回测记录，也不自动迁移真实资料。

这些是推荐的数据边界；跨项目移动、复制及既有记录批量纳入的交互尚未确认。

## 4. 项目、策略与正文模板

### 4.1 项目信息建议

创建时需要：名称、品种、历史开始日期。

可选信息：目标笔数（建议默认 100）、默认策略、规则说明、行情来源、时区、手续费与滑点处理说明。

运行中展示完成数量和待补数量；已检查到的历史日期可在继续测试或结束时更新，不要求每新增一笔都额外汇报进度。历史交易时间与实际录入时间分开，不能用今天的录入日期替代历史日期。

不要求填写本金或完整仓位才能记录 R。目标笔数不是容量上限；达到目标后是否继续及如何确认完成，见第 10 节。

### 4.2 复用方式

- 策略沿用现有策略列表。建议项目选择默认策略，新记录自动带入，单笔仍可调整。
- 正文沿用现有起稿模板，也允许自由书写。当前默认模板为「多周期盘面」：HTF 背景、MTF 触发、LTF 执行、复盘结论。
- 当前默认策略为「未分类」。策略分类名称本身不等于完整测试规则。
- 分类调整不改变项目规则或样本资格。实质改变入场、止损或出场规则属于另一轮测试；仅修正分类名称不需要另开项目。
- 项目默认策略参与既有策略引用维护。删除策略时同步重分配或清除默认值，保留项目规则说明，不能留下失效引用。
- 入场、止损、出场等本轮测试条件以项目说明记录，不新增规则引擎或项目专属模板体系。
- 名称修正、排版修正和不改变规则含义的说明补充可直接修改。

## 5. 单笔记录与统计

### 5.1 已确认的基本口径

- 盈利、亏损、保本都属于有效完成结果；保本不等于缺失。
- 未执行观察、未参与机会、待补结果不进入完成数量或胜率分母。
- 收录数量、有效完成数量、有效 R 数量分别显示，不能用一个数字掩盖数据缺失。
- 系统内交易出现执行错误仍保留结果，并记录错误原因。
- 每笔只使用一个最终结果；观察记录中的假设结果不能当成已执行结果。
- 缺失值不能当作 0R、保本或亏损。相互冲突的结果不能直接进入统计。
- R 表示相对本笔初始风险的最终结果，不随移动止损重新定义风险分母。手工录入与费用处理方式可在项目说明和导出中解释。
- 结果判定复用 Atlas 既有可信口径；只选择「盈利／亏损／保本」而没有有效数值依据，不能为方便计数而判为有效结果。

这些统计描述「本轮实际模拟参与的样本表现」，包含已记录的执行偏差。观察、未参与和待补另列，不将样本统计表述为全部系统机会的理想执行结果，也不要求逐个登记所有未参与信号。

示例：完成 82 / 100，另有 3 笔待补。观察记录即使有截图、正文或假设结果，也不增加这 82 笔。

### 5.2 单笔单位建议

一次完整交易算一笔。分批止盈和移动止损属于其过程，汇总最终结果；退出后重新入场作为另一笔交易。第一版不因采用分批退出而新增多腿交易管理体系。

该单位定义属于建议，尚未就加仓、重叠持仓等特殊情况确认细节。

### 5.3 首版最小统计

| 指标 | 首版口径 |
| --- | --- |
| 完成进度 | 有效完成笔数 / 目标笔数，观察与待补单独显示。 |
| 盈利、亏损、保本数量 | 依据已确认且无冲突的完成结果。 |
| 胜率 | 盈利笔数 /（盈利＋亏损＋保本笔数），沿用现有可信结果口径。 |
| 总 R、平均 R | 只用有效 R；平均 R 的分母为有效 R 笔数。 |
| 有效 R 数量 | 单独显示指标覆盖，例如「R 覆盖 78 / 82」，不假定每笔完成记录都有 R。 |

首版只保留以上统计，自动计算，不要求额外填写分析表单。累计 R 曲线、回撤、连亏、盈亏因子和多维拆分暂不进入首版合同，后续根据实际使用再增加。

项目按自己的成员与历史时间选择样本，复用结果判定及指标计算；不能直接套用账户统计的当前业务日期、实盘阶段和金额范围。

## 6. 案例沉淀

已确认流程：回测记录 → 主动提炼案例 → 案例库 → 既有复盘池与随机复盘。

- 原始记录继续属于回测项目并参与其统计。
- 案例保留来源记录关联、来源项目信息及来源正文与截图证据，拥有独立的经验总结。
- 修改案例总结不能改写原始回测正文或结果。
- 案例沿用已有分类和学习状态，不新增「回测专属案例库」。
- 用户决定是否提炼及如何分类，不能按盈利或亏损自动判定案例质量。
- 来源项目归档后，案例仍可正常学习。
- 回测来源案例独立于实盘阶段，不沿用「来源缺少实盘阶段就写入当前阶段」的回退逻辑；实盘阶段轮换不改变其学习资格。
- 首版原始回测记录留在项目内；主动提炼的案例进入既有复盘池与随机复盘。复盘池计数和会话候选采用一致范围，避免显示可学但会话无法选中的记录。

建议同一来源重复提炼时提供已有案例入口，避免无意重复。案例继续复用既有附件资产，不复制另一套图片管理体系；来源项目说明不能仅依赖一次临时页面状态。来源删除、项目删除及附件保留方式见第 10 节；不能默认级联删除已经沉淀的案例。

## 7. 完成与归档

建议以轻量状态管理：项目列表展示进行中和已归档，完成通过进度与完成标记表达，具体界面无需先增加第三套管理列表。

- 达到目标后允许继续测试，不自动截断新记录。
- 建议由用户主动确认完成，记录实际覆盖范围和简短总结。
- 归档收起项目、保留数据，需要时重新打开。
- 第一版不建立复杂的规则版本管理、自动冻结或多层文件夹体系。
- 如需保留某次结论的历史依据，可以保存当时的分析导出包；导出时间及口径必须可查。

首版采用主动标记完成，达到目标后仍允许记录；归档暂停新增，既有记录可编辑、可提炼案例，可重新打开项目。

## 8. 分析导出与完整备份

### 8.1 已确认范围

第一版支持当前项目的分析导出，并确保完整资料库备份包含回测项目、成员记录、关联关系和引用附件。第一版不承诺分析导出包可以作为独立项目重新导入。

导出范围明确限定为当前项目；不能为了提供给 agent 而无意导出整份资料库或其他项目。

### 8.2 分析包建议

| 内容 | 用途 |
| --- | --- |
| 项目说明 Markdown | 品种、测试规则、历史覆盖、数据来源、进度、统计口径与用户总结。 |
| CSV 与 JSON 记录 | 提供稳定编号、历史时间、最终结果、R、策略、标签、正文等原始依据，便于重新计算。 |
| 统计摘要 | 指标、各自分母、结果缺失及排除情况，避免仅提供一个胜率数字。 |
| 附件与索引（可选） | 截图关联到具体记录，用户选择是否包含。 |

分析包应记录导出时间和数据格式版本，后者不是复杂的项目版本系统。agent 的结论应能指向记录编号，回到 Atlas 核对。

首版分析包为 ZIP，含 README.md、project.json、trades.csv 和当前项目引用的全部截图。JSON 保留原始正文 HTML、策略分类、记录编号、统计摘要、附件索引与导出时间；案例独立总结不包含在分析包，案例不会重复计数。完整资料库备份保留案例。

附件不能仅导出当前机器上的绝对路径作为可携带证据。选择包含截图时，需要核验附件完整性；分析导出不具有完整备份的恢复承诺。

## 9. 第一版范围与验收基线

### 9.1 范围

项目管理、回测记录录入、独立统计、案例沉淀、项目分析导出、完整资料库备份覆盖。

复用现有记录编辑、截图、标签、起稿模板、详情导航与案例学习能力。侧栏「更多」增加「回测项目」，项目列表采用标准内容轨道；项目详情采用既有交易列表工作区，不新增快捷键体系。

在项目内通过页面按钮或已有全局「新建交易」动作创建记录，必须自动归属当前项目和固定品种，不能回退创建为实盘。「新建案例」等其他已有动作保留其用途。项目打开的详情在返回与前后切换时保留项目范围；显式切换到交易日志或策略入口时展示新的范围。具体路由形式留待设计，不新增快捷键体系。

后续再考虑：项目独立导入、自动行情回放、自动识别交易机会、规则引擎、理想与实际双结果、复杂策略版本、多项目自动比较、扩展统计图表及原始回测记录的专属学习入口。

### 9.2 后续实现的验收基线

以下保留完整验收目标；本轮实际已执行范围见第 13 节，未覆盖平台不得视为通过。

1. 可以在同一品种、同一规则下积累目标样本，不强制限制为一年，也不因达到 100 笔截断记录。
2. 有效完成、观察、待补、缺失 R 与冲突结果的进度和统计口径可解释，无缺失补零。
3. 回测不会混入实盘、模拟盘、实盘风险管理及其他账户聚合统计。
4. 提炼案例后，原始样本数量和统计不变；案例可追溯来源，独立总结不会改写源记录。
5. 策略与正文模板复用已有配置，价格、金额可选，单笔只保存一个最终结果。
6. 项目分析导出范围准确，记录编号、统计分母和附件索引可以相互核对。
7. 完整资料库备份及恢复保留项目归属、结果、案例来源与附件；所有写入演示使用隔离测试资料库。
8. Windows 与 macOS 的最新可操作客户端完成所改流程验证，不能以静态检查代替运行验收。
9. 项目内页面新建交易和全局新建交易保持身份与品种；详情返回、前后切换及图片操作沿用现有习惯，不丢失项目或列表位置。
10. 回测来源案例不挂入实盘阶段；项目归档与实盘阶段轮换不改变其学习资格，复盘池数量与会话候选一致。
11. 策略删除同步处理项目默认策略引用；分类变动不改写项目规则，备份恢复后身份和归属不会静默变成模拟盘或实盘。

这些是用户授权施工后采用的轻量默认值，不能回写为用户逐项明确确认的要求。

| 事项 | 首版行为 |
| --- | --- |
| R 的完整性 | 正数盈利、负数亏损、0 保本；留空允许暂存。结果依据不足或冲突不计目标，其他编辑入口已有可信金额结果时仍沿用统一真值口径，不增加 R 必填门槛。 |
| 单笔单位 | 一条完整交易记录计一笔；重新入场另记。加仓、多腿合并及双结果模型不增加专属机制。 |
| 样本纠错 | 沿用详情编辑和可恢复的删除记录流程；不另建排除审批。实际执行偏差保留结果和标签。 |
| 完成与归档 | 手动完成，达标后可继续记录；归档暂停新增，原记录可编辑、提炼案例、导出；重新打开后继续录入。 |
| 删除与移动 | 不新增删除项目、跨项目移动或跨项目复制按钮，不删除来源案例。 |
| 统计 | 进度、胜负保本、胜率、总 R、平均 R；附有效 R 覆盖。未参与、待确认不计目标，无 R 时显示缺失，不伪造现金结果。 |
| 导出 | ZIP 含 Markdown、JSON、CSV 和当前项目全部引用截图；附件缺失则阻断导出并提示。案例独立总结不混入原样本。 |
| 页面入口 | 侧栏「更多」的回测项目 → 项目列表 → 项目记录 → 既有详情；按钮和全局新建动作带入项目上下文。 |
| 记录操作 | 复用日志与案例列表的行勾选、右键菜单、全选和批量复制／删除。复制保留当前项目与历史日期，清空结果和复盘正文；待确认副本不计完成进度。筛选或切换项目后清除不在当前范围的选择。 |
| 固定规则 | 首条记录或来源案例存在后锁定品种、历史开始和规则正文；名称、目标、默认策略仍可调整。 |

后续独立项目导入、复杂版本、行情回放和扩展图表继续留待真实使用反馈，不在本轮增加。
