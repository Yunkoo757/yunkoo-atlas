# Trader Atlas 统一导航与筛选优化计划

> 状态：已实施并完成桌面回归
> 日期：2026-08-23
> 平台：Windows、macOS 桌面客户端
> 基线提交：`ef53ab1`

## 1. 问题结论

当前体验问题不是缺少若干筛选项，而是四种不同职责同时占据页面顶部：

1. “记录 / 统计 / 周期复盘”决定用户去哪里。
2. “当前实盘 / 历史阶段 / 模拟盘”决定数据来自哪里。
3. “进行中 / 星标 / 错过机会 / 待完善”决定看哪一类记录。
4. 快捷视图与筛选面板继续叠加 URL 条件。

这些控制被平铺成多层标签，并由不同规则解释。结果是用户需要记住哪些按钮会换页面、哪些按钮会替换范围、哪些按钮会继续叠加条件。历史阶段还拥有独立页面，使筛选、列表模式和详情返回更容易断裂。

本轮目标是把操作模型压缩为两句话：

- 左侧导航回答“我要做什么”。
- 顶部上下文栏回答“我要看哪些数据”。

## 2. 目标体验

### 2.1 高频路径

| 任务 | 目标路径 |
| --- | --- |
| 查看某个历史阶段的亏损日志 | 阶段选择器 → 历史阶段 → 亏损 |
| 重复查看常用组合 | 点击已保存视图 |
| 打开统计 | 左侧“统计分析”一次点击 |
| 打开本周复盘 | 左侧“周期复盘”一次点击 |
| 从统计返回同范围日志 | 点击指标或“查看记录”，保留阶段与盘型 |
| 筛选无结果 | 展示生效条件摘要，并可一键清除或调整 |

### 2.2 量化约束

- 从交易日志打开统计或周期复盘：1 次点击。
- 从当前阶段切到最近历史阶段：2 次点击以内。
- 常用历史阶段复合查询：首次最多 4 次点击，保存后 1 次点击。
- 任意可见筛选条件都必须可执行，不再出现活动状态的“未支持筛选条件”。
- 页面切换后保留阶段与盘型；日志专属条件只在日志中保留。

## 3. 新信息架构

### 3.1 一级导航

侧栏固定高频入口：

1. 交易日志
2. 统计分析
3. 周期复盘
4. 案例记录
5. 随机复盘

“统计分析”和“周期复盘”从交易日志内部标签提升为一级入口。交易日志不再承担页面级导航，只负责记录浏览、筛选和列表/看板切换。

### 3.2 记录交易入口

“记录交易”收进侧栏头像栏右侧，与搜索组成同一组头部图标动作：

- 使用 28px `+` 图标按钮，不再单独占据一行或形成额外视觉区块。
- 图标使用克制的品牌色，悬停与搜索共用同一轻量反馈。
- 通过 Tooltip 展示“记录交易”及快捷键，保留一键可达和键盘入口。
- 页面内容与当前导航始终拥有更高视觉优先级。

### 3.3 全局上下文

三个页面共享：

- `stageScope`：当前阶段、某个历史阶段、全部阶段。
- `tradeKindScope`：全部、实盘、模拟。

共享上下文显示在页面标题下方的一条工具栏中。页面切换时保留这两个值，避免每次重新选择范围。

### 3.4 页面私有状态

| 页面 | 私有状态 |
| --- | --- |
| 交易日志 | 状态、结果、品种、方向、策略、周期、标签、复盘标记、搜索、列表/看板 |
| 统计分析 | 统计时间窗、指标下钻、图表选择 |
| 周期复盘 | 周期、复盘记录 ID、编辑状态、完成状态 |

页面私有状态不自动污染其他页面。比如日志中的“亏损 + BTCUSDT”不会让统计页意外为空；只有阶段和盘型继续携带。

## 4. 统一筛选模型

### 4.1 筛选维度

```text
TradeQuery
├─ context
│  ├─ stageScope: current | stage:<id> | all
│  └─ tradeKindScope: all | live | paper
├─ record
│  ├─ lifecycle: planned | open | closed | missed
│  ├─ outcome: profit | loss | breakeven | unknown
│  ├─ flags: starred | missed | incomplete
│  ├─ symbol / side / timeframe / strategyId
│  ├─ session / tag / mistakeTag
│  └─ dateRange
└─ presentation
   ├─ mode: list | board
   ├─ grouping
   └─ sort
```

### 4.2 单一执行管线

快捷视图、筛选面板、保存视图、侧栏计数、空状态、统计下钻和详情返回必须使用同一套规范化与匹配函数：

```text
输入 URL / 保存视图 / 快捷操作
        ↓
parseTradeQuery
        ↓
normalizeTradeQuery
        ↓
selectTradesByQuery
        ↓
列表、计数、空状态、下钻
```

禁止页面组件自行拼接另一套过滤规则。

### 4.3 条件有效性合同

- 可选择条件必须能执行。
- 页面自有参数不作为业务筛选展示。
- 旧 URL 可映射时自动映射；不可映射时从活动查询中隔离，并在一次性迁移提示中说明。
- 不兼容选项在选择前禁用并解释原因。
- 筛选数量只统计真正生效的记录条件，不统计阶段、盘型、页面标签或显示模式。
- 清除筛选只清除记录条件，保留阶段、盘型和列表/看板模式。

## 5. 页面设计

### 5.1 交易日志

顶部只保留两层：

1. 标题栏：标题、保存状态、列表/看板、显示设置。
2. 上下文栏：阶段、盘型、搜索、筛选。

上下文栏下方放轻量快捷视图：全部、进行中、亏损、星标、错过机会、待完善、已保存视图。快捷视图本质是 `TradeQuery` 预设，选中后可继续编辑条件。

阶段选择器弹层按以下顺序展示：

- 当前阶段。
- 最近历史阶段。
- 全部阶段。
- 管理阶段。

每项展示日期范围与记录数量，用户不必先进入“历史实盘”页面判断阶段。

### 5.2 统计分析

- 左侧一键进入。
- 顶部继续显示阶段与盘型。
- 默认统计所选阶段的全部已结束记录。
- 指标下钻进入交易日志时生成明确的日志查询，例如“所选阶段 + 亏损”。
- 如果用户从日志进入统计，日志专属筛选保留在后台，返回日志时恢复，但不影响统计结果。

### 5.3 周期复盘

- 左侧一键进入，默认当前可复盘周期。
- 顶部提供上一周期、当前周期、下一周期和周期选择器。
- 阶段选择器负责阶段，周期选择器负责阶段内时间，不再要求先进入历史页面。
- 未完成状态在侧栏显示轻量计数，不通过额外中间页制造任务队列。

## 6. 空状态与恢复

交易日志空状态必须说明当前生效范围，例如：

```text
2026 第二阶段 · 实盘 · 亏损
没有符合条件的记录
[清除“亏损”] [查看该阶段全部记录]
```

不能再使用“当前工作区暂无交易”概括所有原因，也不能把查询冲突伪装成资料库为空。

## 7. URL 与状态策略

建议保留 URL 可恢复能力，但统一键名和所有权：

- 公共：`stage`、`kind`。
- 日志：`view`、`status`、`outcome`、`symbol`、`side`、`strategy`、`tag`、`q`。
- 统计：`range`、`metric`。
- 周复盘：`week`、`reviewId`。

迁移期继续解码 `scope`、`source`、`filter`、`liveStage`、旧独立路由和保存视图，写回时只生成新规范格式。

## 8. 实施阶段

### P0：查询合同与兼容层

- 新增 `TradeQuery`、解析、规范化、序列化和选择器。
- 将页面自有参数与业务筛选参数分离。
- 建立旧 URL、保存视图和历史阶段路由兼容矩阵。
- 修复“未支持筛选条件”进入活动筛选的问题。

验收：所有可见条件都能过滤；列表、计数、空状态和详情返回集合一致。

### P1：交易日志工作区

- 合并当前与历史阶段列表入口。
- 新增阶段选择器与统一上下文栏。
- 快捷视图全部改用 `TradeQuery` 预设。
- 清除条件保留阶段、盘型和布局。

验收：当前、指定历史、全部阶段都使用相同列表和筛选器。

### P2：统计与周期复盘一级入口

- 提升侧栏入口，删除交易日志内部页面级标签。
- 建立公共上下文状态与页面私有状态隔离。
- 统计下钻和复盘历史跳转使用规范查询。

验收：侧栏一次点击可达；公共范围连续，私有条件不串页。

### P3：保存视图与迁移

- 保存完整 `TradeQuery`，同时保存兼容版本号。
- 迁移旧保存视图、侧栏固定项和工作区记忆。
- 无法等价迁移的旧条件进入一次性修复清单，不再显示为活动 chip。

验收：常用历史复合查询保存后一次点击恢复，导入导出与备份保持一致。

### P4：桌面回归与发布

- 覆盖 960×640、1280×900、1440×900、1920×1080。
- 验证 Windows 与 macOS 键盘、焦点、弹层碰撞和详情返回。
- 重新构建客户端并用真实资料库手测升级路径。

## 9. 自动化测试重点

- 查询解析、规范化、序列化可往返。
- 每个可见筛选条件都有真假两侧样本。
- 多维条件维度间 AND、同维多选 OR。
- 当前、单个历史、全部阶段的归属严格按 stage ID。
- 快捷视图、保存视图、侧栏计数和列表共享结果。
- 清除筛选不清除公共上下文。
- 日志、统计、周期复盘切换时只传递公共上下文。
- 旧 URL 与旧保存视图安全迁移，不产生“未支持条件”chip。
- 空状态区分资料库为空、范围为空、筛选为空和数据异常。

## 10. 本轮非目标

- 不重写交易实体、阶段实体、统计公式或周复盘数据模型。
- 不改变 Windows 与 macOS 之外的平台范围。
- 不新增新的颜色、字号、间距、圆角或阴影体系。
- 不在原型确认前直接改造生产页面。

## 11. 实施结果

- 侧栏已固定为“交易日志、统计分析、周期复盘、案例记录、随机复盘”五个一级入口。
- “记录交易”已并入侧栏头部操作组，以 28px `+` 图标按钮与搜索并列，并保留快捷键提示。
- 主工作区已支持直接拖动排序，顺序写入显示偏好并随资料库快照保留。
- 交易日志、统计分析和周期复盘已共享阶段与盘型上下文；切换页面只携带公共范围，不串入日志私有条件。
- 当前阶段、指定历史阶段和全部历史已统一进入同一交易日志与筛选管线，不再要求进入独立历史页面后重新筛选。
- 旧 `scope`、`source`、`filter`、`tradeKind` 等 URL 参数已接入兼容转换，未知条件不会再显示为活动筛选。
- 统计分析已支持所选阶段及实盘、模拟盘、全部盘型，并可带着相同范围下钻回交易日志。
- 周期复盘已提升为一级入口，并能按所选阶段读取复盘记录与趋势。
- 已新增统一查询单元测试、上下文栏浏览器测试，并更新侧栏、统计、周期复盘和回归合同。
