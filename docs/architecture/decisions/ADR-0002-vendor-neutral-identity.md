# ADR-0002：供应商中立的软件身份

- 状态：已批准方向，待实施
- 日期：2026-07-26

## 背景

Trader Atlas 是独立软件。当前仓库仍包含第三方产品来源的图标资产、生成工具、源码前缀、持久化键名、导出文件名、环境变量和测试断言。这些内容会让产品身份、代码所有权边界和后续维护产生歧义。

本决策的目标是让项目自有目录、运行时代码、用户可见内容和工程工具全部使用 Trader Atlas 自身语义，同时安全承接旧版本已经写入的用户数据。

## 决策

### 1. 图标体系

- 删除整套第三方产品来源的原始图标归档、抓取数据、生成器、图库和专用 QA 脚本。
- 通用界面图标统一从现有 `lucide-react` 依赖导出，并继续通过 `src/icons/appIcons.tsx` 作为业务层唯一入口。
- 进度、交易状态和加载动画等产品特有图标使用少量本地 Atlas 组件实现；组件名称、CSS 类名和类型均使用业务语义，不再使用第三方产品前缀。
- 不通过机械改名前缀来保留第三方图标集合。

### 2. 产品标识

- 新的浏览器数据库、广播频道、锁名、导出文件名、Electron 数据目录和环境变量统一使用 `trader-atlas` 或 `TRADER_ATLAS`。
- 用户界面、注释、测试名称、错误信息、脚本名称和工作流命令不得将第三方产品作为视觉或交互基准。
- CSS 标准关键字（例如线性渐变和线性计时）以及算法复杂度描述属于通用技术语义，不视为品牌引用。

### 3. 旧数据兼容

- 旧浏览器数据库、本地存储和桌面目录必须先迁移成功，再切换到新标识；失败时保留旧数据并给出可恢复错误，不覆盖或删除原数据。
- 旧标识只允许存在于一个边界明确的兼容模块及其测试夹具中，不得传播到业务代码、界面、导出文件或新建数据。
- 兼容模块在启动阶段执行，迁移应幂等：重复启动不会重复复制、覆盖较新的新库或删除旧库。
- 本次不自动删除旧数据。确认新版本稳定后，可通过单独的数据清理版本移除兼容层。

### 4. 工作区目录

- 仓库内部改造和验证全部完成后，将根目录从旧名称改为 `D:\Trader-Atlas`。
- 重命名前确认没有开发服务器或构建进程占用目录；重命名后运行 `git worktree repair`，检查主工作树及已有辅助 worktree 的指针。
- 根目录迁移是最后一步，避免在改造过程中令当前工具会话和相对路径失效。

## 实施边界

本次仅处理软件身份、图标来源及其必要的数据兼容。不改动交易业务规则、视觉布局、数据库结构版本或发布功能。

正式迁移和发布文档保留；早期方案、演示、截图和已完成的临时审计不恢复。

## 错误处理

- 数据迁移先读后写，写入完成后重新读取校验；任一步失败都继续保留旧数据。
- 图标替换缺少等价图形时，优先使用语义最接近的 Lucide 图标，不新增完整图标框架。
- 根目录重命名或 worktree 修复失败时停止，不删除任何仓库或 worktree 元数据。

## 验证标准

1. 项目自有路径不再包含第三方产品名称。
2. 除单一旧数据兼容模块、其测试夹具和通用技术关键字外，项目文本不再包含第三方产品名称。
3. 新建数据库、导出文件、进程环境变量和 Electron 数据目录全部使用 Trader Atlas 标识。
4. 旧版本数据迁移测试覆盖成功、重复执行、目标已有较新数据和迁移失败四种情况。
5. `pnpm typecheck`、`pnpm test`、`pnpm build` 和图标/发布相关契约全部通过。
6. 最终仓库位于 `D:\Trader-Atlas`，`git status` 与 worktree 指针可正常读取。

## 不采用的方案

- 仅将第三方前缀批量替换为 Atlas：仍保留来源不独立的资产，只是隐藏来源。
- 直接删除旧持久化标识：可能让已有交易记录在升级后看似丢失。
- 在实现前先重命名根目录：会放大工具会话和 worktree 指针失效的风险。
