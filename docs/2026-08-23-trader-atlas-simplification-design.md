# Trader Atlas 化繁为简设计

## 背景

Trader Atlas 已从交易日志扩展出今日工作台、随记、交易日志、案例记录、周复盘、随机复盘、仪表盘、历史实盘、模拟盘、错过机会和完整风控等多套入口。底层能力已较完整，但一级概念、页面入口与状态维度不断叠加，使日常使用从“随时记录、盘后复盘”逐渐变成“处理任务和理解系统”。

本次设计在现有 React、Zustand、Electron 与本地资料库存储架构上收敛产品表面，不进行框架替换或数据体系重写。适配范围仅为 Windows 与 macOS 桌面客户端，不考虑浏览器、手机、iPad 或其他平台。

## 产品目标

Trader Atlas 的核心使用节奏为：

1. 随时低摩擦记录一笔交易或机会。
2. 盘后或周末补充交易事实、结果与复盘思考。
3. 将值得长期保留的内容单独沉淀为案例记录。
4. 从案例和已结束日志中快速进入指定范围的随机复盘。
5. 让风险持续可见并及时提醒，但不替用户作交易决定。

产品成功的首要标准不是提高每日任务完成率，而是减少首次记录所需的操作和判断。今日待办、复盘进度和风控确认不能成为持续心理负担。

## 设计原则

- **先捕捉，后整理**：首次记录只收集足以找回上下文的信息。
- **日志与案例独立**：日志记录交易事实，案例保存用户主动筛选的经典内容。
- **能力收纳而非删除**：统计、周复盘、历史实盘和各类筛选继续存在，但不再与核心能力平级。
- **默认直接可用**：随机复盘点击即开始，高级条件和自定义配置按需出现。
- **提醒大于干涉**：风控可以强化提醒和保留审计，不以业务规则硬性阻止用户决策。
- **兼容现有资料库**：不改变已有交易、案例、实盘阶段和风险历史的含义。

## 现有基础与设计系统

本次改版是对现有产品表面的收敛，不是从零重做。实现前必须先复用以下已经落地的能力：

- 应用默认路由已经进入 `/list`。
- 新建账户交易默认使用 `planned`，不进入已平仓绩效，也不会在创建时触发开仓风控。
- 交易正文与本次新增图片已经支持同批原子提交。
- 案例已经使用 `TradeKind = case`，并保留 `sourceTradeId` 追溯来源。
- 随机复盘已经使用稳定 ID 队列；记录失效时可以安全移出队列。
- 快照可选字段升级、资料库迁移、导入导出、备份和恢复已有成熟路径。
- 现有旧路由已有一部分兼容重定向，不重新建立第二套路由兼容层。

项目已有设计 Token，规范来源为 `src/styles/tokens.css` 与 `src/styles/global.css`。本次界面调整必须继续消费现有语义 Token，不得在页面内建立平行色板、字号、间距、圆角或阴影体系：

- 表面层级使用 `--surface-app`、`--surface-pane`、`--surface-inset`、`--surface-floating`。
- 文字角色使用 `--text-strong`、`--text-body`、`--text-muted`、`--text-faint`，数字使用 `--numeric-tabular`。
- 页面宽度使用 `--page-rail-wide`、`--page-rail-standard`、`--page-rail-reading`、`--page-rail-form`。
- 间距使用 `--sp-*` 与 `--space-*`；控件高度、图标和动效使用已有语义 Token。
- 盈亏、风险、等待与机会状态使用 `--pos`、`--neg`、`--warn`、`--pending`、`--opportunity`。
- 键盘焦点、减少动效和桌面字体回退继续遵循全局规则。

优先复用现有 `AppFrame`、`Button`、`IconButton`、`Chip`、`InlineStatus`、`ModalShell`、`SegmentedControl` 与 `Select`。只有现有组件无法表达稳定交互语义时才新增组件，并同步补齐组件级样式与键盘测试。

## 信息架构与首页

### 核心导航

侧栏收敛为三个核心内容入口和一个全局操作：

- 全局主操作：快速记录。
- 交易日志。
- 案例记录。
- 随机复盘。

应用启动后进入交易日志。快速记录在侧栏顶部使用最高视觉优先级，并提供全局快捷键；应用启动时不自动弹出表单，避免打断查阅旧内容。

侧栏底部显示轻量风险状态以及设置入口。随记保留为次级入口，并继续支持搜索和快捷键，但不占核心导航位置。

侧栏结构固定为：

```text
快速记录
交易日志
案例记录
随机复盘

更多
  随记
  用户保留的保存视图与策略入口

风险摘要
设置
```

全局“快速记录”在任何页面都默认创建当前实盘阶段的 `live` 交易，不再根据当前页面隐式切换为随记、案例或模拟交易。用户只有在“更多信息”中显式选择模拟盘时，才创建 `paper`。随记与案例的新建操作保留在各自页面工具栏及原有快捷键中，避免同一按钮在不同页面改变业务含义。

### 现有能力的收纳

| 现有能力 | 调整后位置 |
| --- | --- |
| 今日工作台 | 不再作为一级入口；“待完善”变为交易日志内的可选筛选 |
| 仪表盘 | 交易日志的“统计”标签 |
| 周复盘 | 交易日志的“周期复盘”标签 |
| 历史实盘 | 交易日志的数据范围切换 |
| 模拟盘 | 交易日志筛选条件 |
| 进行中、星标、错过机会 | 交易日志快捷筛选 |
| 策略与保存视图 | 交易日志内的策略筛选与保存视图 |
| 随记 | 次级入口、搜索和快捷键 |
| 风控详情 | 设置中的风险管理页面 |

### 交易日志承载层

交易日志不是把原侧栏入口原样搬成一排标签。页面只保留三个稳定的一级标签：

```text
交易日志
├─ 记录
├─ 统计
└─ 周期复盘
```

- “记录”承载列表或看板，以及当前实盘、历史阶段、模拟盘、进行中、星标、错过机会、待完善、策略和保存视图等范围与筛选。
- “统计”内嵌现有仪表盘，不重复建立第二套统计计算。
- “周期复盘”内嵌现有周复盘与历史记录。
- 当前实盘、历史阶段和模拟盘属于数据范围，不作为与“记录、统计、周期复盘”同级的标签。
- 列表与看板继续作为同一范围下的视图切换；旧 `/board` 链接映射到“记录 + 看板”。
- 默认进入“记录 + 当前实盘 + 列表”，首次进入不得同时展开高级筛选。

“待完善”统一表示当前范围内需要补充结果或复盘正文的记录。计数必须由一个共享选择器生成，侧栏、筛选项和结果列表不得各自计算。

“待完善”只使用中性状态和计数，例如“待完善 6”，不得使用红色告警、强制弹窗或首页任务队列。用户主动进入该筛选后，才显示需要补充结果或复盘的记录。

### 路由兼容

现有路由在收敛阶段继续保留。被收纳的页面通过重定向进入交易日志对应标签、范围或视图，旧收藏链接和内部跳转不得直接失效。旧路由只承担参数翻译，不长期并行维护两套完整页面壳。待新导航稳定后，才能在单独设计中评估是否清理遗留路由。

至少固定以下映射：

| 旧入口 | 新位置 |
| --- | --- |
| `/today-record` | `/list?incomplete=1` |
| `/dashboard` | 交易日志“统计” |
| `/weekly-review` | 交易日志“周期复盘” |
| `/live-history` | 交易日志“记录 + 历史阶段” |
| `/sim` | 交易日志“记录 + 模拟盘” |
| `/active`、`/favorites`、`/missed` | 交易日志“记录”中的对应快捷范围 |

具体 URL 参数名在实现计划中统一定义；同一语义不得同时存在两种规范参数。

旧 `sidebarWorkspaceItems` 中的 `system:active`、`system:missed`、`system:paper`、`system:favorites` 与 `case-view:*` 不再作为新侧栏项目渲染，也不得重新挤占核心导航。升级时继续保留并安全解码这些配置，使旧资料库、旧 URL 和保存视图仍能落到交易日志或案例记录的对应范围；导入导出不得因它们不再显示而丢弃未知数据。用户在新导航中重新保存布局时，只写入新合同支持的导航与复盘池配置，不继续生成上述旧侧栏钉选。

## 快速记录

### 默认精简表单

快速记录复用现有 `TradeComposer`，默认进入精简模式，只展示：

- 品种：必填并自动聚焦。
- 方向：做多或做空。
- 截图或一句话：二者至少存在一个。
- 策略：可选。

表单提供“保存记录”和“更多信息”。展开更多信息后继续使用现有完整字段，包括实盘或模拟、状态、入场价、仓位、止损和时间。精简模式与完整模式写入同一个 `Trade` 数据结构，不建立第二套草稿实体。

波段级别、交易时段、交易日期、价格、仓位和止损默认收进“更多信息”。新建时焦点直接落到品种控件，不使用“弹窗内第一个可聚焦控件”作为隐式规则。

截图或一句话使用“至少一项”的轻量校验：用户输入品种和方向后，如果两者都为空，保存按钮保持可用，但点击时在内容区给出一次就地提示，不清空已经填写的字段。这里的目标是保证记录仍有可找回的上下文，而不是建立新的完整度任务。

### 默认状态与统计边界

快速保存的记录使用当前实盘阶段中的 `planned` 状态：

- 不进入已平仓盈亏统计。
- 不触发开仓风险判断。
- 后续可以改为持仓中、盈利、亏损、保本、模拟盘或错过机会。
- 只有用户明确将记录变为持仓中或执行确认开仓时，才计算并展示风险状态。

保存成功后只提示“已记录”，不要求立即完善。保存失败或截图仍在写入时，不得出现正文成功、附件失败的半成功记录。

新建成功后关闭弹窗并停留在原页面，不自动跳转详情。编辑已有记录成功后仍停留在当前详情或列表上下文，并恢复触发按钮焦点。成功提示提供短暂的“打开记录”次级操作，但不得抢占键盘焦点。

### `planned` 与实盘阶段合同

快速记录创建的实盘记录归属创建当时的当前实盘阶段。`planned` 表示该阶段内已经捕捉、但尚未确认执行结果的事实，不等同于必须完成的待办。

- `planned` 不再阻止实盘阶段切换。
- 阶段切换后，`planned` 保留在原阶段，不自动搬到新阶段。
- 原阶段中的 `planned` 仍可补充为盈利、亏损、保本、错过机会或保持计划中。
- 原阶段中的 `planned` 不得转为新阶段持仓，也不提供跨阶段复制或迁移入口；用户如果仍想在当前阶段执行，应重新创建一条当前阶段记录。
- `open` 继续阻止阶段切换，本次不设计跨阶段持仓。
- 上一周周复盘未完成不再阻止阶段切换；周复盘继续归属原阶段，并允许稍后补做。
- 阶段切换界面可以展示未完成记录和未完成周复盘的中性摘要，但不得把它们作为硬门闩。

上述规则必须同时应用于前端检查、Electron 耐久提交、恢复逻辑和阶段切换测试，不能只改变提示文案。

### 交易详情

交易详情第一屏优先展示截图和复盘正文。交易属性、价格、时间、标签和活动历史降低视觉层级，放入右侧属性区或折叠区。用户可以在盘后补充结果、策略、复盘思考和错误标签。

详情页保留“一键加入案例记录”。该操作不要求填写收藏理由或立即选择案例分类。

## 交易日志与案例记录

### 两个独立体系

交易日志保存真实发生、模拟或观察到的交易事实、执行过程、结果与盘后复盘。案例记录是用户主动整理的个人经典案例库，包括标准范例、常犯错误、高权重形态、模糊决策和错过机会。

案例记录不是实盘日志的筛选视图，普通日志不会因为星标、盈利或完成复盘而自动成为案例。

案例与来源交易之间采用“可追溯、不同步”的关系：

- `sourceTradeId` 只用于打开来源和显示来源是否可用。
- 创建案例时冻结来源正文与图片快照。
- 来源交易之后的修改不得自动覆盖案例快照。
- 案例自己的正文、分类、标签和掌握状态不得回写来源交易。
- 来源被删除或彻底清理后，案例和已经引用的图片仍必须可读；资产回收以全资料库引用关系为准。

### 案例创建

案例支持两种创建方式：

1. 在案例记录页面单独新建。
2. 从交易日志一键复制为案例。

从日志生成案例时复制当时的截图、复盘正文、策略、品种、方向和结果，并保留来源记录标识用于追溯。实现上保留冻结的 `sourceNoteHtml` 作为来源快照，`note` 作为案例独立正文；停止现有来源正文级联更新。界面可以分别显示“来源快照”和“案例洞见”，不得把两者无提示地拼成一个可覆盖字段。

历史案例升级时不执行破坏性正文合并：保留既有 `sourceNoteHtml` 与 `note`，停止后续级联即可。若历史案例缺少来源快照但来源仍存在，可在迁移时补写一次；无法补写时保持案例正文并标记“来源快照不可用”。

迁移完成后，详情页只能读取案例自身的 `sourceNoteHtml`。必须移除运行时 `sourceNoteHtml ?? sourceTrade?.note` 回退，否则来源交易后续变化仍会间接改变案例展示。来源快照缺失时显示明确缺失状态，不临时读取来源最新正文冒充历史快照。

案例分类与错误标签均为可选信息，可以盘后补充。案例进入案例记录本身已代表“值得长期保留”，不再要求补充“为什么值得记录”。

### 案例查阅

案例页面提供以下快捷范围：

- 全部案例。
- 标准案例。
- 错误案例。
- 模糊决策。
- 错过机会。
- 策略、品种、方向、盈亏结果、标签和错误标签。

策略、品种、方向和结果在从日志复制时自动继承，减少重复填写。

现有 `focus`、`unreviewed`、`reviewed` 案例范围不再占用默认快捷入口，但继续作为高级筛选与旧链接兼容值：

- `focus` 在高级筛选中显示为“重点”。
- `unreviewed` 与 `reviewed` 在启用掌握评估后显示为“待复看”和“已掌握”。
- 旧 URL、保存视图和侧栏钉选继续解码到对应高级筛选，不重定向成错误的新分类。
- 新默认范围“标准、错误、模糊决策、错过机会”使用规范 `caseType`，不得复用掌握状态或星标进行推断。

## 随机复盘

### 默认候选池

随机复盘默认包含：

- 全部未删除的案例记录。
- 已结束且未删除的实盘日志。
- 已结束且未删除的模拟盘日志。
- 未删除的错过机会。

默认排除计划中、持仓中和已删除记录。日志即使尚未填写完整复盘也可以进入候选池，用户可以在被抽到时补充内容。

### 点击即开始

随机复盘首页不再默认展示完整筛选表单。进入后显示候选数量和快速复盘池，点击任一复盘池直接开始并固定本轮快照。

系统提供以下内置预置：

- 全部内容。
- 只看案例。
- 亏损日志。
- 盈利日志。
- 错过机会。
- 近期多看。

按钮显示实时候选数量，例如“亏损日志 · 42”。“全部内容”始终保留；其他系统预置允许隐藏和排序。候选数量、按钮可用状态和实际开始的会话必须来自同一次候选池计算。点击复盘池后立即冻结本轮 ID 与顺序，不在开始和首条展示之间重新抽取。

### 自定义复盘池

用户可以创建自定义复盘池，组合以下条件：

- 来源：案例、实盘日志、模拟日志。
- 结果：盈利、亏损、保本、错过。
- 案例类型。
- 策略。
- 品种。
- 方向。
- 标签与错误标签。
- 是否要求存在有效截图或正文。

自定义复盘池保存名称与筛选条件。系统池和自定义池是否出现在首页以及首页顺序统一由独立布局配置管理。随机复盘首页最多显示六个复盘池，其余收进“更多复盘池”，避免自定义入口再次膨胀。

### 复盘池数据合同

系统预置使用稳定 ID，不作为用户自定义记录重复保存：

| ID | 名称 | 规范范围 |
| --- | --- | --- |
| `all` | 全部内容 | 案例、已结束实盘、已结束模拟、错过机会 |
| `cases` | 只看案例 | 全部未删除案例 |
| `losses` | 亏损日志 | 已结束且结果为亏损的实盘与模拟日志 |
| `wins` | 盈利日志 | 已结束且结果为盈利的实盘与模拟日志 |
| `missed` | 错过机会 | 日志与案例中的错过机会 |
| `boosted` | 近期多看 | 用户显式加入近期多看的有效记录 |

`ReviewPoolPreset` 只表示用户保存的自定义复盘池，至少包含：

```ts
interface ReviewPoolPreset {
  id: string
  name: string
  filters: ReviewPoolFilters
  createdAt: string
  updatedAt: string
}

type ReviewPoolSource = 'case' | 'live' | 'paper'
type ReviewPoolResult = 'win' | 'loss' | 'breakeven' | 'missed'

interface ReviewPoolFilters {
  sources: ReviewPoolSource[]
  results: ReviewPoolResult[]
  caseTypes: Array<'exemplar' | 'mistake' | 'ambiguous' | 'missed'>
  strategyIds: string[]
  symbols: string[]
  sides: Array<'long' | 'short'>
  tags: string[]
  mistakeTags: string[]
  requireContent: boolean
  stageSource?: ReviewStageSource
}

type SystemReviewPoolId = 'all' | 'cases' | 'losses' | 'wins' | 'missed' | 'boosted'

interface ReviewPoolRef {
  kind: 'system' | 'custom'
  id: string
}

interface ReviewPoolLayout {
  homeOrder: ReviewPoolRef[]
  hiddenSystemIds: Exclude<SystemReviewPoolId, 'all'>[]
}
```

`ReviewPoolFilters` 必须使用稳定业务值保存，不能保存策略名称、页面 URL 或本地化展示文案。策略使用稳定 ID；品种、普通标签和错误标签在当前数据模型中本来就是规范字符串，分别保存到 `symbols`、`tags` 与 `mistakeTags`，不得虚构 `tagId`。

- 所有数组字段的空数组统一表示“不限制该维度”，不得解释为“无匹配”。布尔字段 `requireContent` 为 `false` 时不限制正文或截图。
- 非空维度总体按 AND 组合；同一数组内的多个值按 OR 匹配。例如 `sources: ['live', 'paper']` 与 `results: ['loss']` 表示来源为实盘或模拟盘，并且结果为亏损。
- `results` 对案例、实盘和模拟盘都按规范 `status` 判断。由交易提炼的案例保留来源状态；直接创建且没有终态结果的案例不会命中结果筛选。这里“已结束”只指 `win`、`loss`、`breakeven`，`missed` 是独立的错过状态。
- `caseTypes` 非空时，候选必须是案例并匹配对应 `caseType`；不得对实盘或模拟盘忽略该条件后意外放宽候选池。
- `stageSource` 缺失时按“当前与全部历史阶段”处理，并继续复用现有 `ReviewStageSource` 解码与规范化规则。
- 策略被删除后保留对应 `strategyId` 并将条件标记为失效，用户可以编辑或移除；不得静默扩大候选池。
- 品种从目录移除、标签从预设移除不代表历史值失效；只要记录中仍有该字符串，条件继续匹配。
- `homeOrder` 同时决定系统池与自定义池在首页的混合顺序，最多规范化为六项；不在首页的自定义池进入“更多复盘池”。缺失布局时默认顺序为 `all`、`cases`、`losses`、`wins`、`missed`、`boosted`。
- 布局规范化顺序固定为：移除未知、重复与已删除引用；移除 `hiddenSystemIds` 命中的系统池；将 `all` 补回并移动到第一项；最后截断为六项。`all` 永远保留在首页且不可隐藏。
- `hiddenSystemIds` 只保存允许隐藏的系统池，不复制系统池名称与筛选定义。

系统预置由代码内置的专用候选构造器生成，不要求伪装成 `ReviewPoolFilters`，也不保存进 `reviewPoolPresets`。其中至少固定以下可执行语义：

- `all`：全部满足通用候选资格的案例，以及 `status` 为 `win`、`loss`、`breakeven` 或 `missed` 的实盘和模拟盘。
- `missed`：满足通用候选资格，并且 `status === 'missed'` 或 `caseType === 'missed'`。
- `boosted`：满足通用候选资格，并且记录 ID 存在于 `subscribedIds`；它使用专用查询，不为自定义筛选新增 `subscribedOnly` 字段。

“近期多看”在本次设计中采用持续标记语义：用户加入后一直保持较高抽取优先级，直到主动取消，不做隐式时间衰减。优先复用已有、已经进入快照与导入导出的 `subscribedIds`，在迁移和界面中将旧“置顶关注”解释为“近期多看”。如果后续需要时间衰减，应另行设计带 `markedAt` 的权重记录，不在本次实现中猜测算法。

“近期多看”只调整已经满足候选条件的记录权重，不放宽候选资格：

- `planned`、`open` 与软删除记录即使仍存在于 `subscribedIds`，也不进入“近期多看”或其他复盘池。
- 记录进入已结束或错过状态后，只要仍被标记，就自动成为“近期多看”的合格候选。
- 移入回收站时保留标记，恢复后按当前状态重新获得资格。
- 彻底清理记录时同步移除 `subscribedIds` 引用。

持久与临时状态边界如下：

- 自定义复盘池、首页顺序、系统池隐藏状态和“近期多看”进入资料库规范快照。
- 本轮随机 ID、顺序、游标、临时评估与返回位置继续按 `libraryId` 保存在 `sessionStorage`，不进入备份和导出。
- 旧 `review-session:v1/v2/v3` 会话继续可恢复或安全放弃。
- 旧复盘会话保存的是过滤快照而不是预设 ID，恢复时继续按旧 `includeCases`、`includeLiveTrades`、`includePaperTrades`、`caseScope`、`reviewTiming` 与 `stageSource` 语义解码。`due` 保留为高级设置中的 `reviewTiming: 'due'`；`exemplar`、`mistakes`、`missed` 通过旧过滤组合恢复，不虚构不存在的预设 ID 迁移。无法等价转换的过滤只用于恢复旧会话，不继续写入新的长期偏好。
- 不把进行中的会话写入规范快照，避免翻页造成整库写入、备份噪声和多窗口冲突。

### 复盘会话

复盘会话以截图和正文为主体，明确标注来源为“案例”或“交易日志”。主要操作收敛为：

- 下一条。
- 近期多看。
- 打开完整记录。

“近期多看”提高该内容在后续近期复盘中的出现优先级。现有到期时间、掌握状态和阶段来源继续用于兼容历史数据与高级设置，但默认会话不要求用户逐条完成“陌生、待复看、已掌握”的评估。

默认会话中的“下一条”和“近期多看”不修改 `masteryState` 或 `nextReviewAt`。用户从高级设置启用掌握评估后，才继续使用现有间隔复看规则并写入这些字段。旧字段不是废弃数据，也不得在迁移时批量清空。

本轮开始后保存稳定 ID 快照。资料库变化不得中途插入新记录或打乱顺序；被删除或失效的记录在前进时安全跳过。

## 风控

### 产品原则

风控负责让风险可见、及时提醒并留下事实记录，不替用户决定是否交易。业务风险判断不得成为不可绕过的开仓阻塞。

### 展示层级

| 风险状态 | 保存 `planned` | 转为持仓 | 用户交互 | 审计 |
| --- | --- | --- | --- | --- |
| 正常 | 允许 | 允许 | 侧栏安静显示最关键剩余额度 | 使用当前政策版本 |
| 接近限额 | 允许 | 允许 | 增强颜色与文案，不弹窗 | 使用当前政策版本 |
| 已触及限额 | 允许 | 允许 | 首次转为持仓时确认一次；原因可选 | 保存当时的额度快照和确认结果 |
| 风险未建档 | 允许 | 允许 | 本次转为持仓前明确提示无法计算，并确认一次 | 保存政策为空与确认结果 |
| 风险数据不完整或计算未知 | 允许 | 允许 | 本次转为持仓前显示未知原因，并确认一次 | 保存未知原因与确认结果 |
| 数据损坏、持久化失败 | 阻止 | 阻止 | 显示技术错误和恢复入口 | 不产生半提交审计记录 |

风险状态只在用户明确把实盘记录转为持仓时进入确认流程。“首次转为持仓”按记录粒度定义为：该记录在其所属实盘阶段内第一次从非 `open` 状态进入 `open`；不得按应用会话、业务日或整个阶段只确认一次。快速创建 `planned`、补充正文、上传截图、修改分类和记录错过机会不得触发开仓门闩。

完整的日、周、月额度和历史记录继续放在风险管理页面。超限后的继续开仓原因改为可选，不作为继续操作的前置条件；系统自动保存当时的风险状态和确认结果，供盘后复盘。为兼容现有 `RiskOverrideEvent.reason: string`，用户未填写时规范保存空字符串，审计界面统一显示“未填写理由”，不得将空值误写成系统推断原因，也不新增同义的 `confirmedReason` 字段。

本次简化只放宽业务风险判断，不删除交易状态机自身的硬门禁。目标记录不属于当前阶段、已有待处理开仓提交、目标丢失、目标已不再满足转持仓条件等 `not-current-stage`、`pending-exists`、`target-missing` 与 `target-no-longer-eligible` 情况继续阻止提交；技术损坏和耐久写入失败同样继续硬阻止。

### 规则生效周期

每周不再强制重新确认相同规则：

- 风险规则确认后持续生效。
- 用户主动修改时生成新版本。
- 新实盘阶段开始时重新确认一次风险基准。
- 月度限额、规则版本、超限确认和历史审计继续保留。

`weeklyRiskPreparations` 作为历史兼容与审计数据继续读取、导入、导出和验证，但新流程不再要求每周生成一条记录。已有记录不得删除；新的风险政策只在用户主动修改规则或新实盘阶段确认风险基准时生成版本。周复盘完成状态与风险政策是否生效相互独立。

### 新实盘阶段风险基准

新阶段不显示启动向导，也不在进入应用时强制弹窗。第一次把该阶段记录转为持仓时，复用现有风险确认弹窗并按以下顺序处理：

1. 如果上一阶段存在可用政策，弹窗预填上一阶段资金基准、单笔风险、日周月限额和纪律文本。
2. 用户确认沿用或修改后，原子创建归属新阶段的 `RiskPolicyVersion` 与当前月 `MonthlyRiskLimit`；该首次基准从当前业务日立即生效，不套用旧“有当日已平仓交易则次日生效”的周准备规则，也不创建新的 `weeklyRiskPreparations`。
3. 风险基准耐久写入成功后，重新计算本次开仓风险。只有重算结果为正常或接近限额时才直接继续；若仍为 `triggered` 或 `unknown`，必须留在同一确认弹窗展示重算后的事实，等待用户再次确认，不得因刚完成配置而自动开仓。
4. 任一步耐久写入失败都保持交易为原状态，不留下只有政策、只有审计或只有开仓的半提交。

如果没有任何可复用政策，弹窗明确显示“当前无风险基准”，提供“设置风险基准”和“仍然继续本次开仓”两项。用户选择继续时只记录本次未知风险确认，不伪造政策；在真正建立政策前，每次新的转持仓动作仍按未知状态确认。该行为保证用户拥有最终决定权，同时不把一次确认伪装成已经完成风险配置。

## 桌面交互状态与无障碍

本设计只面向 Windows 与 macOS 桌面窗口。常规窗口使用现有页面 rail 与侧栏宽度 Token；窄窗口优先压缩次级上下文、折叠高级筛选，不把桌面导航替换为移动端汉堡菜单。窗口小到无法安全展示主工作区时，使用现有最小窗口尺寸约束，不新增手机或平板布局。

| 功能 | 加载 | 空状态 | 错误 | 成功 | 部分或降级 |
| --- | --- | --- | --- | --- | --- |
| 快速记录 | 保存按钮显示“保存中”，禁止重复提交 | 不适用 | 就地保留字段并说明未写入 | 关闭弹窗、原地提示“已记录” | 图片仍处理时保持保存中，不提交正文 |
| 交易日志 | 使用现有延迟加载指示，不闪烁整页骨架 | 说明当前范围没有记录，并提供“快速记录” | 保留导航壳，显示重试入口 | 展示记录及当前范围 | 失效筛选条件可见且可移除 |
| 案例记录 | 与交易日志一致 | 说明案例由用户主动沉淀，并提供新建与从日志提炼入口 | 保留已有可读案例 | 展示案例与来源状态 | 来源不可用时仍展示冻结快照 |
| 复盘池 | 候选计数计算中禁用开始 | 说明当前条件没有候选，并提供“恢复全部内容” | 不显示伪造数量，提供重试 | 点击后固定本轮顺序 | 失效条件标记出来，不静默放宽 |
| 复盘会话 | 当前内容或图片准备中显示局部状态 | 本轮记录全部失效时返回复盘池 | 保留当前游标并允许重试或跳过 | 下一条保持焦点位置稳定 | 图片缺失时正文仍可读并标记缺失 |
| 风险状态 | 计算中显示“风险计算中” | 未建档按未知处理 | 技术错误阻止提交并进入恢复 | 正常或确认后继续 | 数据不完整显示具体未知原因 |

键盘与焦点合同：

- 快速记录使用全局快捷键打开，初始焦点固定为品种；`Escape` 只在没有提交进行时关闭。
- 弹窗关闭后焦点恢复到触发控件；从全局快捷键打开时恢复到打开前的活动元素。
- 交易日志标签、数据范围、列表/看板切换和复盘池均支持标准键盘导航，不建立只靠右键或悬停才能发现的主路径。
- 状态变化使用 `aria-live` 的短消息；错误与确认弹窗使用现有 `ModalShell` 焦点陷阱。
- 颜色只表达增强语义，触线、未知、盈利和亏损同时提供文本或图标标签。
- 所有新增动效遵循 `prefers-reduced-motion`，不得绕过全局降级规则。

## 技术设计

### 保留的架构

- React 页面和组件体系。
- Zustand 全局状态。
- Electron 主进程与预加载边界。
- SQLite/快照、图片资产、备份与导入导出机制。
- `TradeKind = live | paper | case` 和现有实盘阶段归属。

本次不重写主 Store。新增业务计算放入独立模块和选择器，页面只消费稳定接口，避免继续扩大 `useStore.ts`。现有大型页面只在相关改动触达时做针对性拆分，不开展无关重构。

### 新增持久化状态

规范快照新增可选字段 `reviewPoolPresets?: ReviewPoolPreset[]` 与 `reviewPoolLayout?: ReviewPoolLayout`。系统预置由代码生成；快照只保存用户自定义池以及首页混合顺序和系统池隐藏状态，避免默认筛选定义在每个资料库中重复固化。

`subscribedIds` 保留现有持久化字段和导入合并规则，但产品语义调整为“近期多看”。读取旧资料库时不需要迁移数据；只需更新界面文案、候选池消费方式和测试语义。

快照升级必须同步覆盖：

- `PersistedSnapshot` 与空快照。
- snapshot codec、验证、迁移和持久化键清单。
- Zustand hydration、持久化选择器和资料库刷新。
- JSON/ZIP 导入导出与合并时的 ID 重写。
- Electron 资料库 Schema 迁移、备份恢复和版本兼容。
- 当前 Schema 版本递增以及旧 v12 资料库回归。

导入合并时，自定义池 ID 与其他可重写实体一样处理冲突，并同步重写 `reviewPoolLayout.homeOrder` 中的自定义引用。替换导入使用导入资料库布局并执行规范化；合并导入保留当前资料库首页布局，新导入的自定义池默认进入“更多复盘池”，不得未经确认打乱当前首页。

候选计数、按钮状态和开始会话统一复用同一个记忆化候选选择器。选择器至少以资料库修订、复盘池定义、布局无关的候选资格参数和 `subscribedIds` 修订为输入；不得在每个复盘池按钮的每次 React 渲染中独立全表扫描。以一万条记录验证筛选、计数和开始快照仍使用同一结果且交互无明显阻塞。

案例来源独立不新增另一套案例实体，但必须停止 `cascadeReviewCaseSourceSnapshot` 写入路径。迁移只补缺失快照，不覆盖已有 `sourceNoteHtml` 或 `note`。

### 数据流

```text
快速记录 → 现有 Trade 存储 → 盘后补全
                         └→ 冻结来源快照 + 独立案例正文

复盘池配置 → 单一候选池选择器 → 固定本轮 ID 快照 → 随机逐条复盘
近期多看 ────────────────────────┘（调整抽取优先级）

交易状态变化 → 计算风险状态 → 提醒或确认 → 用户自行决定是否继续

阶段切换 → 仅 open 硬阻止 → planned 与未完成周复盘留在原阶段
```

## 错误与退化处理

- 复盘池为空时说明当前条件没有候选项，并提供“一键恢复全部内容”。
- 自定义复盘池引用的策略被删除时，保留预置并标出失效条件；用户可以编辑或移除条件。品种或标签从设置预设中移除时仍按记录中的历史字符串匹配，不视为失效。
- 候选数量、开始按钮和实际会话必须使用同一个候选池计算结果。
- 已开始的会话遇到删除记录时安全跳过，不改变其他记录的相对顺序。
- 快速记录附件未写入完成时不提交半成功数据。
- 快速记录内容校验失败时保留已选品种、方向、策略和截图，不关闭弹窗。
- 案例来源改变或删除时继续展示冻结快照，不用最新来源覆盖。
- 风控计算失败时显示“当前风险未知”，不伪造正常状态，也不因业务判断阻止用户继续。
- 风险确认后的耐久提交失败时保持原交易状态，不只留下审计事件。
- 旧路由、旧随机复盘筛选和历史掌握状态继续可解码，升级后不得丢失。

## 测试与验收

### 自动化测试

- 导航契约：核心入口数量、旧路由兼容和隐藏入口定位正确。
- 全局快速记录：从交易日志、模拟盘、案例、随记、复盘和设置打开时都默认创建当前阶段 `live`；只有显式切换才创建 `paper`。
- 交易日志壳：记录、统计、周期复盘层级稳定；数据范围与列表/看板视图不会产生冲突参数。
- 快速记录：最小字段可保存，保存后不跳详情，默认不进入绩效统计，不触发开仓风控，附件保持原子性。
- 阶段切换：`planned` 与未完成周复盘不阻止，记录留在原阶段；`open` 仍阻止。
- 日志转案例：字段复制完整，来源可追溯，冻结快照不再级联，后续双方编辑互不覆盖。
- 随机候选池：案例、已结束实盘、已结束模拟和错过机会纳入；计划、持仓和删除记录排除。
- 复盘池预置：系统预置数量正确；`all`、`missed`、`boosted` 的专用候选谓词正确；`ReviewPoolFilters` 空数组不限制、数组内 OR、维度间 AND、案例结果与 `caseTypes` 收窄语义正确；各稳定键、自定义组合、失效条件、`subscribedIds` 映射和持久化正确。
- 复盘池布局：缺失布局恢复六个系统池默认顺序；隐藏项优先从 `homeOrder` 移除；`all` 恒为第一项；未知、重复、已删除引用安全清理；系统池与自定义池混合首页最多六项。
- 复盘池布局导入：替换导入采用并规范化导入布局；合并导入保留当前首页并正确重写自定义池 ID。
- 近期多看资格：标记不放宽 `planned`、`open` 和软删除资格；状态结束后自动进入，恢复后重新生效，彻底清理后移除引用。
- 会话稳定性：开始后的顺序稳定，删除记录安全跳过，候选预览与实际轮次一致，进行中会话不会写入规范快照。
- 掌握兼容：默认会话不修改掌握字段；高级评估仍按原规则写入；旧会话和过滤偏好可解码。
- 风控状态机：正常、接近、触线、未建档、未知和技术失败分别验证能否记录、能否开仓、是否确认和审计结果；首次确认按所属阶段内的单条记录粒度计算；可选原因未填写时保存空字符串并展示“未填写理由”。
- 风控硬门禁：`not-current-stage`、`pending-exists`、目标丢失、目标不再合格、数据损坏和持久化失败继续阻止提交，不因业务风险可确认继续而被旁路。
- 新阶段风险基准：沿用上一阶段时政策、月限额、风险重算与开仓原子提交；重算后仍触线或未知时留在同一弹窗等待确认；无可用政策时继续开仓不伪造配置并在后续继续提示未知；即使新阶段当前业务日已有已结束交易，首次基准仍从当天立即生效。
- 案例来源展示：停用 `cascadeReviewCaseSourceSnapshot` 并移除详情运行时来源回退后，来源修改或删除不改变冻结快照。
- 案例旧范围：`focus`、`unreviewed`、`reviewed` 的旧 URL、保存视图和侧栏入口继续解码到高级筛选。
- 旧配置兼容：旧复盘过滤快照按原 `caseScope` 与 `reviewTiming` 恢复；旧 `system:*`、`case-view:*` 侧栏钉选不再渲染，但旧资料库、旧 URL、保存视图和导入数据仍可读且不丢失。
- 快照、导入导出、导入合并、备份、恢复和旧 v12 资料库迁移回归通过。
- Windows 与 macOS 桌面布局、键盘导航和焦点恢复契约通过。

### 产品验收

- 从应用启动到完成一条最小记录只需要一次打开、填写最小信息和一次保存。
- 无论用户当前位于哪个页面，全局快速记录都默认产生当前阶段实盘记录，不会因页面上下文误建随记、案例或模拟交易。
- 保存后用户仍停留在原工作上下文，并可通过成功提示打开新记录。
- 首页不出现强制今日任务队列或每周风险确认任务。
- 用户可在交易日志内找到统计、周期复盘、历史阶段、模拟盘和策略范围。
- 用户可分别查阅交易日志和案例记录，两者不会被误认为同一个列表。
- 用户可以一键开始全部内容、只看案例或亏损日志的随机复盘。
- 用户可以保存自定义复盘池，并将常用池放到首页；首页包含“全部内容”且总数最多六项。
- 用户加入“近期多看”后可以在专属池中找到该记录，取消后立即退出该池。
- 计划中、持仓中或回收站记录不会因为被标记“近期多看”而提前进入复盘池。
- 来源交易修改或删除后，既有案例仍保持创建时的来源快照和案例洞见。
- 到达阶段切换时间时，未完善记录和未完成周复盘不会阻止进入新阶段。
- 风险触线时信息清晰，但用户始终保有最终交易决定权。

## 分阶段落地

0. 先锁定并测试四份合同：阶段切换、风控状态机、复盘池数据与布局、案例来源快照；不设计跨阶段复制或迁移。
1. 精简侧栏与今日待办，建立交易日志“记录 / 统计 / 周期复盘”承载层，保留旧路由兼容。
2. 增加快速记录精简模式、一句话输入、内容校验和保存后原地停留，并降低交易详情属性层级。
3. 停止案例来源正文级联，完成历史案例兼容；上线系统复盘池、“近期多看”和默认精简会话。
4. 增加自定义复盘池并接入快照、导入导出、备份和资料库迁移。
5. 将风控交互从硬业务门闩调整为提醒与一次确认，停止每周重复准备，同时保留历史审计事实。

每个阶段独立完成类型检查、相关单元测试、浏览器交互测试和桌面端回归后再发布，不要求一次完成整套改版。

## 非目标

- 不更换前端框架、状态管理或桌面运行时。
- 不重做数据库、图片资产、备份和导入导出架构。
- 不自动把普通日志升级为案例。
- 不删除统计、周复盘、历史实盘、模拟盘或随记能力。
- 不引入社交、云同步、经纪商自动下单或移动端能力。
- 不在本次设计中清理所有大型文件或遗留路由。
- 不引入新的颜色、字号、间距、圆角或阴影 Token 体系。
- 不把进行中的随机复盘会话写入资料库快照。
- 不在本次实现中设计“近期多看”的时间衰减算法。
- 不在本次实现中提供 `planned` 的跨阶段复制、迁移、关联或审计流程。
- 不支持手机、iPad、浏览器或其他平台布局；自动化浏览器页面只作为桌面渲染测试载体。
