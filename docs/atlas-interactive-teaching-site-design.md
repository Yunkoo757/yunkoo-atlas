# Atlas 互动教学站设计

日期：2026-09-06
状态：已按任务地图式方案定稿，进入实现
范围：独立于 Trader Atlas 桌面客户端的教学 / 文档站页面

## 1. 目标

为第一次接触 Trader Atlas 的用户提供一条可以实际走完的学习路径。用户不需要先读完一份长说明书，而是跟随一个教学工作区完成一次完整复盘闭环，并在过程中建立以下核心概念：

1. Atlas 是本地优先的交易日志与复盘工作台，不是行情终端。
2. 交易事实、复盘判断和案例沉淀是三个不同层次的内容。
3. 实盘、模拟盘、错过机会和案例有不同的数据含义，不能混为一个统计口径。
4. 统计、周期复盘和随机复盘是从记录回到行为改进的反馈环。
5. 风险、数据备份、导入、回收站和设置承担的是数据可信与工作流维护。

教学站的单一主任务是：让用户在教学数据上完成一次“记录 → 补充 → 复盘 → 案例 → 分析 → 回顾”的闭环。

## 2. 非目标

- 不把教学站嵌入 Electron 渲染进程。
- 不新增移动端、平板端、手机端或浏览器版客户端布局；页面只按 Windows / macOS 桌面浏览器设计。
- 不承诺收益、不展示虚构用户量、不伪造产品未实现的能力。
- 不复制 TikHub 的品牌色、字体或 API 文档结构。
- 不创建第二套 Atlas 产品色板、灰阶、间距、圆角、按钮或动效体系。

## 3. 学习路径

左侧学习地图使用真实的业务顺序，不按“功能数量”堆叠章节。主线步骤完成后才把相关分支标记为可学习；用户可以回看已完成章节，但不能跳过必需概念直接获得“已掌握”。

| 阶段 | 教学章节 | 用户要形成的理解 | 互动结果 |
| --- | --- | --- | --- |
| 00 | 认识 Atlas | 记录的是自己的决策证据，而不是行情信息 | 选择“我想改进交易过程”完成入门判断 |
| 01 | 记录第一笔交易 | 先捕捉基本事实，后续可以补充 | 在交易日志示例中选择方向、状态、品种与策略 |
| 02 | 补充详情 | 盘面摘要、复盘正文、截图和属性各自承担不同作用 | 打开属性区、添加一条摘要、展开补充信息 |
| 03 | 完成复盘 | 复盘状态代表“这条记录已被处理”，不是盈亏好坏 | 写下一个事实和一个改进动作，点击完成复盘 |
| 04 | 沉淀案例 | 高价值交易要从日志中形成可检索、可追溯的案例 | 将教学交易加入案例库并查看来源关系 |
| 05 | 读懂统计 | 先看范围与口径，再看指标；错过机会不等于实盘亏损 | 切换实盘 / 模拟范围并识别口径变化 |
| 06 | 周复盘与随机复盘 | 周期复盘看模式，随机复盘检查记忆与执行 | 完成一次掌握度评估，并生成一条周复盘观察 |
| 07 | 其它记录方式 | 模拟盘、错过机会、随记、今日工作台是不同捕捉入口 | 选择场景并判断它是否进入实盘统计 |
| 08 | 风险与维护 | 风险证据、备份、导入、回收站和修复保护长期数据 | 查看风险状态、选择备份方式并识别恢复后果 |
| 09 | 设置与桌面效率 | 快捷键、策略、标签、品种、模板、显示和更新让工作流稳定 | 在 Windows / macOS 修饰键之间切换并完成一次命令面板练习 |

## 4. 任务地图式页面结构

页面使用一个桌面工作区外壳，三列边界清楚但不制造多余卡片：

```text
┌────────────────────────────────────────────────────────────────────┐
│ Atlas 教学站 · 搜索 / 平台提示                                   │
├───────────────┬────────────────────────────┬───────────────────────┤
│ 学习地图       │ 当前章节：概念 + 示例 + 小测 │ 教练台：当前动作       │
│ 244px 语义宽度 │ 中栏内容限宽 920px            │ 只显示一项可操作提示   │
│               │                            │                       │
│ 00 认识       │ 说明文字                    │ 现在试试：             │
│ 01 记录       │ 教学数据示例窗口             │ 点击“方向：做多”      │
│ 02 补充       │ 反馈 / 解释                   │                       │
│ ...           │ 下一步                       │ 已完成 2 / 6           │
└───────────────┴────────────────────────────┴───────────────────────┘
```

- 页面最大宽度使用 `--page-rail-wide`；正文段落、解释与测验使用 `--page-rail-reading` 的限宽。
- 学习地图沿用 `--sidebar-width` 的既有宽度语义，不重新定义一套导航尺寸。
- 右侧教练台同样沿用 `--sidebar-width` 的尺寸语义；中栏占据剩余空间，正文内容再使用 `--page-rail-reading` 限宽。
- 中央和右侧是同一节课的两个视角：中央解释“为什么”，右侧演示“怎么做”。
- 右侧教练台不是聊天机器人，不自由生成内容；它由当前步骤的状态机驱动，保证文案、操作和结果一致。
- 页面只保留一个明确主操作：当前步骤的“继续学习 / 完成这一节”。其它操作为 `ghost` 或 `bordered`。

## 5. 每节课的互动状态机

每个章节都使用统一的四段节奏，避免用户面对一组没有重点的功能卡片：

1. **观察**：展示一个真实 Atlas 语境下的示例，先说明它解决的任务。
2. **操作**：右侧工作台只开放当前目标控件；未到步骤的控件保持可见但不可操作，并说明原因。
3. **理解**：操作成功后立即解释数据、状态或统计口径发生了什么。
4. **确认**：用一个单选或排序题确认理解，答错时保留上下文并给出简短解释，不惩罚式重置。

每个操作有 `idle`、`active`、`success`、`blocked` 四种状态；异步或切换场景时再增加 `busy`。状态不能只靠颜色表达，必须同时有文字、图标或形状线索。

主线完成状态保存在教学站本地存储中。重载页面后保留进度，不上传交易内容、不请求账户、不访问桌面客户端本地资料。提供“重新开始教学”入口，并在执行前明确会清除教学进度。

## 6. 功能覆盖

### 工作台与导航

讲清固定侧栏、工作区与“更多”区、当前范围、页面窗格、搜索 / 命令面板、快捷键、Windows 与 macOS 修饰键差异。导航示例沿用：交易日志、统计分析、周期复盘、案例库、随机复盘、随记、进行中、星标、错过机会、模拟盘。

### 记录与详情

通过一条教学交易串起交易日志、创建记录、进行中状态、方向、品种、策略、标签、盘面摘要、复盘正文、截图、属性区、交易数据、时间信息与来源关系。强调“先捕捉，后整理”，不要求初次记录一次填完所有字段。

### 复盘与案例

解释复盘状态、复盘正文、错误 / 违规、情绪、市场叙事、案例来源、案例正文和案例库的区别。完成复盘后，示例数据在来源关系中可回到原始交易；删除、回收和案例保留的边界在维护章节说明。

### 分析与反馈

统计章节先让用户选择数据范围，再呈现胜率、盈亏、交易数量、策略表现等教学指标。所有数字旁都显示“当前范围 / 已完成记录”等口径说明。周复盘负责模式总结，随机复盘负责旧交易抽查与掌握度评估。

### 日常记录与特殊来源

用对照练习说明实盘、模拟盘、错过机会、随记和今日工作台的使用时机。特别说明错过机会不计入实盘绩效，模拟盘是独立来源，随记不等同于交易记录。

### 风险、数据与设置

覆盖风险管理、风险数据修复、阶段归属、完整备份、JSON 数据副本、CSV 导入、Notion 导入、重复检测、恢复数据库、回收站、资料、快捷键、策略、标签、品种、模板、显示与更新。危险操作只展示事实、影响和恢复路径，不用恐吓式文案。

## 7. 视觉与 token 约束

网站样式以 `src/styles/tokens.css` 和仓库根目录 `design.md` 为唯一视觉来源。网站可以比客户端更舒展，但只能通过现有语义角色组合，不直接新增原始色值。

### 允许消费的角色

- 表面：`--surface-app`、`--surface-pane`、`--surface-elevated`、`--surface-inset`、`--surface-floating`
- 边框：`--border-subtle`、`--border-default`、`--border-strong`、`--border-divider`、`--border-chrome`
- 文字：`--text-strong`、`--text-body`、`--text-muted`、`--text-faint`
- 焦点：`--accent`、`--accent-hover`、`--accent-readable`、`--accent-bg`
- 业务语义：仅在对应语境使用 `--pos`、`--neg`、`--warn`、`--pending`、`--opportunity`、`--diagnostic`
- 尺寸：`--page-rail-wide`、`--page-rail-standard`、`--page-rail-reading`、`--page-rail-form`、`--sidebar-width`
- 间距：`--sp-1` 到 `--sp-8`、`--space-section-gap`、`--space-page-inset-*`
- 形状：`--radius-4`、`--radius-6`、`--radius-8`、`--radius-10`、`--radius-14`、`--radius-rounded`
- 字体 / 动效：`--font-ui`、`--font-mono`、`--font-size-*`、`--font-weight-*`、`--motion-*` 与既有缓动曲线

网站只复制必要的语义子集，并在文件头注明来源；复制是为了独立发布，不改变源 token 的含义。禁止在组件中出现新的品牌蓝、渐变背景、发光阴影、夸张大标题、未经命名的字号或非 token 圆角。

### 互动与可访问性

- 按钮、链接、选项、折叠区和对话框使用原生语义；不使用可点击 `div`。
- `Tab` 顺序遵循学习地图 → 中央内容 → 教练台 → 当前主操作。
- 所有状态同时提供文本描述；焦点使用 `focus-visible`，不依赖 hover。
- `prefers-reduced-motion: reduce` 时移除非必要转场，只保留静态状态变化。
- Windows 展示 `Ctrl`，macOS 展示 `Command`；可切换平台时同步更新所有快捷键提示。
- 站点按桌面窗口设计；窗口变窄时收窄阅读区域并保持桌面三列逻辑，不添加手机端折叠导航方案。

## 8. 技术边界与数据流

站点放在 `atlas-docs-site/`，使用独立入口和资源，不依赖 Electron API、IndexedDB 交易库或桌面客户端运行时。教学数据是只读的本地静态 fixture，互动状态只包含章节、步骤、选择和完成记录。

建议模块边界：

- `content/`：章节文案、步骤、问题、解释和模块目录。
- `data/`：教学交易、案例、统计范围和设置示例的类型化 fixture。
- `components/`：学习地图、教学窗格、示例工作台、教练台、状态提示和测验控件。
- `state/`：教学进度、平台修饰键、当前章节和步骤的状态机。
- `styles/`：Atlas token 语义子集、页面布局、组件状态和减少动效规则。

内容数据与渲染逻辑分离，新增章节只需添加内容与步骤，不复制整套页面。教学站不做账号体系、云端同步或真实用户数据导入。

## 9. 验收标准

- 从首页进入后，用户能在不阅读外部资料的情况下完成主线闭环。
- 10 个章节都能从学习地图进入；主线步骤有顺序，已完成章节可以回看。
- 至少包含一次方向选择、字段填写、属性展开、来源关系查看、统计范围切换、掌握度评估和平台快捷键切换。
- 所有核心模块在教学内容中有明确入口和“何时使用 / 不计入何处 / 结果是什么”的解释。
- 无虚构产品能力或收益承诺；教学数据与真实用户数据在文案和界面上明确区分。
- 视觉仅使用 Atlas token 语义角色；页面没有第二套品牌色板、灰阶、圆角或按钮体系。
- 默认、hover、active、focus-visible、disabled、busy、success 和错误 / 阻塞状态可见且可理解。
- Windows 与 macOS 桌面窗口下无横向内容丢失；不引入移动端适配分支。
- `prefers-reduced-motion` 下交互仍能完成。
- UTF-8 无 BOM 保存中文内容；类型检查、构建和浏览器交互测试通过。
