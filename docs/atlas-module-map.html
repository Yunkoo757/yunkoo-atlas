NORTH STAR

把一次交易，变成可复用的决策资产。

Atlas 的主线不是“看一眼赚了多少”，而是：低摩擦捕捉事实，安全推进执行，补齐结果与解释，再把高价值内容沉淀为案例和下一周的行动。

使用时只记住四件事

01交易详情记录事实；随记记录暂时没有交易归属的想法。
02当前阶段决定实盘数据的归属边界。
03统计先看范围和数据健康，再解释结果。
04周复盘负责总结，案例库负责长期学习。
facts → learning → next action
01 / THE LOOP

Atlas 的一条主线

所有模块都服务于同一条反馈回路
01 · CAPTURE

捕捉

快速建立计划、模拟盘、错过机会或交易事实。

02 · EXECUTE

执行

通过计划中、持仓中、已平仓推进生命周期。

03 · REVIEW

复盘

补齐截图、结果、正文、标签和执行解释。

04 · DISTILL

沉淀

把值得长期学习的交易提炼为来源可追溯的案例。

05 · FEEDBACK

反馈

用统计、周复盘和风险证据形成下一步行动。

↺闭环不是一次性填表。 每周的“只改变一件事”会回到下一周的盘前准备，继续验证是否真正改变了行为。
02 / MODULES

模块地图：每个入口只负责一类问题

交易工作台是中心，其他模块围绕它读写和反馈

交易日志

/list · /board

发现、筛选和推进交易。列表适合扫描，看板适合看状态流转。

记录
计划、持仓、已平仓、错过机会、模拟盘
入口
今日、进行中、周期、策略、星标等快捷视图
边界
这些是同一批交易数据的视图，不是多个数据库

交易详情

/trade/:id

单笔记录的事实中心：身份、执行、结果、截图、正文、标签和活动。

适合
解释为什么进场、怎么执行、哪里做错、结果是什么
动作
编辑、平仓、补复盘、提炼案例、删除/恢复
原则
先捕捉最小事实，盘后再补完整解释

风控与实盘阶段

risk · stage

给实盘数据划边界，并在开仓前把风险条件变成可确认的门控。

管理
周风险政策、日/周/月限额、风险覆盖事件
阶段
当前实盘阶段、历史阶段、阶段切换和归属修复
注意
模拟盘不属于实盘阶段，也不参与实盘风险门控

案例库

/review-cases

把少量高价值交易转成长期学习对象，而不是把所有交易都复制一遍。

分类
优秀范例、错题、模糊决策、错过案例
关系
保留来源交易和来源正文快照，保证可追溯
边界
案例不进入账户绩效 KPI

随机复盘

/review-session

把复盘变成有节奏的练习：选择池、逐条阅读、记录掌握度。

来源
到期案例、已结束实盘、错过机会、模拟盘或自定义池
状态
还没掌握、待复看、已经掌握
重点
重点案例和近期多看是学习优先级，不是交易星标

周期复盘

/weekly-review

把一周的事实、风险、执行缺口和下一步承诺放在同一条阅读轨道。

包含
本周事实、风控执行、交易证据、模式、承诺
完成
完成后冻结指标、交易证据和风险快照
作用
让下一周有可验证的行为目标

统计分析

/dashboard

回答“在这个范围内，发生了什么”，不是手工修改事实的地方。

范围
阶段、实盘/模拟、周/月/30d/90d/YTD
口径
已验证结果、胜率、平均 R、USD 现金盈亏
原则
缺失、冲突、无效日期会显式提示，不强行补数据

随记

/notes

承接暂时没有具体交易归属的观察、灵感和思考。

适合
盘面观察、待验证假设、临时想法、非交易笔记
不做
不自动进入交易统计或随机复盘池
升级
形成计划转成交易，形成方法转成策略

设置与数据维护

/settings

维护系统规则和资料库安全，不承担日常交易输入。

配置
策略、标签、品种、模板、快捷键、显示
数据
资料库切换、CSV/Notion 导入、journal.zip 导出
安全
自动备份、验证、恢复、数据健康和回收站
03 / CORE LOGIC

核心数据逻辑：四个词决定 Atlas 怎么算

不要把状态标签、学习状态和统计真相混在一起

记录类型 tradeKind

决定它属于哪条业务线

live

实盘；有阶段归属和风控门控。

paper

模拟盘；用于练习和对照。

case

案例；用于长期学习，不进 KPI。

note

随记；独立思考，不是交易。

交易状态 status

决定执行生命周期，不等同于统计真相

计划中→持仓中→盈利亏损保本
计划中→错过机会

错过机会是执行证据，不是真实成交结果。 它可以进入周复盘和复盘池，但不应混入实盘胜率与权益曲线。

实盘阶段 liveStageId

决定交易、风险和复盘的时间归属

current

当前唯一可写入的新实盘阶段。

archived

历史阶段，只读回看和分析。

risk

政策、限额和覆盖事件随阶段归属。

review

周复盘保留所属阶段的证据。

统计真相 TradeTruth

结果来源和数据完整性决定是否计入

pnl

以现金盈亏作为结果依据。

r

以 R 倍数作为结果依据。

price

由价格和冻结风险计算 R。

conflict

冲突数据会被排除并提示修复。

一次编辑如何落盘

界面只是入口，持久化快照才是资料库的完整合同

页面 / 快捷键列表、详情、复盘、设置
Zustand Store统一动作、规范化和不变量
PersistedSnapshot交易、阶段、风控、复盘、随记、设置
本地资料库journal.db、附件和备份
04 / DAILY ROUTINE

推荐使用节奏：盘前、盘中、盘后、每周

把记录拆成低摩擦捕捉和延迟整理两步

一笔交易的最短闭环

不要等所有信息齐了才创建记录。

01
盘前：新建计划品种、方向、策略、周期、入场、仓位和止损先记下来。
02
盘中：推进状态计划中 → 持仓中；实盘触发风险条件时完成确认。
03
盘后：补齐事实填写平仓、盈亏或 R、截图和交易正文。
04
当天：完成复盘进入今日记录，处理未完成交易和待复盘项。
05
筛选：提炼价值值得反复学习的交易才提炼为案例，不追求全部案例化。

一周的反馈闭环

先看证据，再做判断，最后形成一个行为承诺。

01
周初：确认风险政策检查当前阶段、周风险准备和限额是否清楚。
02
周中：正常记录交易详情保存事实；随记保存无明确归属的观察。
03
周末：查看统计范围先选阶段、实盘/模拟和时间范围，再看绩效和执行缺口。
04
周末：完成周期复盘填写事实、风控、证据、模式和下周只改变一件事。
05
之后：随机复盘复习到期案例，标记掌握度，让学习内容重新进入节奏。
05 / RECORDING GUIDE

记录归属：不知道写哪里时看这一张

一类信息只保留一个主要归属
你想保留的东西放在哪里为什么不要放在哪里
发生了什么交易字段 / 状态 / 结果可被统计、筛选和追溯不要只写在随记正文里
为什么这样做交易详情正文和单笔执行事实绑定不要只依赖标签
重复出现的模式策略 / 标签 / 错误标签便于跨交易、跨周观察不要为同义词无限建标签
值得长期学习的交易案例库有独立掌握度和复看节奏不要把所有交易都提炼成案例
本周的结论和承诺周期复盘形成下一周可验证的行为改变不要用仪表盘代替判断
暂时没有交易归属的想法随记低摩擦保留观察，不污染交易口径不要期待它自动进入 KPI
需要重点关注的内容星标 / 重点案例 / 近期多看分别对应导航、案例优先级、复盘频率不要把三种语义混用
06 / WHEN THINGS LOOK WRONG

统计或风险看起来不对时，按这个顺序查

不要先怀疑图表，先确认数据边界

使用侧排查

  1. 确认顶部范围：当前阶段、全部阶段，还是某个历史阶段。
  2. 确认记录类型：实盘、模拟，是否误把案例当成账户交易。
  3. 确认时间范围：本周、本月、30d、90d 或 YTD。
  4. 确认交易结果：是否已平仓，盈亏/R 是否缺失或相互冲突。
  5. 确认平仓日和币种：日期有效，现金盈亏是否能合并到 USD。
  6. 仍不明确时，进入数据健康或风险数据修复，不要手工修正统计数字。

研发侧推进顺序

每个新功能先定位实体和不变量，再决定页面

src/data/　数据模型与持久化实体
src/lib/　业务规则、统计、复盘、风控
src/store/　状态动作、规范化、不变量
src/views/　页面编排与路由入口
src/components/　可复用桌面组件
src/storage/　快照、附件、持久化
src/editor/　富文本和图片
electron/　桌面资料库、IPC、备份、更新
scripts/　QA、构建、发布
场景→实体→规则→Store→持久化→页面→QA

一句话：先记事实，再补解释；先选范围，再看统计；先完成周复盘，再提炼案例；先保护资料库，再做导入、恢复和清理。
