## 检查范围与证据边界

以 Git 跟踪的 1,413 个文件为基线，清点全仓文件、字节与编码；解析 843 个自有 JS/TS 模块的静态导入，并按桌面主进程、存储、业务页面、独立工具、构建验证、官网与教学站分面审查。Renderer 生产入口图覆盖 423 个源文件，其中 417 个可从入口到达。相邻测试、生成入口与独立页面入口另行核对，不能把不在应用入口图上的文件全部视为废弃。

第三方 vendor、字体、图片、历史截图和原型压缩包只做资产/引用/体积清点，不将供应商代码的 TODO 当成项目缺陷，不重写其内容。`node_modules`、安装包、隔离资料库和历史测试结果不属于生产源码审查范围。单次审查无法证明所有行为均无缺陷；本表区分已复现问题、静态风险和产品取舍。

全仓扫描：[inventory.json](../../test-results/project-health-20261110/inventory.json)。Renderer 图与逐项发现：[renderer-findings.json](../../test-results/project-audit-20261110/renderer-findings.json)。最终测试和原生运行结果：[validation.json](../../test-results/project-health-20261110/validation.json)。这些本地验证产物位于被忽略的 `test-results`，清理后可能不再存在；本文件保留长期结论。

## 验证与限制

定向回归要求可控时序或实际失败路径，避免只验证实现形状。全量验证使用 `pnpm qa:ci` 与包含类型检查的 `pnpm build:app`；独立离线工具和站点另按其实际入口检查。原生验收只使用本轮新建、明确标识的隔离资料库，复核判断台导入原图、预览、随机复盘池恢复和正常退出重启，并查看实际截图。具体执行结果以本轮 `validation.json` 和日志为准。

本机可验证 macOS；本轮未触发远端 Windows CI、正式发布、真实更新安装，也未替用户操作真实交易资料库。静态扫描未发现错误不等于所有功能已得到动态证明。已移除的旧 hook 与正则有明确零引用证据，其余“可能不用了”的内容经后续复核作了明确清理或保留决定，见后续优化结果。
